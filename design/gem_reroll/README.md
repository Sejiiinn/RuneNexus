# 젬 리롤 UI · 젬 리셋권

2026-10-12. 승인 시안의 우측 상단 작은 리롤 조작과 신규 리셋권 아트를 실제 Godot 보상 UI에 연결했다.

## 승인 원본과 런타임

- `approved-free.png`, `approved-ticket.png`: 사용자 승인 시안. 기존 속성색 보상 카드, 파편 행동, 획득 젬 목록을 유지한다.
- `gem_reset_ticket_source.png`: 승인한 1254×1254 투명 PNG 원본. 금속 티켓 외곽, 짙은 청록 면, 민트 젬과 순환 화살표를 그대로 보존한다. 재생성·재디자인하지 않았다.
- `gem_reset_ticket_prompt.txt`: 보존된 ImageGen 제작 입력.
- 게임용 `assets/images/ui/hud/icons/gem_reset_ticket.png`: 원본을 Lanczos로 256×256에 축소한 무손실 투명 PNG. `godot/ui/assets.json`으로 패키징하며 보상 비용 영역에서 16px로 사용한다.
- 원본 SHA-256: `324739376ab820a0ce4d5b383d333099762e19f054b1096dcb7b82821f642afe`.
- 런타임 SHA-256: `6b78b08021149e72b9a871509e07a4ad0f3d99580c8615e0d0c2decbc52546fc`.

## 구현 범위

`godot/ui/battle_rewards.gd`는 기존 보상창에 32px 순환 화살표 조작, 44×52px 터치 영역, 총 남은 횟수 배지, 무료 또는 리셋권 아이콘 ×1 비용 표시를 추가한다. 일반 웨이브 보상에만 표시하고 파편 20개로 구매한 선택창에는 표시하지 않는다. 무료·리셋권·재시도·처리 중·소진 상태는 앱의 `gem_reroll_state()`를 표시한다. 실제 횟수·결제·보상 후보·영속성은 앱/도메인/서버가 소유한다.

처리 중과 결과 미확정 시 기존 후보를 표시하면서 젬 선택·파편 수령·뒤로가기를 차단한다. 결과 확인/저장 실패는 리롤 조작으로 재시도할 수 있다. 연속 클릭과 이전 화면 콜백은 화면 리비전·보상 식별자로 차단한다. 보상 등장 애니메이션은 같은 웨이브의 리롤에 반복하지 않는다.

## 리롤 UI 최초 연결 검증

- `godot/verify_gem_reroll_ui.gd`: 실제 `battle_hud.gd`/`battle_rewards.gd`와 카탈로그를 사용한 격리 UI 검사. 최종 headless 39개 검사 통과. 320/440px 가독성·제목/조작 분리·배지 잘림 방지, 무료/리셋권/부족/소진, 구매창 제외, 처리 중 입력 차단, 재시도, 중복/지연 콜백을 확인한다.
- 기존 `verify_battle_rewards.gd` 통과: 보관, 대상 선택, 교체, 슬롯 추가, 파편, 구매창, 카메라 보존.
- 기존 `verify_gem_reward_entrance.gd` 45개 검사 통과: 애니메이션·입력 복구·갱신/리사이즈/구매 화면 계약.
- Godot 4.7.2 OpenGL Compatibility, Mesa llvmpipe 실제 렌더: 440×900 / 320×736. 같은 최종 UI 코드의 41개 검사(당시 검사 35개+캡처 6개) 통과. 이후 테스트에 재시도 4개 검사를 추가했으며 제품 코드는 바뀌지 않았다.
- 대표 실제 UI 렌더 `native-free-320.png`, `native-ticket-440.png`는 로컬 검증 자료로 보관하며 Git에는 포함하지 않는다. 승인 시안과 비교하여 배지·제목·티켓 비용·카드 정보·파편/보유 목록이 잘리거나 겹치지 않음을 확인했다. 네이티브 보상 UI의 카탈로그 fixture이며 3D 전장·실계정·Android 본게임 캡처가 아니다.
- 리롤 UI 최초 연결 시점의 렌더 입력 SHA-256: `battle_rewards.gd` = `3ca0520a8daa5f96749430783acb911455d1f596d648ed6d8250b9da385db18f`, `gem_reward_entrance.gd` = `3117d0ff94dfddc86006948e41d45faaf7ff7af3e16e797ff429b88298444778`, `battle_theme.gd` = `2835770159433803837cf55337fdd429e23c797646ce6a1c61b57fb18c8fafe9`.

Android 전용 터치/뒤로가기·실서버 연동 검증은 이 UI 작업에서 수행하지 않았다. APK를 만들거나 배포하지 않았다.

### 우편 리셋권 표시

기존 서버 우편의 `gemResetTickets`를 승인한 리셋권 아이콘과 수량으로 표시한다. 리셋권만 있는 우편을 ‘보상 없음’으로 표시하지 않으며, 기존 읽기·개별/일괄 수령·페이지네이션 계약과 카드 배치를 유지한다. `verify_mailbox_ui.gd` 62개 검사와 같은 네이티브 GL 렌더 검사가 통과했다. 리셋권만 7장 있는 격리 fixture의 440/320px 화면에서 아이콘·수량·수령 행동을 확인했다. 대표 화면 `native-mailbox-ticket-440.png`는 로컬 검증 자료로만 보관하며 실제 계정 보상을 발급하거나 수령한 결과가 아니다.


## 현재 리롤 연출: 고정 배치·단일 180도 회전

2026-10-12. 높이 변화와 단순 가로 압축 느낌을 보완한 뒤, 사용자가 한 번 뒤집히면 바로 새 카드가 나오도록 요청했다. 현재는 고정 배치를 유지하는 단일 180도 원근 회전이다. 기존 압축형과 360도·룬 뒷면 단계의 GIF는 이전 버전으로 보존하며 현재 시각 기준으로 사용하지 않는다.

### 배치·표현 계약

- 카드 높이 220px를 유지한다. 카드 아래 `GemRewardDetails`가 현재 폭에서 가능한 두 RULES와 긴 처리 안내를 담을 최대 높이를 폰트·줄간격 기준으로 미리 확보한다. 잠금 중 안내와 평소 후보 설명을 같은 영역에서 바꿔, 클릭 전·처리 중·완료 후 제목·카드 행·파편·리롤·모달 bounds가 일치한다. 기존의 조건부 헤더 처리 안내 줄은 사용하지 않는다. 새 고정 영역을 포함한 최초 모달 배치는 이전 버전과 달라질 수 있다.
- 파편 ‘받기’ 확정행이 이미 열려 있으면 리롤 때 접지 않는다. 연출 중에는 비활성화하고 완료 후 같은 위치에서 선택 상태를 유지한다. 카드 선택·뒤로가기의 기존 동작은 유지한다.
- `godot/ui/gem_reward_flip.gd`와 `.gdshader`가 약 0.36초 동안 세 카드를 동시에 한 번, Y축 180도 회전한다. 기존 앞면 → 90도 얇은 측면 → 새 앞면 순서로 즉시 이어지고 별도 뒷면 단계는 없다. 후보의 젬·이름·효과는 0.18초 측면 경계에서 한 번만 함께 교체한다. 마지막 프레임을 건너뛰어도 새 후보를 한 번 적용하고 angle=PI로 마무리한다.
- 원본 Control의 위치·크기·스케일은 바꾸지 않는다. 임시 CanvasGroup 세 개와 CanvasItem shader로 합성하고, 앞면 글자는 반전하지 않는다. 절제된 사다리꼴 원근·측면 음영·얇은 두께는 카드 슬롯 안에서만 표현한다. 새 면의 투영 축 방향도 보정하여 한 번의 회전이 같은 방향으로 이어진다. 별도 이미지·SubViewport·3D 장면·GPU readback을 추가하지 않는다.
- 임시 합성도 원본 상위 `clip_contents` Control의 교집합을 따른다. 작은 화면에서 스크롤된 카드가 보상창 밖으로 새지 않는다. 종료·취소·숨김·scene exit에서 합성 노드를 제거하고 원본과 입력을 복구한다.

### 확정·수명주기

앱의 확정 성공 반환 전에는 저장/서비스 갱신 신호가 먼저 와도 이전 카드를 유지한다. 결과 미확정·저장 실패 때도 이전 카드와 잠금을 유지하고, 성공한 재시도·복구 이후에만 회전한다. 확정 거절로 후보가 바뀌지 않았으면 잠금을 해제한다. 선택·파편·뒤로가기·중복 리롤을 연출 중 차단하고 전투 정지를 유지하며 UI는 실제 시간으로 진행한다. 최초 보상의 0.82초 입장과 겹치거나 이를 재사용하지 않는다.

### 실제 렌더 및 검증

- 같은 격리 UI 조건의 변경 전 검사와 비교했다. 현재 `verify_gem_reroll_ui.gd` 134개 통과: 14종 후보의 짧고 긴 효과·RULES 0~2개·처리/복구/저장 실패 문구를 320/440px에서 검사하여 고정 bounds와 텍스트 수용을 확인했다.
- 최종 `verify_gem_reroll_flip.gd` 312개 통과: 확정 전 노출 차단, 실패·응답 유실·저장 실패 뒤 재시도, 지연 잠금 해제, 입장과 순차 재생, 동일 보상 중복 신호, 임시 합성과 정확한 위치, 입력 잠금, resize, 숨김/재열기, HUD 분리/재진입, scene exit, 드롭 프레임, 열린 파편 확정행, 전투 정지와 실제 시간 완료를 확인했다.
- 단일180도 변경의 독립 검사에서 각도·교체·드롭 프레임 98개, 안전 경계 30개, 실제 presenter 313개가 통과했다. 고정 배치 presenter SHA가 같아 이전 배치 804개 근거를 재사용했다.
- 기존 보상 직접 실행과 입장 45개 검사도 통과했다. 공식 `scripts/run_godot_native_regressions.py`는 UI·flip·입장 3종 PASS이고, 기존 보상 사례는 마지막320폭 구간에서20초 한도를 넘었다. 단독 공식 재확인도 같은 한도를 넘었으므로 공식 전체4종 PASS로 취급하지 않는다. 플립 사례60초 및 기존 사례20초 한도는 변경하지 않았다. 동일 최종 소스를90초 관찰 한도로 실행했을 때18.81초에 exit0/PASS로 끝났지만, 이를 공식20초 한도 통과로 대체하지 않는다.
- Godot 4.7.2 OpenGL Compatibility, Mesa 25.0.7 llvmpipe, 440×900/320×736 실제 viewport 렌더 검사 387개 통과. 320×400 스크롤 사례에서 원본 clip 밖 픽셀 변화가 없음을 확인했다.
- `flip-before-440.png`와 `flip-440-{old,closing,edge,opening,final}.png`는 대표 클릭 전·회전·완료 프레임이다. `gem-reroll-flip-440.gif`는 실제 GL viewport의 60fps 타임라인 샘플을 조합했고 클릭 전·처리·완료 확인용 정지 시간을 더했다. 회전 구간은 0.36초이며 실시간 데스크톱 녹화는 아니다. 이 캡처·GIF와 320px 자료·MP4·실행 로그는 로컬 검증 자료로 보관하고 Git에는 포함하지 않는다.
- 최종 입력 SHA-256: `battle_rewards.gd` = `ee9beae81511feebd26aeefe5ba439e46d7f1c0ea8ff38d9c18ba6e20b461e1b`, `gem_reward_flip.gd` = `73bdbf32ffd4d361463eedea262b7d763e08052d3880af1aafb8ac93efecc816`, `gem_reward_flip.gdshader` = `29b4d29def21587893dd77f79825968ecb4a49676bcb3bb2fb40431d5d208ca3`. 기존 입장 helper는 최초 연결 검증 시점과 동일하다.

화면은 3D 전장이 없는 UI/catalog fixture이며 실계정·Android 본게임 캡처가 아니다. Android 전용 수명주기·터치·GPU 및 실서버 연계를 추가 검증하지 않았으며, 기존 서버/DB 검증 한계와 미배포 상태는 유지한다.
