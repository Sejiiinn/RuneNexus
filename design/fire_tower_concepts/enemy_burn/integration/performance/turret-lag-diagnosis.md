# 화염 포탑 추가 후 전투 끊김 분석 — 2026-09-14

## 후속 조사

[생성 전후 비교와 함수 스택 후속 결과](render-path-followup.md)에서 대포 31.4 → 화염 13.1 → 대포 32.0 FPS로 저하·회복을 확인했다. 추가 심볼 해석과 효과별 비교에서 **2D 화염 명중 효과의 도형 재생성**을 Godot 병목으로 확인했다. 3D 효과를 유지하고 그 명중 표현만 끄면 13.7→34.7 FPS였으며, Flutter 지연은 별도로 남았다. 아래는 그 이전의 가시성 비교 결과이며 후속 결과와 함께 해석한다.

## 결론

화염 포탑 구현에 기존 대포보다 큰 메시와 수동 입자 누적 계산 비용이 있다. 그러나 같은 APK에서 효과·본체를 순차적으로 숨긴 실험은 이 둘이 현재 약 8–10 FPS의 지배적 원인임을 입증하지 못했다. 적 화상만 끈 이전 실험으로 포탑 추가의 영향을 배제할 수는 없다.

실행 환경은 Android 17 ARM64 에뮬레이터, GoldfishGFXStream(Apple M4), Godot Vulkan Mobile + Flutter Impeller OpenGLES다. 실기기 성능 결론이 아니다. 모든 비교는 녹화 없이 release에서 수행했다. 포탑 6개·고정 탱커 3개·4배속이며 적 화상은 본체 비교 내내 껐다.

## 관측과 해석

| 조건 | Godot 평균 FPS | Flutter raster 평균 ms | 렌더 primitive 평균 |
| --- | ---: | ---: | ---: |
| 전체 화염 효과 | 8.61 | 95.87 | 420,822 |
| GPU 입자 제외 | 10.53 | 96.37 | 414,797 |
| 화염 효과 전체 제외 | 9.61 | 97.15 | 406,943 |
| 효과와 포탑 본체 제외 | 6.57 | 96.80 | 151,097 |

교대 반복한 7개 구간, 42개 표본이다. 본체 제외는 1구간이며 시간에 따른 변동이 커서 느려진 원인으로 해석하지 않는다. 중요한 사실은 그릴 primitive가 약 64% 줄어도 raster 시간이 거의 같다는 점이다. 가시성만 바꾸었으므로 이미 생성된 자원·초기화의 영향까지 배제하는 실험은 아니다. [원자료와 구간별 결과](turret-final-analysis.md).

10초 Android trace에서 앱 main과 VkThread는 각각 vCPU 한 코어 기준 약 93.3%, 94.3%의 실행 시간을 차지했다. swap 평균은 4.68/5.86ms, 관측 GPU completion 대기는 평균 4.32ms였다. 따라서 96ms 전체를 긴 GPU fence 대기라고 설명할 수 없다. 계산·그래픽 드라이버·busy polling을 구분할 함수 스택은 확보하지 못했다. [추적 결과](trace-analysis.md).

## 소스에서 확인한 부담

- 화염 포탑 본체 원본: 46,795 삼각형·112,288 정점. 대포는 11,452 삼각형·15,897 정점이다. 각각 약 4.1배·7.1배이고 그림자도 활성화된다. Godot 자동 LOD가 있으므로 원본 수를 그대로 매 프레임 처리량으로 보지 않는다.
- 작은 불티 메시도 1,600 삼각형이다. 입자 수뿐 아니라 정점 비용이 있다.
- 포탑 불꽃·발사체는 전투 시간 차이를 `request_particles_process`에 넣는다. 엔진은 이 시간을 1/60초 단위로 누적 계산하므로 4배속·낮은 FPS에서 따라잡기 계산이 커질 수 있다. 이 코드상의 위험과 실제 주원인 판정은 별개다. 입자를 끈 실험에서 일관된 전체 프레임 회복은 없었다.
- 적에게 붙는 신규 화상은 별도의 정적 MultiMesh/외부 시간 방식이다. 기존 적 화상 켜기/끄기에서는 8.86/9.10 FPS로 차이가 작았다. 당시 실제 화상 적은 2개이므로 대량 화상 성능 증명은 아니다.

[상세 코드 근거](turret-particle-code-analysis.md). Godot GPU timer 0은 미지원/미측정이며 GPU 비용 0이라는 의미가 아니다. 원 영상 자체도 약 7.91 FPS였고 소프트웨어 녹화 비용이 추가될 수 있다.

## 계측 영향 확인

동일 장면에서 profile 켜기→끄기→켜기를 추가 비교했다. 각 6개 일반 FPS 표본의 산술평균은 9.08→10.19→10.51 FPS, Flutter raster 평균은 93.54→96.33→99.12ms였다. 계측을 끈 구간에서 일관된 회복이 없었다. 위 본체 비교의 interval 기반 FPS와 집계 방식이 다르므로 직접 합산하지 않는다. [원자료](profile-probe-records.json). 소스에서도 getter는 저장된 timestamp 차이만 반환하며 추가 GPU wait를 요청하지 않는다.

## 남는 범위

추가 직전 빌드와 신규 포탑 자원을 아예 생성하지 않는 빌드의 비교, 렌더 스레드 함수 샘플링, 대상 실기기 측정이 있어야 추가 시점과 병목의 인과관계를 더 좁힐 수 있다. 현재 결과만으로 “화염 포탑은 무관하다”, “GPU 입자 때문에 확정적으로 느리다”, “Flutter 합성 대기가 원인이다”라고 결론 내리지 않는다. 게임 외형 변경이나 성능 수정은 이번 분석에서 채택하지 않았다.

진단 후 원래 일반 release APK를 에뮬레이터와 빌드 출력 경로에 복원했다. 진단 harness Dart 분석은 통과했다.
