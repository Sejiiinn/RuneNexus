# 챕터 3 추가 맵·라운드

역할: 3-6~3-10의 승인 지형, 라운드 의도와 정적 페이싱 감사. 구현 원본은 [콘텐츠 source](../../godot/content/source/stages/)의 `026.json`~`030.json`이다. 생성물이나 이 문서를 수정 원본으로 사용하지 않는다.

## 네 단계 라운드 구성

각 10라운드는 5종 기본 상황을 변주하지만, 다음 단계는 수량 증가뿐 아니라 순서·역할·출현 시차가 바뀐다.

- 3-6: 1–10 외곽 장갑/차폐와 빠른 추격; 11–20 묶음 순서 반전과 2.2초 간격 교차; 21–30 탱커 선봉 뒤 3초 지연; 31–40 8초 차폐 꼬리와 9초 추격으로 안쪽 재교전 압박.
- 3-7: 1–10 절벽 전후 두 대열; 11–20 후속 묶음을 4초 더 늦춤; 21–30 차폐 선봉 뒤 본대 3초; 31–40 15초 빠른 적 꼬리로 중앙 남쪽 귀환과 최후 두 칸을 재시험.
- 3-8: 1–9 홀수 위/짝수 아래 단일 경로 중심(5는 양쪽 복습); 11–19 첫 적의 이론상 합류 도착시각을 맞춘 서로 다른 경로 묶음; 21–29 8초 차폐 추가; 31–39 12초 빠른 후속. 한 묶음은 모두 같은 경로를 따르며 난수 분기는 없다. 합류 맞춤은 경로13/17보행×48px÷기본 속도의 차이만 사용하므로 실제 상태이상·사격·프레임 효과까지 동기화한다고 보장하지 않는다.
- 3-9: 1–10 작은 장갑/일반 대열; 11–20 일반 병력을 덜고 탱커 선봉+3초 장갑으로 능선 공성; 21–30 후속을 3.5초 늦추고 차폐 보강; 31–40 일반 대열을 덜고 14초 빠른 추격.
- 3-10: 1–20 홀수 A/짝수 B, 11부터 탱커 선봉과 후속2초; 21–30 후속2.5초, 31–40 차폐 꼬리10초. 양쪽 동시는 22·25·28·30·33·35·38·40이며 나머지는 계속 단독 교대한다. 동시 라운드는 본대 수량을 A/B로 나눠 총 물량을 무조건 두 배로 만들지 않는다. 글로벌 스폰 최소 간격0.18초는 유지하므로 같은 시각 요청도 안정 순서로 미세 분산된다.

## 보스·보상 이정표

모든 맵은 10·20·30·40에 forgeBoss 1기다. 10은 보스0초 뒤 호위+3초, 20은 탱커/장갑 선봉 뒤 보스6초, 30은 차폐 선봉 뒤 보스4초, 40은 보스1초 뒤 차폐11초·추격15초의 이중 꼬리다. 3-8은 묶음별 경로, 3-10은 파쇄자의 A/B 경로도 미리 표시한다.

기본 클리어 골드는 `24 + (챕터 내 단계−6) + 라운드`; 5·15·25·35는 `25+라운드` 추가, 보스 라운드는 `65+2×라운드` 추가다. 최초 클리어는 각 코어 포인트2, 모듈권0. 기존 스테이지의 최초 보상·연구/포탑 해금·순번은 변경하지 않았다. 신규 ID26–30은 기존3-5(ID15) 뒤에 이어져 내구도 순번26–30을 쓴다.

## 콘텐츠/런타임 경계

포탈은 `spawnPortals`(A/B), 경로는 `routes`와 `spawnPortalId`, 출현 묶음은 안정 `id`와 `routeId`로 구분한다. 그룹의 포탈 선택은 경로에서 유도한다. 컴파일러가 전역 최소 간격0.18초·원본 동률 순서로 스폰 큐와 소유 그룹을 함께 만들고 `groupDispatch`에 실제 시작/마지막 시각과 소유 큐 인덱스를 기록한다. HUD와 전체200라운드 표는 이 메타데이터를 그대로 사용하고 각자 그룹을 펼치거나 정렬하지 않는다. [필드·시간 기준](../../godot/content/README.md#스폰-정책묶음-디스패치-메타데이터)을 따른다.

## 검증 범위

- `scripts/test_chapter_three_content.py`: 승인 지형 fingerprint·건설칸·즉시 분기·전송 좌표, 200라운드, 보스/경로 예고, 단계별 타이밍 차이, 기존25맵 typed digest 보존.
- `scripts/test_content_compiler.py`, `test_content_runtime_format.py`, `test_stage_durability.py`: 기존 콘텐츠 비교는 기존 fixture의25맵에 계속 적용하고 신규맵은 추가 검사. 기존 fixture를 새 콘텐츠로 덮어써 차이를 감추지 않는다.
- `scripts/verify_godot_content.py`: 원본/생성물 최신성,30×40×8 내구도 정의 및 진행 registry.
- 네이티브 경로 이동·저장/복원·표시는 해당 Godot 회귀 검사로 확인한다. 이 문서의 정적 감사는 실플레이·밸런스·Android 검증을 통과했다는 뜻이 아니다.

### 재사용 가능한 실제 스탯 전투 fixture

`godot/session/chapter_three_combat_fixture.gd`는 계정/온라인 저장과 격리된 테스트 프로필이다. 앞선 스테이지 클리어, 영구 강화 최대30·연구 최대3, 런 골드60,000·젬 조각1,000·해금 젬 각60개를 초기 조건으로 둔다. 건설칸을 행 우선 순서로 순회해 해금 포탑을 번갈아10–12개 배치하고 레벨10, 링크2회, 호환 젬 최대3개, 런 강화 각10회를 정상 명령으로 구입한다. 코어 전투 스킬과 모듈을 선택한 최적 조합은 아니다. 적/코어 체력, 포탑 공격력, 경로, 스폰 시각을 별도 덮어쓰지 않는다.

`verify_chapter_three_normal_combat.gd`는 각 맵의10·20·30·40라운드를 **독립적으로 시드한 사례**에서 사격·피해·처치·도착·보상 수집과 일시정지 저장 후 새 런타임의 전투 지속을 검사한다. 앞선39라운드부터 연속 플레이한 경제·배치 결과나 초회 이용자의 적정 난이도를 보장하는 검사는 아니다. 짧은 경로의 후반 라운드에서 사격해도 처치 없이 적이 도착할 수 있으며, 이는 별도 전략/밸런스 플레이테스트가 필요한 항목이다. 기능 확인을 위해 적 내구도를 낮추거나 코어 체력을 늘려 통과시키지 않는다.

`verify_chapter_three_combat_render.gd`는 실제 앱 처리 루프·HUD 조작·렌더러를 사용한다. 각 사례의 사격/투사체/피해/처치/보스 표적, 일시정지·4배속 이후 시간 진행, 전송 또는 두 경로, 분기/양쪽 입구의 디스크 저장→새 런타임 복원→추가 피해가 모두 관측되면 종료한다. 보고서의 `fullWaveCompletion=false`는 이 렌더 검사가 웨이브 끝까지의 승리나 보상을 확인했다는 뜻이 아님을 명시한다. 자연 종료·보상은 별도의60Hz 회귀 검사 근거로 구분한다. 앱 저장의 네이티브1타일 계약은 `verify_chapter_three_combat_checkpoint.gd`로 먼저 검사한다.
