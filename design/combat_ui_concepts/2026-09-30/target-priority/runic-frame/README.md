# 공격 목표 룬 프레임 제작 원본

역할: 승인된 [3번 시안](../frame-concepts/03-runic-edge.png)의 프레임·라디오 제작 입력과 재사용 가능한 편집 원본. 확인: 2026-09-30. 실제 Godot 화면·동작 검증 결과는 아래 통합 검증에서 관리한다.

- 추가 생성 없이 기존 GIMP 3.2.4 MCP 인스턴스를 재사용했다. 기존에 열려 있던 이미지와 미저장 작업은 수정하지 않았다.
- 프레임은 승인 이미지의 `(653, 930, 211, 358)` 영역을 크롭했다. 금속 모서리 네 개와 청록 측면 룬은 원본 픽셀을 유지하고, 바깥 배경만 투명 처리했다.
- `target-priority-frame.xcf`는 숨긴 승인 원본, 외곽 알파를 분리한 원본 프레임, 글자·라디오·선택 행을 제거한 남청색 내부 복원 레이어를 보존한다. 내부색은 위 `#07131e`에서 아래 `#04090e`로 이어진다.
- `target-priority-frame-master.png`는 211×358 RGBA 제작본이다. 게임용 [frame.png](../../../../../assets/images/ui/hud/target_priority/frame.png)는 GIMP cubic 보간으로 104×180에 맞췄다.
- `radio-checked.xcf` / `radio-unchecked.xcf`는 각각 `(681, 966, 32, 32)` / `(681, 1029, 32, 32)` 영역에서 원본 라디오를 추출한 32×32 편집본이다. 외곽은 원형 알파로 정리했다. 게임용 라디오는 16×16 RGBA이며 실제 링의 지름은 약 14px이다.

게임 프레임의 9patch 고정 영역 권장값은 좌우 11px, 위 94px, 아래 18px이다. 측면 룬이 있는 위쪽을 고정하고 룬 아래의 직선 영역을 늘린다. 콘텐츠 여백은 별도로 좌 10px·우 9px·상하 10px을 적용한다. 선택 행의 원본 배경 샘플은 RGB `(9,32,45)` / `(10,32,44)`이므로 동적 선택 배경에는 `#0a202c`와 모서리 반경 4px을 권장한다.

제작본 직접 시각 확인에서 단일 모서리 깎인 외곽, 네 금속 코너, 작은 청록 룬, 빈 남청색 내부를 확인했다. PNG 크기·알파를 확인했고 제작본 테두리의 대표 기준점 7개 RGB는 승인 원본과 같았다. 인게임 크기·배치·조작 검증은 이 기록의 범위 밖이다.


## 실제 적용·통합 검증

승인된 프레임·라디오 PNG를 `target_priority_popup.gd`의 `PopupPanel`·표준 `VBoxContainer`·목표 행 버튼에 연결했다. 프레임은 `StyleBoxTexture`로 표시하고 룬이 있는 고정 영역을 유지한다. 목표 이름은 실제 텍스트 노드로 표시하며, 현재 목표의 `#0a202c` 행 배경과 청록 라디오는 초점·hover와 별개로 유지한다. 목표 선택·연구 해금·저장 명령과 우측 정렬·아이콘 위 목록·전투 지속 계약을 보존한다. 자동 진행 메뉴의 기존 프레임은 이 변경에 포함하지 않는다.

2026-09-30 독립 검증 PASS. Godot 4.7.2 / macOS Metal Forward Mobile / Apple M4의 격리된 실제 `--app` 실행에서 440×900·320×900 화면을 승인 3번과 직접 비교했다. 청동 코너 네 개·작은 청록 측면 룬·모서리 깎인 단일 외곽·남청색 내부·현재 선택 강조를 확인했다. 상단 추가 배경·잘림·겹침 결함이 없으며 부모도 최종 캡처를 직접 검토했다.

실제 포인터로 목표 변경·재열기·Esc·밖 클릭을 확인했고, 공유 뒤로 핸들러·포탑 전환·stale ID 보호·다른 모달·연구 잠금도 통과했다. 목록을 연 실제 웨이브에서 전투 시간이 증가하고 일시정지되지 않음을 확인했다. 관련 `verify_battle_hud.gd`·`verify_modal_input.gd` 회귀가 통과했고, 최종 선택 배경색에서 `verify_battle_hud.gd`를 다시 통과했다. Android 전용 변경이 아니므로 이번 작업에서 APK·실기기 검증은 수행하지 않았다.
