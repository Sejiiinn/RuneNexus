최종 비교: [comparison.png](comparison.png). 내장 ImageGen으로 제작했다. 최초 요청은 [prompt.txt](prompt.txt), 수량·연결선 보정은 [revision-prompt.txt](revision-prompt.txt)와 [final-correction-prompt.txt](final-correction-prompt.txt)에 기록했다. 초기 생성본은 `comparison-v1.png`이며 최종 판단에는 사용하지 않는다.

## 세 안

1. 소켓 팝오버: 패널 밖 작은 확인창에 비용과 해금 버튼을 둔다. 목록을 유지하지만 전장 일부를 가리고 선택 소켓과 거리가 생긴다. 바깥 탭으로 취소한다.
2. 고정 상세행: 소켓과 보유 목록 사이에 같은 높이의 상세행을 항상 확보한다. 장착 젬 선택 시 이름·효과와 해제, 빈 소켓 선택 시 안내, 잠금 선택 시 비용과 해금을 교체 표시한다. 레이아웃과 버튼 위치가 안정적이므로 우선 추천한다.
3. 소켓 직결 버튼: 상세행의 높이는 고정하고 선택 잠금 소켓 바로 아래에 비용과 해금 버튼을 붙인다. 선택 대상이 직관적이나 최대 6개 및 가장자리 선택에서 버튼 위치를 제한해야 한다. 소켓을 누르는 것만으로 결제하지 않는다.

## 공통 동작과 검수

- 세 화면 모두 기본 소켓 3개(장착 1개, 잠금 2개)를 한 줄로 표시한다. 연구 전 4~6번 소켓은 숨기고 연구 후 최대 6개를 한 줄로 지원한다.
- 잠금 선택 중 보유 젬 목록을 유지하고 패널·상세행 높이가 변하지 않는다. 해금 조작을 위한 스크롤을 추가하지 않는다.
- 비용 90 G는 각 화면에 한 번, 구매 버튼은 ‘해금’만 표시한다. 개수 변화·잔액 변화·해금 완료 문구·추가 버튼은 없다.
- 보유 목록은 48px 정사각형 6칸이 기준이며 0개일 때도 빈칸을 유지한다. 생성 이미지 오른쪽 끝의 희미한 빈 윤곽은 별도 7번째 칸을 요구하지 않는다.
- 최종 래스터에서 세 개의 원형 소켓, 여섯 종류 보유 젬, 기존 청록 금속·금색 소켓·젬 형태, 상단 HUD·전장·선택 포탑 액션·하단 탭 보존을 확인했다.
- 터치 목표는 해금 버튼 최소 44×44px이다. 이 이미지는 시각 비교용이므로 실제 히트 영역·320px 폭·최대 6개·0개 상태는 구현 선택 후 별도 확인 대상이다. 생성된 전체 화면 비율과 버튼 실측치를 구현 치수로 복제하지 않는다.
- 1안의 작은 팝오버가 수동 진행 UI 부근에 가까워진다. 이 배치 약점 때문에 2안을 추천한다. 3안은 비용과 선택 소켓의 거리를 가장 짧게 만드는 대안이다.

## 이전 승인 및 적용 방향

사용자가 3번 소켓 직결 방식을 선택했다. 잠긴 소켓 아래 작은 실제 가격 태그를 미리 표시하고, 선택 소켓 아래 해금 버튼을 배치한다. 비용은 태그에서 한 번만 보여준다. 기본 1개 개방·최대 3개, 연구 밖 소켓 숨김, 최대 6개 가로 연결을 유지한다. 보유 젬 목록과 패널 높이는 선택 전후 유지하며, 거래 조건과 장착 동작은 기존 규칙을 따른다. 이전 2번 추천은 선택되지 않았다.

## 이전 구현 검증

3번과 가격 태그를 Godot에 적용했다. 기존 StyleBoxTexture 배지(10px 글자/18px 높이), 고정 64px 상세 공간, 선택 소켓 아래 금색 연결부와 해금 팝오버를 사용한다. 실제 할인 포함 가격은 복제한 견적 상태에서 기존 도메인으로 계산하며 플레이 상태를 바꾸지 않는다.
