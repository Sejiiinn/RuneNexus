# 전투·표시 스탯 계산 공유

> 원시 로그·일회성 검사·측정 덤프는 로컬 기록으로 Git 추적에서 제외했다. 본문의 요약 결과와 유지되는 회귀 테스트는 보존하며, 아래 로컬 기록은 새 체크아웃에 포함되지 않는다.

2026-09-28. [표시용 캐시 개선](../display-cache/README.md)에 이어, 전투와 HUD·선택 표시가 동일한 기본 스탯을 한 번 계산해 재사용하도록 연결했다. 현행 입력·소유권·캐시 제한은 [콘텐츠 계약](../../../../../../godot/content/README.md)에 기록한다. 피해 공식·저장 스키마·명령 스키마·전체 전투력 및 코어 피해 합산은 유지한다.

## 검증

- 관련 회귀 로그 (`implementation-regressions.log`, 로컬 기록): 신규 공유 계산 및 기존 전투·웨이브/코어·피해·런 명령·선택·HUD 검사 통과. 신규 회귀는 282개 원본 입력에 거리·코어 배율·연쇄 정리 조합을 적용한 3,384개 결과를 원래 계산과 정확히 대조한다.
- [별도 Astra 독립 검증](independent-review.md): 실제 `Stats.stats_at()` 진입을 별도 계측해 개별 강화 1회·미리보기 1회·미리보기 확정 0회·반복 갱신 0회를 확인했다. 23개 통합 상태의 전투·선택·HUD·수호광선·저장 스냅샷과 저장 복원 검사가 통과했다. 충돌 시 전체 입력 비교, 캐시 소유권 및 256개 한도도 확인했다.
- 실제 앱 89개 검사 (`app-result.json`, 로컬 기록): 스테이지 15, 320/440px, 마우스 강화 미리보기·확정 및 런 구매. 새 미리보기의 전투·표시 공통 계산은 1회, 강화 확정 시 추가 계산은 0회, 서로 다른 2개 포탑의 전체 화력 업그레이드는 2회다. 합산 전투력과 선택 범위는 원 `stats_at()` 직접 호출 결과와 비교했다. 실행 코드 (`verify-app.gd`, 로컬 기록) · 로그 (`app.log`, 로컬 기록) · 입력 해시 (`app-inputs.json`, 로컬 기록).
- [440px 강화 확정](stage15-440-confirmed.png) · [320px 미리보기](stage15-320-preview.png) · [320px 런 구매](stage15-320-run-upgrades.png).

실제 앱 검사는 이전과 같은 격리 프로젝트·저장 영역에서 수행했다. 저장 복원이 동일한 입력을 미리 캐시에 넣을 수 있으므로 계산 횟수 측정 직전에 공용 캐시를 비운다. 처음 전체 강화의 추가 계산이 0회였던 것은 이전 격리 저장과 같은 입력을 재사용한 정상 결과였다(진단 로그 (`app-diagnostic.log`, 로컬 기록)).

Android/A34 실기기 지연과 전체 FPS 개선량은 미측정이다. 저장 검증·파일 쓰기 병목은 이번 변경 범위에 포함하지 않았다.
