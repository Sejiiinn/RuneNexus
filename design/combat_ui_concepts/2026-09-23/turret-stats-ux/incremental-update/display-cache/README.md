# 표시용 포탑 스탯 캐시

> 원시 로그·일회성 검사·측정 덤프는 로컬 기록으로 Git 추적에서 제외했다. 본문의 요약 결과와 유지되는 회귀 테스트는 보존하며, 아래 로컬 기록은 새 체크아웃에 포함되지 않는다.

2026-09-28 후속 개선. [기존 UI 기준](../../README.md)의 외형·수치·조작을 보존하며, 선택 표시와 HUD가 포탑별 최종 계산 입력이 같은 결과를 재사용한다. 전체 전투력 합산은 유지하고 선택 범위의 1타일 좌표와 HUD의 48픽셀 좌표를 구분한다. 현재 레벨과 미리보기 결과는 별도로 보관하며 캐시 크기를 제한한다.

실제 `main.tscn --app` 스테이지 15의 마우스 강화 미리보기·확정·런 구매·탭 전환과 320/440px 화면을 확인했다. 캐시 없는 전체 전투력 및 개별 범위와 비교한 86개 검사 (`app-result.json`, 로컬 기록)가 통과했다. 실행 소스 (`verify-app.gd`, 로컬 기록) · 로그 (`app.log`, 로컬 기록) · 입력 해시 (`app-inputs.json`, 로컬 기록). 프로젝트와 저장 영역은 [이전 검사](../README.md)의 격리 경로를 재사용했다.

[320px 미리보기](stage15-320-preview.png) · [440px 강화 확정](stage15-440-confirmed.png) · [320px 런 구매](stage15-320-run-upgrades.png). Android/A34 실기기 시간 및 전체 FPS 개선량은 측정하지 않았다. 저장 검증·파일 쓰기 경로는 변경하지 않았다.

콘텐츠 제작 도구가 성장 카탈로그 내부를 직접 변경할 때는 캐시의 `invalidate()`를 호출한다. 실제 플레이의 성장 상태 변경과 성장 객체 교체는 자동 감지한다. HUD에서 추가하는 표시 전용 필드는 복사본에 기록해 캐시 원본을 보존한다. 이 후속 변경은 화면 수치·외형에 영향을 주지 않으며 입력 해시에 변경 사유와 최종 해시를 함께 기록했다.

관련 회귀 (`implementation-regressions.log`, 로컬 기록)와 [별도 Astra 독립 검증](independent-review.md)이 통과했다. 독립 19상태에서 6포탑의 반복 갱신은 실제 스탯 계산 0회, 개별 레벨업은 대상 포탑의 HUD·선택 좌표계별 1회로 확인했다. 전체 스탯·합산 전투력·선택 범위와 젬 장식은 캐시 없는 결과와 일치했다. 전역 성장·다양성·삭제/재생성·세션/카탈로그 교체 및 명시 무효화를 포함한다.
