# 업그레이드 수치 갱신

2026-09-28. [승인 UI 기준](../README.md)을 보존하며 포탑 강화 미리보기·확정, 런 업그레이드에서 기존 노드를 재사용한다. 변경값만 갱신하고 조건부 스탯 행은 필요한 경우에만 추가·제거한다. 특성·판매 콜백은 현재 도메인 상태를 조회한다. 전체 전투력 합산과 코어 계산, 저장·차감 계약은 유지한다.

사용자의 후속 요청에 따라 큰 수치와 구매 가격·판매 환급액에 K/M을 사용한다. 1,000 미만은 기존 표시 정밀도를 유지하고 축약값의 불필요한 소수 0은 제거한다. 구매 가격·판매 환급액은 3유효숫자(`1.25K`, `12.5K`, `123M`)로 축약해 숫자와 단위가 한 줄에 읽히도록 한다. 정확한 수치는 기존 컨트롤의 툴팁에 제공하며, 표시 문자열로 구매 가능 여부를 판정하지 않는다.

표시용 전체 스탯 재계산도 후속으로 줄였다. HUD와 선택 표시가 변경되지 않은 포탑의 계산 결과를 재사용하며 전체 전투력 합산은 유지한다. [표시용 캐시 구현·검증](display-cache/README.md). 이어서 전투와 표시 경로도 기본 스탯 결과를 공유하도록 통합했다. [공유 계산 구현·검증](shared-stats/README.md).

## 검사 근거

- `implementation-tests.log`: 기존 HUD·UI 레이아웃·런 명령 검사와 노드 ID 유지, 반복 구매, 최신 금액, 긴 가격 회귀.
- `independent-result.json`, `independent.log`, `independent-verify.gd`: 별도 Astra가 준비한 노드 유지·상태·콜백·전체 전투력·코어 검사. 추가 검증은 해당 `independent*` 자료에 기록한다.
- `app-result.json`, `app.log`, `verify-app.gd`: 실제 `main.tscn`/`--app` 경로의 스테이지 15, 두 포탑 배치와 마우스 입력, 320/440px 레이아웃. `app-inputs.json`은 실행 사본의 관련 UI 입력 해시다.
- `stage15-440-confirmed.png`, `stage15-320-preview.png`, `stage15-320-run-upgrades.png`: 실제 앱의 강화·런 업그레이드 화면.
- `stage15-320-large-values.png`, `stage15-440-large-values.png`, `stage15-320-large-run-price.png`: 실제 앱 UI에 큰 값을 주입한 가독성 검사용 화면. 정상 게임의 가격·밸런스를 뜻하지 않는다.

실행은 별도 프로젝트·저장 영역에서 Godot 4.7.2 macOS Metal Mobile로 수행한다. 준비 에셋·캐시를 독립 복사하고 변경 소스만 반영하며 열린 Godot 편집기와 사용자 저장은 변경하지 않는다. 검사 프로젝트 위치는 `project-path.json`에 있다. 실제 실행 예:

```sh
Godot --path <격리 프로젝트> --resolution 440x900 --script res://verify-incremental-app.gd -- --app
```

렌더 검수 중 발견한 여러 줄 가격의 프레임 겹침은 내용 높이와 안쪽 여백을 기존 버튼에 전파하도록 수정했다. 모달 닫기 애니메이션 완료 후 다음 입력을 보내도록 검수 스크립트도 보완했다. 최종 실제 앱 검사는 123건 통과했으며, 320/440px의 축약 구매 가격은 한 줄 표시를 확인했다. `app-inputs.json`의 후속 변경 항목은 화면에 영향을 주지 않는 음수 가격 포맷 경계 수정과 최종 해시를 기록한다. Android APK·A34 실기기 성능과 FPS 개선량은 측정하지 않았다.
