## 실제 화면과 조작

Godot 4.7.2 / Metal 4.0 Forward Mobile / Apple M4. `build/godot/run-upgrades-review`와 전용 `RuneNexus-TurretStats-Review` 저장 경로를 사용했다. 공용 에디터와 사용자 플레이 인스턴스는 조작하지 않았다.

- `base-440.png`, `arrow-320.png`: 포탑 정보 → 특성 → 강화 → 판매 순서, 기존 금속 외형·비율·스탯/젬 링크 탭 보존. 2열 스탯, 별도 누적 피해, 여유 행 간격과 공격 목표 버튼 확인.
- 태그는 작고 독립된 프레임. 물리 F4F7FA, 원소 9FFFE8, 경량 E7C66A, 중화기 FF8A2A, 지속피해 9DFF4A를 기존 젬 팔레트와 대조했다. 냉각은 기존 분류색 7FD8FF. 320px 화염·냉각·기관총·대포·저격·라이트닝 화면 확인.
- `arrow-preview-320.png`, `preview-440.png`, `gems-preview-440.png`: 현재/다음값과 강화 확정, 젬 탭에서 시작한 미리보기 확인.
- `verify.gd` 실제 포인터 입력으로 목표 연구 잠금/해금·후미 선택, 강화 미리보기/확정, 특성 두 단계 선택, 판매 취소/확정·환급, 스탯/젬 링크 전환 검증. 1,218 검사, 실패 0 (`result.json`, `verify.log`).
- `live-damage.log`: 직접·범위·연쇄·화상 피해 합계 102.5 → 113.0 갱신, 동일 라벨과 스탯 그리드 인스턴스 유지. 3 검사 실패 0.
- `dense.log`: 긴 레벨 미리보기·123456 G 가격의 320/440 폭 회귀 PASS. 캡처 `synthetic-dense-fixed-{320,440}.png`.
- `battle-hud.log`: 준비 프로젝트에서 기존 `verify_battle_hud.gd` 회귀 PASS. 현재 업그레이드 PurchasePrice 구조에 맞지 않던 과거 기대값은 구현 담당이 수정했다.

## 발견 및 수정 확인

초기 스탯 컨테이너가 레이아웃 전 최소높이로 260px까지 늘어나 큰 빈 공간과 320px 누적피해 잘림이 발생했다. 구현 담당이 실제 행 기준 높이로 수정하여 4행 160px, 누적 피해 전체 노출을 확인했다. 확장된 패널 뒤 전장이 글씨와 겹치던 문제도 선택 포탑 스탯 패널의 남색 배경 불투명도 조정으로 해결됐다.

최종 소스와 실행 사본의 일치 근거는 `source-evidence.json`에 기록했다. 시각 확인은 이미지의 모든 픽셀 복제보다 승인된 구조·재질·정보 위계·가독성을 기준으로 했다.

## 한계
