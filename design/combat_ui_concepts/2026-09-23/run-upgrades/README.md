# 인게임 업그레이드 탭 시안

역할: 2026-09-23 인게임 업그레이드 시안과 채택 기준. 사용자는 05를 구현 기준으로 채택하고, 제목·범위 안내 상단바 제거를 추가 요청했다. 01~04는 비교 후보 기록이다.

## 채택 기준

[05](05-clean-rows.png)의 세로 3행, 기존 아이콘·이름·레벨·설명·현재→다음 효과, 우측 금속 구매 버튼을 유지한다. 행별 명패 없이 공용 남색 바탕과 얇은 구분선을 사용한다. 이미지에 남아 있는 ‘업그레이드’ 제목과 ‘이번 전투에 적용’ 문구 및 그 상단바는 **구현에서 제거**한다. 하단 업그레이드 탭의 선택 표시로 화면을 식별한다. 수치는 실제 런 데이터에 연결하고 연구 상한·부족·최대·구매 후 갱신을 유지한다.

## 시안 기록

- [시안 원본](01-run-upgrades.png): 전투 하단의 포탑 화력·처치 보너스·정비 보급을 세로 3행으로 정렬. 아이콘, 레벨, 효과 비교, 구매 비용을 구분한다. 가운데 업그레이드 탭을 선택한다.
- 추가 3개는 사용자 요청에 따라 내장 ImageGen을 병렬 호출하여 제작했다. [금속 명패형](02-metal-rows.png)은 행과 구매 영역이 이어지는 구조, [가로 3열형](03-three-columns.png)은 세 업그레이드를 나란히 배치하는 구조, [압축 표형](04-compact-table.png)은 현재·다음·구매 열로 비교하는 구조다. [추가 생성 프롬프트](prompts-variants.json).
- [05 행 프레임 제거형](05-clean-rows.png): 사용자 후속 요청에 따라 02의 아이콘·텍스트·구매 버튼 배치를 유지하면서 행별 명패 외곽과 입체 바탕을 제거했다. 공용 남색 바탕에 얇은 구분선만 사용하고 구매 버튼의 금속 외형은 유지한다. 내장 ImageGen으로 편집했다. [프롬프트](prompt-05-clean-rows.txt).
- 짙은 남색·청록과 얇은 금속 프레임, 기존 업그레이드 아이콘을 사용했다. 로비 영구 강화나 개별 포탑 강화 화면이 아니다.
- [생성 프롬프트](prompt.txt). 내장 ImageGen 사용, 876×1795 PNG.
- 배경·HUD 참조: [실제 화면](../../2026-09-22/resource-hud/strict-440.png). 값은 기본 Lv.0의 예시이며 구현 시 실제 런 데이터에 연결한다. 생성 이미지의 주변 지도·HUD 미세 차이는 변경 제안 대상이 아니다.

독립 Astra 시각 검수: 01~04 모두 PASS. 최종 이미지를 직접 확인하고 원본 화면·기존 아이콘과 대조해 테마, 탭 순서·선택, 세 항목의 명칭·레벨·효과·비용·구매 의미를 확인했다. 02의 행·구매 영역, 03의 열별 정보 대응, 04의 공통 구매 제목과 가격 버튼이 명확하다. 심한 겹침·누락이나 새 기능 추가는 없다.

아래 시각 검수는 이미지 제작 단계의 기록이며 실제 게임 구현·조작 검증과 구분한다.

05 독립 Astra 시각 검수: PASS. 행별 명패 제거와 얇은 구분선, 기존 정보·구매 버튼·테마 보존을 직접 확인했다. 잘림·겹침·정보 누락이 없다. 실제 동작·반응형 검증은 범위 밖이다.

## Godot 구현·실행 확인

`godot/ui/hud_build_panel.gd`의 업그레이드 표시와 `battle_hud.gd`의 업그레이드 명칭·공용 도크 선택만 변경했다. 기존 구매 명령·quote·효과 데이터와 자원 변경 시 버튼 갱신을 재사용한다. 행별 프레임과 제목바 없이 기존 아이콘, 흰색 이름, 회색 설명·레벨, 청록 다음 효과, 금속 구매 버튼을 배치했다. 최대 레벨에는 다음 효과·비용 대신 현재 효과와 비활성 ‘최대’를 표시한다.

- 실제 화면: [440px](implementation/normal-440.png), [320px](implementation/normal-320.png). 본문 높이는 각각 196px·190px로 기존 198px 상한 안에 3행 모두 표시된다.
- 관련 상태: [골드 부족](implementation/poor-320.png), [구매 후](implementation/purchased-320.png), [최대](implementation/max-320.png), [연구 상한 확장·긴 가격](implementation/research-320.png).
- [검증 스크립트](implementation/verify.gd)와 [실행 로그](implementation/verify.log): Godot 4.7.2, macOS Metal Forward Mobile 실제 렌더. 320×760·440×900에서 텍스트/행 경계, 제목바 부재, 실제 클릭 구매·골드 차감·레벨/효과/가격 갱신, 골드만 바뀔 때 버튼 객체 유지와 disabled/색 갱신, 기본 MAX, 연구 최대30·비용 할인·확장 MAX 구매를 확인했다. 파서/런타임 오류 없음.
- 실행 사본은 `build/godot/run-upgrades-review`, `user://`는 `RuneNexus-RunUpgrade-Review`로 분리했다. 기존 준비 사본에 누락된 최신 UI 에셋·냉각 안개 GLB를 동기화한 뒤 최종 캡처했다. 사용자 저장·에디터 세션은 변경하지 않았다. [관련 입력 해시](implementation/inputs-sha256.json).
- Android·배포·실계정 검증은 이번 변경에 포함하지 않았다. 푸시·배포는 수행하지 않았다.

최종 독립 Astra 검증 **PASS**: 05와 최종 실제 320/440·부족·구매·MAX·연구 화면을 직접 대조했다. 최초 검수에서 지적한 명칭·공용 남색 바탕·아이콘 및 정보 열 비율을 수정한 결과를 재확인했다. 최종 소스와 실행 사본 해시, 저장 격리, 검증 스크립트의 실제 입력·상태 검사 범위와 오류 없는 최종 로그를 자체 확인했다. Android 실기기는 미검증이다.

재실행은 준비된 격리 사본에서 다음 명령을 사용한다. 테스트는 해당 사본의 저장 경로를 검사하고 런의 테스트 성장값을 초기화한다.

```sh
build/godot-preview/tools/Godot.app/Contents/MacOS/Godot --path build/godot/run-upgrades-review --resolution 440x900 --script "$PWD/design/combat_ui_concepts/2026-09-23/run-upgrades/implementation/verify.gd" -- --app
```
