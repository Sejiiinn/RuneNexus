# 젬 UI 구현·검증

2026-09-23. [승인 기준](../README.md)을 기존 Godot Container·Theme·StyleBoxTexture와 공용 젬·소켓·연결부 PNG로 구현했다. 구매 명령·가격·성장·저장 규칙은 유지한다.

- 기본 1개 개방/최대 3개, 잠금 클릭으로 인라인 해금, 잠긴 소켓마다 실제 가격 태그를 미리 표시하고 선택 소켓 아래 작은 해금 팝오버를 연다. 상세 공간을 고정 예약해 보유 젬 목록과 패널 높이를 유지한다. 성공 시 새 소켓 선택. 변화량·완료 안내·별도 추가 버튼은 없다.
- 연구 수용량 밖은 숨기며 최대 6개까지 가로 연결한다. 작은 화면에서 소켓 크기를 조절한다.
- 보관함은 34px 공용 이미지·수량·이름·효과를 분리해 440px 3열, 320px 2열로 표시한다. 포탑별 보관함은 작은 이미지 타일이다.

## 검증 근거

- `godot/verify_gem_ui.gd`: 순차 구매, 실제 비용, 재화 부족, 취소, 레벨 제한, 중복 입력, 연구 확장, 320/440px 소켓, 장착·해제·호환성, 14종 보관함 검증. [전체 로그](verify-gem-ui.log), [타일 후속 검사](verify-gem-strip.log).
- 최종 레이아웃 후속 검사: 동일 6개 소켓 노드의 440→320 리사이즈, 도크·본문 경계, 연결부 크기, 해금 버튼 스타일 PASS. [로그](verify-gem-layout.log). 독립 검증 에이전트가 해금·보관함·320px 6소켓 최종 이미지도 직접 확인해 PASS 판정했다.
- 기존 HUD 회귀 검사: [로그](verify-battle-hud.log).
- 실제 `AppLifecycle` 마우스 입력으로 해금과 정확한 골드 차감을 확인: [캡처 스크립트](capture.gd), [실행 로그](visual.log).
- 최종 화면: [해금](unlock-440.png), [열린 두 번째 소켓](opened-440.png), [보관함](inventory-440.png), [320px 6개 한 줄](six-320.png).

Godot 4.7.2의 격리 프로젝트 `build/godot/modal-v2-review`와 별도 사용자 저장 디렉터리로 검증했다. 사용자 플레이 저장은 수정하지 않았다. 현재 실제 성장 수용량 3→4는 도메인으로 검사했고, 5·6개는 UI fixture다. Android APK 검증은 수행하지 않았다.

## 이전 컴팩트 해금·빈 보관함 수정 기록

소켓 직결 방식 승인 전 단계에서는 해금 조작의 중복 제목과 수직 배치를 제거했다. 이 해금 방식은 이후 소켓 직결 팝오버로 대체됐다. 320/440px에서 본문 높이와 스크롤 영역 높이가 같음을 실제 앱에서 확인했다. [후속 구매 검사](verify-gem-compact-unlock.log)는 취소·구매 후 보관함 복귀와 중복 결제 방지도 포함한다. 포탑 젬 장착 화면 하단의 보유 젬 목록만 공용 프레임의 비조작 정사각형 빈 칸 6개(48×48px, 간격 3px)를 가로 한 줄로 표시한다. 별도 젬 보관함은 기존 빈 상태 안내로 원복했다. [포탑 장착 화면의 빈 목록](empty-strip-320.png).
