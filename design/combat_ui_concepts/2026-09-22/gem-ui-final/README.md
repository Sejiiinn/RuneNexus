# 젬 UI 승인 시안과 구현

2026-09-23. 승인 시안을 Godot 젬 UI에 반영했다. 구현·검증 근거는 [구현 기록](implementation/README.md)에 있다. 기본 소켓 수 기준은 [05-one-open-three-capacity.png](05-one-open-three-capacity.png), 최신 해금 UX는 [3번 소켓 직결 시안과 승인 내용](../../2026-09-23/gem-ux-rework/README.md)이다. 보관함의 작아진 젬 이미지는 03-six-inline.png의 왼쪽 화면을 참고한다.

## 확정된 요청

- 초기 열린 소켓은 **1개**, 기본 최대 수용량은 **3개**다. 처음에는 열린 1개와 골드 구매로 열 수 있는 잠긴 2개를 가로로 연결해 표시한다.
- 잠긴 두 번째 소켓 선택 → 실제 골드 비용 확인 → ‘해금’으로 구매 확정 → 두 번째 자물쇠가 사라지고 빈 소켓으로 바뀐다. 세 번째 소켓은 계속 잠겨 있다.
- 추가 수용량 4~6은 해당 해금 전에는 표시하지 않는다. 최대 6개까지 지원하되 항상 가로 한 줄로 연결한다.
- `+` 조작과 별도 슬롯 추가 버튼은 사용하지 않는다. 기존 표시된 잠긴 소켓 자체가 구매 진입점이다.
- 잠긴 소켓 아래 실제 가격 태그를 항상 표시하고, 선택 소켓 직하의 가격 태그를 가격·청록 해금 버튼이 연속된 일체형 금속 명패로 확장한다. 보유 젬 목록과 패널 높이는 그대로 유지한다. 같은 소켓 재선택이나 바깥 영역 선택으로 닫는다. 개수 변화·보유 골드 변화량·완료 안내는 표시하지 않으며, 성공하면 새 소켓을 선택한다.
- 그림의 300G에서 90G를 지불해 210G가 되는 수치는 예시다. 실제 레벨·비용·성장 조건과 구매 원자성은 기존 규칙을 따른다.
- 전역 보관함과 포탑별 젬 링크는 분리한다. 기존 14종 공용 젬 PNG, 소켓·연결부, 장착/해제/빠른 장착/호환 불가 사유를 보존한다.
- 포탑 젬 장착 화면의 보유 젬 목록은 약 48px 정사각형 칸을 가로로 나열하고 부족한 칸은 빈 프레임으로 오른쪽 끝까지 채운다. 화면 폭에 맞춰 칸 수와 크기를 조절하며 젬 이미지는 34px로 유지한다. 별도 젬 보관함의 빈 상태는 변경하지 않는다. 안내 문구만 남기지 않는다.
- 보관함은 이전 제안보다 젬 이미지만 약 15% 줄이고 이름·효과·수량 가독성을 유지한다. 하단 탭 순서는 포탑→업그레이드→젬이다.

## 제작과 검증

내장 ImageGen으로 [최신 지시문](05-prompt.txt)을 사용했다. 이미지의 세 단계에서 각각 3개 소켓을 확인했다: 젬/잠금/잠금 → 젬/선택된 잠금/잠금 → 젬/열린 빈 소켓/잠금. `+`와 4번째 소켓이 없는 것을 시각 확인했다.

이미지는 확대 흐름도이며 실제 도크 높이 변경 기준은 아니다. 구현은 기존 Container·Theme·StyleBoxTexture와 원본 에셋을 사용한다. 320/440px·최대 6개 한 줄·재화 부족·레벨 조건·구매 취소·중복 결제·장착 및 해제를 자동 검사와 실제 앱 화면으로 검증했다. 현재 성장 규칙의 기본 수용량은 3, 연구 후 4이며, 5·6개 표시는 격리된 UI fixture로 검사했다.

이전 01~04 이미지는 폐기된 중간안이다. 특히 04의 ‘기본 열린 3개’와 `+`는 잘못 해석한 것으로 현행 기준이 아니다. 기존 지시문은 생성 이력으로만 보관한다.
