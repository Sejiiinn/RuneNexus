# Godot 기본 StyleBoxTexture용 원형 에셋

`../nine-slice-source-v3.png`의 기존 source_rect로 6개 컴포넌트 전체를 자른 후 GIMP NoHalo로 25% 축소했다. 수동 재작화·재생성·9개 조각 분리는 하지 않았다. 투명 여백은 원형 손실 방지를 위해 유지했으며 축소 후 약 1~2px다. 정수 크기 반올림 때문에 가로·세로 배율에는 극소 차이가 있다.

- 게임 파일: `assets/images/ui/combat_components/native/`
- 좌표·최종 크기·해시·권장 여백: `extraction.json`
- 원본 크기 편집 파일: `*-source.xcf`
- 최종 크기 모음: `native-preview.png`, `native-preview.xcf`
- 재현: `extract_gimp.py` (GIMP Python batch)
- 검사: `check_png.py`, `verification.txt`

권장 texture margin은 모달 네 방향 14px, 버튼 네 방향 11px. 콘텐츠 여백은 모달 좌우 18/상하 16px, 버튼 좌우 14/상하 7px. 이 값은 실제 라벨 크기에 맞춰 조정 가능하며 원형 텍스처 경계값과 별개다.

시각 확인에서 모서리 금속·각진 윤곽·상태별 면색이 유지된다. V3 원본의 미세한 외곽 색 점은 그대로 남아 있다. PNG alpha는 0..254이며 외부에 완전 투명 픽셀이 존재한다. 원본과 픽셀 동일한 결과가 아니라 GIMP 축소본이다. 본게임 적용 검증은 이 추출 단계의 범위 밖이다.

## Godot 적용

- `godot/ui/combat_component_theme.gd`에서 `StyleBoxTexture`와 Theme 변형을 등록한다. 이미지 6개만 실행 자산 목록에 포함한다. 개별 54조각은 실행 목록에서 제거하고 이전 분할 폴더에 보관했다.
- 전투 모달, 특성·판매·공격 목표·젬 교체·결과 버튼에 연결했다. 기존 행동·저장 계약과 하단 도크 배치를 유지한다.
- 젬 보상·구매 선택 화면은 사용자 피드백에 따라 기존 색상 카드·파편 선택·배경으로 복원했다.
- 380px 미만에서는 스테이지 메뉴·종료 확인의 두 행동을 세로 배치해 긴 문구 잘림을 방지한다.
- Godot 4.7.2 macOS, 격리된 `hud-review-v4`에서 [HUD 회귀](hud-test.log) 통과. [440px 모달](../../modals/README.md), [320px 스테이지 메뉴](screens-320/01-stage-menu.png), [320px 특성](screens-320/04-traits.png)에서 프레임·글자 배치를 확인했다. Android는 이번 작업에서 검증하지 않았다.

## 시각 재검수·수정

- 제목 18px와 얇은 구분선, 본문 간격 10px로 모달 정보 위계를 정리했다. 닫기·특성 탭의 과한 금속 강조를 줄였다.
- 특성·공격 목표는 이름 14px/설명 12px와 좌측 정렬로 분리하고, 복수 효과는 줄을 나눴다. 선택 항목은 금색, 비활성 항목은 감쇠한다. 판매는 위험 색을 사용한다.
- 컨테이너 배치에 위치 트윈이 덮어쓰던 문제를 제거해 중앙 모달의 위치를 복원했다. 포탈은 기존 하단 시트 동작을 유지한다.
- 종료 확인·포탈 스탯의 한 글자씩 줄바꿈되는 문제를 고쳤다.
- 320·440px 실제 렌더에서 중앙 배치·긴 설명·선택 강조·포탈 수치·종료 보상을 다시 확인했다. 젬 보상·구매 카드 외형은 기존 유지. 성공·실패의 전용 결과 아트는 이번 정리에서 보존했다.

## 젬 교체 UX

- 보상 선택 카드는 보존하고, 포탑 슬롯이 가득 찼을 때의 교체 창을 재구성했다. 포탑·새 젬·기존 소켓/연결부·선택 젬 효과·교체 요약을 한 창에 표시하고 겹치던 전장 선택 안내와 바닥 버튼을 숨긴다.
- 슬롯 선택은 상태 미리보기만 수행한다. ‘선택한 젬과 교체’로 확정하며 기존 젬을 보관한다. 뒤로·재진입·정산 완료 시 선택을 초기화한다.
- ‘슬롯 추가 후 장착’은 기존 link 견적·레벨·최대 슬롯 조건을 따르고 보유 골드·부족액·제한 사유를 표시한다. `chooseRewardGemEquip`의 `buySlot:true`로 슬롯 구매·장착을 원자 처리한다. 실패하면 골드·장착·보상 상태를 변경하지 않는다.
- 도메인 회귀 4830 checks failures=[] 및 [보상 UI 회귀](replacement-test.log) 통과. [440px](replacement-440/10-gem-replace.png), [교체 선택](replacement-440/10b-gem-replace-selected.png), [320px 3슬롯](replacement-320/10c-gem-replace-full.png) 실제 화면 검수. 기존 사용자 저장과 분리된 미리보기 상태 사용.

### 소켓 표현 복구 및 독립 UX 검증

- 일반 젬 카드 목록을 제거하고 기존 `gem_socket_empty/selected` 및 `gem_link_active`를 사용한다. 64px 소켓과 24px 연결부를 소켓 중심에 정렬한다.
- 미해금·미구매 소켓은 잠금 표시 없이 숨긴다. 별도 ‘슬롯 추가’ 항목을 눌러도 미리보기만 수행한다. 확정 버튼 하나가 교체/추가 후 장착으로 바뀐다. 최대 슬롯일 때 구매 불가 버튼을 만들지 않는다.
- 선택 링과 체크, 기존 젬 반환·유지, 구매 후 골드를 상황에 맞춰 안내한다.
- UX 전담 에이전트와 기능 회귀 에이전트를 별도로 실행했다. [UX 검토 결과](ux-review.md). 실제 Android 터치 검증은 수행하지 않았다.

### 최대 6개 표시

- 일반 장착 탭과 보상 교체 창 모두 열린 소켓만 3개씩 두 줄로 배치한다. 행 안의 연결부 에셋과 선택 링을 유지한다.
- 현재 진행 데이터의 최대 슬롯은 3~4개이며 이번 변경은 해금 조건을 변경하지 않는다. 6개 상태는 사용자 저장과 분리한 UI 검증 fixture로 확인했다.
- [320px 6개 선택](replacement-320/10h-six-selected.png), [440px 6개 선택](replacement-440/10h-six-selected.png). UI 회귀에서 6개 렌더·2행·미해금 숨김·여섯 번째 미리보기 무변경을 확인한다.
