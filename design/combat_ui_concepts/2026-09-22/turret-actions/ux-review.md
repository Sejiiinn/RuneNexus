# 포탑 헤더 액션 UX 독립 검토

2026-09-22. 레벨업·판매·특성에 공통 두꺼운 버튼 프레임을 반복한 문제에 대한 수정 결과를 독립 검토했다. 범위는 포탑 헤더이며 스탯 표·젬·보상·판매 동작을 재설계하는 검토가 아니다. 소스 수정 없이 실제 Godot 캡처를 확인했다.

## 최종 판정

**제공된 320×760·440×900 데스크톱 Godot 캡처에서 UX PASS. 차단 결함 없음.**

- `after-320.png`, `after-440.png`: 레벨업·판매·특성 각각의 아이콘과 역할명이 구별된다. 두꺼운 금속 외곽 프레임 대신 얕은 어두운 배경과 얇은 하단선을 사용해 헤더의 시각적 밀도가 줄었다. 기존 스탯·젬 링크 연결 탭과 경쟁하지 않는다.
- 레벨업은 비용 `204 G`, 판매는 회수금액 `+45 G`, 특성은 진행 상태 `0/2 선택`으로 두 번째 줄의 의미를 구분한다. 비용과 환급액의 방향은 판매의 명시적 더하기 부호로 식별된다. 색만으로 역할을 구분하지 않으며 텍스트가 함께 남는다.
- `after-preview-320.png`: 미리보기 상태에서 레벨 `7 → 8`과 행동명 `강화 확정`이 동시에 나타나 다음 누름이 확정임을 설명한다. 새 레벨 수치 비교도 계속 보인다.
- `disabled-320.png`: 보유 골드 0에서 강화 액션이 비활성 톤으로 구별되고 비용은 유지된다. 판매·특성의 활성 표시와 혼동되지 않는다.
- `max-level-320.png`: 최대 레벨에서는 비용 대신 `최대 레벨`을 표시하고 비활성 상태로 나타난다. 존재하지 않는 다음 강화 비용을 제시하지 않는다.
- 320px에서도 포탑 이름·레벨과 세 액션의 이름·보조 정보가 잘리지 않는다. 스탯 3행과 하단 탭이 온전히 보이며 전장 가시 영역을 보존한다. 440px에서도 액션 의미와 위계가 동일하다.

## 검토 한계

캡처 판정은 가독성·위계·상태 구분에 한정하며 실제 클릭 실행, 판매 확인 절차, hover/focus, Android 터치 체감은 직접 실행 검증하지 않았다. 헤더의 조밀한 액션 높이는 실제 기기 터치 확인 범위로 남긴다. 기능 보존·회귀 결과는 구현 담당자의 검증과 구분한다.
