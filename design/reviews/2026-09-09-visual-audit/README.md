# 시각적 결함 검토 — 2026-09-09

현재 체크아웃 `96fca2f`의 기존 `tool/gem_reward_game_render_test.dart`로 젬 선택 → 장착 대상 선택 → 교체 상태를 렌더했다. 320×800, 390×844, 640×360의 통합 테스트 3개가 모두 통과했다. 이미지는 논리 화면 크기의 2배로 저장된다. 코드·게임 데이터는 수정하지 않았고 기존 렌더 파일은 보존했다.

브라우저에서는 중복 실행 안내가 나왔으며, Mac 잠금으로 기존 게임 탭에 접근하지 못했다. 아래는 현재 코드의 **테스트 렌더에서 확인한 결과**다. 실제 브라우저·기기의 전체 화면 검증으로 해석하지 않는다. 로비, 성장 화면, 전투 애니메이션은 이번 확정 결과에 포함하지 않는다.

## 1. 중간 — 가로 화면에서 교체창 복귀 버튼이 잘림

- 재현: 640×360에서 젬 선택 후 슬롯이 찬 대포의 교체창 진입.
- 관찰: `타워 다시 선택` 버튼은 최초 표시에서 아래쪽이 잘려 문구가 온전히 보이지 않는다. 내부 스크롤 후에는 버튼이 보이지만 포탑 이름과 레벨이 화면 위로 사라진다.
- 영향: 돌아가기 동작 발견이 늦어지고, 대상 포탑 정보와 복귀 액션을 동시에 확인하기 어렵다. 기능 자체가 불가능한 것은 아니다.
- 원인: `lib/ui/hud/gem_reward_target_overlay.dart:313`의 높이 제한 안에 제목·소켓·설명·복귀 버튼을 모두 하나의 `SingleChildScrollView`로 배치한다(332행).
- 수정 방향: 제목과 복귀 액션을 고정하고 젬 목록 부분에 스크롤을 배분한다. 기존 문구와 소켓 표기는 유지한다.
- 증거: [최초 표시](game_640x360_replacement.png), [스크롤 후](game_640x360_replacement_scrolled.png).

## 2. 중간 — 교체창 뒤 버튼의 시각 상태와 실제 동작 불일치

- 재현: 젬 교체창이 열린 상태. 세로·가로 모두 해당하며 가로에서는 설명과 버튼이 부분적으로 가려져 더 두드러진다.
- 관찰: 뒤쪽 `젬 다시 선택`·`보관` 버튼과 `장착할 타워를 선택하세요` 안내가 그대로 밝게 남는다. 가로에서는 교체창이 설명과 버튼 문구 위에 겹친다.
- 영향: 교체창 밖 버튼을 실행할 수 있는 것처럼 보이고 현재 단계도 대상 선택 단계처럼 읽힌다.
- 코드 근거: `lib/ui/hud/gem_reward_target_overlay.dart:316`의 전체 영역 `GestureDetector`가 뒤쪽 버튼 위를 덮어, 해당 영역 탭은 `cancelRewardGemReplacement`로 처리한다. 현재 렌더의 밝은 버튼 표기와 동작이 맞지 않는다. 실제 브라우저 클릭은 미검증이다.
- 수정 방향: 교체 중인 단계에 맞춰 뒤쪽 버튼·안내의 비활성 또는 가림 처리를 일치시킨다. 포탑을 밝게 유지하는 기존 전장 강조는 보존한다.
- 증거: [가로](game_640x360_replacement.png), [세로](game_390x844_replacement.png).

## 3. 중간 — 가로 화면에서 장착 대상 포탑이 너무 작음

- 재현: 640×360의 젬 장착 대상 선택 최초 상태.
- 관찰: 전장이 화면 중앙의 작은 영역에 모여 있고 포탑 한 칸은 논리 크기 약 14px 수준이다. 설명·액션은 큰데 선택해야 하는 포탑은 작고 오른쪽 빈 공간이 크다.
- 영향: 포탑 종류와 선택 테두리를 구분하고 원하는 대상을 정확히 누르기 어렵다. 오탭 빈도는 실제 기기에서 측정하지 않았다.
- 원인 판단: 가로 화면의 전장 배율·공간 배분에 대한 추가 확인이 필요하다. 젬 선택으로 자동 축소됐다는 뜻은 아니다. 기존 테스트는 선택 전후 배율·시점 유지가 통과한다.
- 수정 방향: 일반 가로 전장 배치와 사용자 확대 조작을 검토한다. 보상 선택 시 자동 이동·축소 금지라는 확정 기준은 유지한다.
- 증거: [가로 대상 선택](game_640x360_target.png).

## 4. 수정 완료 — 좁은 보상 카드의 효과 단어 분리

- 재현: 320×800의 젬 구매 선택 화면.
- 관찰: 사거리 카드의 `사거리 20% 증폭`이 `사거리 20% 증` / `폭`으로 나뉜다. 옆 가속 카드와 줄바꿈 구조도 다르다.
- 영향: 핵심 효과의 읽는 흐름이 끊긴다. 텍스트 유실이나 기능 차단은 아니다.
- 원인: `lib/ui/hud/reward_overlay.dart:377`의 좁은 효과 영역에 문구를 일반 `Text`로 배치하여 단어 내부에서 줄바꿈된다.
- 적용: 사용자 승인에 따라 `사거리` / `20% 증폭`처럼 의미 단위로 줄바꿈하고, 한글 단어 내부 분리를 방지했다. 설명 글자 크기를 일반 10.5→10, 좁은 카드 9→8.5로 줄였다. 이름·아이콘·수량은 유지하고 설명 영역은 긴 내용과 글자 확대에 맞춰 높이가 늘어난다.
- 확인: 모든 젬을 320·390 폭, 글자 배율 1.0·1.3에서 검사했다. 관련 테스트 12개, 렌더 테스트 2개, 정적 분석, 웹 빌드가 통과했다. 브라우저는 중복 실행 안내로 미검증이다.
- 적용 이미지: [일반 효과](card-wrap-applied/game_320x800_choices.png), [긴 효과](card-wrap-applied/reward_320x800_choices.png). 두 이미지는 현재 코드의 테스트 렌더다.
- 증거: [320폭 선택 카드](game_320x800_choices.png).

## 검증 해석

자동 테스트는 장착·교체·보관 흐름, 카메라 유지, 예외 없음 등을 검증한다. 테스트 통과는 버튼 노출 정도, 시각적 단계 구분, 문구 줄바꿈 품질까지 보장하지 않는다. 세로 화면에서 설명에 가려진 포탑을 직접 드래그로 노출하는 동작은 확정 디자인이므로 그 자체를 결함으로 분류하지 않았다.
