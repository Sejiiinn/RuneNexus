# 젬 선택 등장 애니메이션 시안

2026-10-04. 5배수 웨이브 클리어의 젬 선택 화면에 사용할 등장 애니메이션 비교 시안과 승인 3번의 Godot 적용 기록. [재생 가능한 시안 원본](gem-reward-entrances.html)은 15웨이브 보상을 예로 사용한다.

| 시안 | 동작 | 정상 속도 |
| --- | --- | --- |
| 부드러운 상승 | 전체 창이 28px 상승하며 자연스럽게 정착 | 0.58초 |
| 카드 순차 등장 | 왼쪽부터 0.13초 간격으로 카드가 상승하고 작게 정착 | 0.86초 |
| 중앙에서 펼치기 | 중앙에 모인 카드가 양옆으로 펼쳐지고 룬 고리는 사라짐 | 0.82초 |
| 룬빛 스캔 | 청록빛 선이 내려가며 화면을 드러내고 카드에 짧은 광택 | 0.96초 |

최종 화면은 네 시안 모두 동일하다. 시안 전환은 자동 재생하지 않으며 `재생`과 `0.5배속`으로 비교한다. 재생 중에는 선택 입력을 막고 끝나면 활성화한다. 모션 줄임 환경에서는 완성된 화면으로 전환한다. 카드·파편 선택은 시안 내부 강조 표시만 바꾼다.

## 승인 3번의 게임 적용

사용자가 선택한 ‘중앙에서 펼치기’를 [보상 화면](../../../godot/ui/battle_rewards.gd)과 [전용 등장 처리](../../../godot/ui/gem_reward_entrance.gd)에 반영했다. 후속 요청에 따라 모달 프레임·제목도 중앙을 기준으로 90% 크기·14px 아래에서 약 0.40초 동안 확대·상승하며 정착한다. 적용 기준은 [DESIGNS.md](../../../DESIGNS.md#화면별-확정-결정과-기준-자료)에 기록한다. 전체 0.82초의 실제 시간으로 재생하고 완료되면 기존 프레임·카드·파편·획득 젬의 외형과 선택 입력을 복구한다. 동일 보상의 갱신·선택 취소·구매 화면에서는 반복하지 않는다.

- [프레임 애니메이션 포함 실제 Godot GIF](implemented-frame-godot.gif): 440×900px, 캡처 시간 간격 보존, 등장 전과 최종 정지를 포함한 3초 무한 반복.
- [프레임 보완 후 실제 Godot 최종 화면](implemented-frame-godot.png)
- 최초 적용 기록: [카드 중심 GIF](implemented-godot.gif), [최종 화면](implemented-godot.png)

Godot 4.7.2 / Metal 4 Forward Mobile / Apple M4의 분리한 실행 프로젝트에서 440×900·320×900 화면을 확인했다. 실제 앱의 5번째 웨이브 완료와 보상 전환 경로를 사용하되, 재현 시간을 줄이기 위해 테스트에서 적 생성 대기를 생략하고 대표 젬 3종을 고정했다. 5개 웨이브 전체 플레이 검증은 아니다. 등장 중 4배속 전투 시계가 정지된 상태에서도 애니메이션은 완료됐으며, 실제 포인터의 카드 선택·장착 대상 화면·뒤로가기와 재등장 방지를 확인했다. 중간·최종 화면의 정보·잘림 검사도 확인했다.

[등장 회귀 검사](../../../godot/verify_gem_reward_entrance.gd), 기존 보상·결과 등장·모달 입력의 관련 네이티브 회귀와 별도 검증자의 입력 경계·스타일·취소 복구 검사를 통과했다. 독립 검증에서 승인 시안과 실제 440/320px 중간·최종 화면 및 선택·뒤로가기를 대조해 PASS로 판정했고 미해결 결함은 없다. Android 기기·APK 빌드와 배포는 수행하지 않았다.

프레임 보완 후 같은 격리 경로와 렌더 환경에서 440×900·320×900 실제 화면을 다시 확인했다. 프레임 확대·상승과 카드 펼침의 연결, 최종 정보·배치 및 실제 포인터 선택·뒤로가기·재생 방지를 확인했다. 프레임 원래 변환의 종료·취소 복원, 리사이즈·본문 재생성의 배치 반영, 결과창 간섭을 포함한 젬 등장 검사와 관련 네이티브 회귀 4개를 통과했다. 별도 검증자의 프레임 계약 검사와 실제 두 해상도의 중간·최종 화면 대조도 PASS이며 미해결 결함은 없다.

일회성 검사·상세 결과·중간 화면은 Git 추적에서 제외된 `local/`에 보관했다.
