# 공통 그림자 적용

2026-09-13. 사용자 요청에 따라 고사리 전용 외피를 제거하고 전장의 공통 그림자 범위와 실제 식생 LOD를 수정했다. Astra 에이전트가 카메라·식생 구현과 기존 성능 측정 경로 조사를 나누고, 주 에이전트가 통합·실제 화면·Android 설치와 패키지를 검수했다.

## 적용 결과

- 지형·포탑·적·식생은 기존 Godot 주광의 공통 그림자를 사용한다. 고사리 전용 GLB·셰이더·외곽 데이터·그림자 전용 점유 재질은 런타임에서 제거했다. 과거 원본은 design에 보존했다.
- 직교 카메라의 near/far를 실제 맵·모델·탄체·폭발 경계에서 산정한다. 전투 중 관측된 큰 효과의 경계는 해당 맵 수명 동안 보존하여 소멸할 때 범위가 왕복하지 않는다. 구도·줌·HUD 투영·0.7초 시점 전환은 유지한다. 카메라 근거·검사 (`camera-agent.md`, 로컬 자료).
- Blender에서 이미 단순화한 실제 식생의 추가 Godot LOD만 해제한다. 같은 GLB의 바위와 다른 지형·포탑·적 LOD는 유지한다. 실제 잎의 양면 그림자와 공유 바람·건설 점유가 같은 기하에서 처리된다. 식생 구현 (`foliage-agent.md`, 로컬 자료).
- 주광·보조광·PBR·PCF Medium·bias·blur는 직전 재질 단계의 값을 유지했다. 실제 잎의 차폐가 복구된 결과에서 추가 조명 보정 없이 포탑 기단·바위·군락의 접촉 음영이 읽혔다. 검은 다각형 외피가 사라지고 넓은 잎·낮은 풀에도 실제 그림자가 남는다.

## 실제 화면

Android 17 ARM64 에뮬레이터의 **일반 본게임 APK 6013**, Godot 4.7.2 Mobile/Vulkan, Goldfish GFXStream / Apple M4, 1080×2424 화면이다.

- 고정 시점 (`android-fixed.png`, 로컬 자료) / 드론 시점 (`android-drone.png`, 로컬 자료)
- 시점 전환 녹화 (`android-camera.mp4`, 로컬 자료): 실제 Android 화면 녹화이며 프레임 성능 측정용이 아니다. 약 5.19초 파일에서 1.3·2.0·4.0초 프레임을 디코딩했다. 디코딩 기록 (`android-video.log`, 로컬 자료).
- 로비에서 기존 전투를 이어서 열고 시점 버튼으로 전환·복귀했다. 7/40라운드, HP 13/20, 403G, 조각 16, 기존 기관총 2기·대포 1기를 유지했다. 추가 전투·구매·초기화 없이 고정 시점·1배속·웨이브 대기로 두었다.
- 실제 잎 아래 차폐, 포탑 기단·석재 측면, 맵의 깊이 잘림·면 누락 여부를 확인했다. 전환 도착 후 기존 HUD 정렬과 입력이 유지된다. Android 실행 로그 (`android.log`, 로컬 자료)에 Godot 스크립트·Vulkan 파이프라인 오류가 없다. 기존 `xr/shaders/enabled` 설정 경고는 남아 있다.

공용 GPU 장면의 고정 (`desktop-angled.png`, 로컬 자료) / 드론 (`desktop-drone.png`, 로컬 자료)은 대포 6기·표적 3기·폭발을 포함하는 **데스크톱 검사**이며 본게임 화면과 구분한다. 두 시점 모두 81 draw calls, 173,271 GPU primitives다. 같은 장면의 직전 외피 포함 82 / 143,743 대비 실제 잎의 세부 기하가 늘고 전용 외피 드로콜은 사라졌다. GPU primitives는 렌더 패스 합계이며 에셋 삼각형 수나 모바일 GPU 시간 증가율이 아니다.

대표 GPU 장면의 깊이 범위는 기존 0.1–100에서 고정 **19.444–38.234**, 드론 **25.000–31.500**으로 줄었다. 실제 프레임의 모델·폭발 크기에 따라 달라지며 이 숫자를 제품 상수로 사용하지 않는다. GPU 로그 (`desktop.log`, 로컬 자료).

## 관련 검사

- 기존 준비 테스트: 깨끗한 준비·반복 준비·재질 갱신·바위/다른 import 설정 보존·폐기한 외피와 캐시 제거 통과.
- 환경 검사 (`environment.log`, 로컬 자료): 실패 0. 실제 imported 식생 mesh의 LOD가 비어 있고 바위 LOD는 유지되는 것을 확인했다. 두 메시·23,964 원본 삼각형, 바람·건설 점유/철거·미리보기·자원 공유·재진입·맵 분리 통과.
- 첫 통합에서 import 키가 GLB 원명과 달라 무시되는 결함을 발견했다. Godot이 생성한 `Dressing Export (temporary)_stage1_dressing_foliage` 키로 교정한 뒤 실제 메시 검사까지 통과했다.
- 카메라 검사 (`camera.log`, 로컬 자료): 실패 0. 전환·재입력·HUD 가로/세로 정렬, 실제 기하, scale 1.7 보스, 맵 끝 radius 2.4 폭발의 초기/중기/말기, 효과 소멸 후 경계 유지·맵 재생성을 확인했다.
- 공용 런타임 (`runtime.log`, 로컬 자료) 및 실제 GPU 기관총 검사 (`machinegun.log`, 로컬 자료): 실패 0. 여섯 포탑·적·탄체 유형, 입체 효과의 카메라 갱신·수명·풀 재사용과 정리 통과.
- 문서·코드 `git diff --check` 통과. Dart 코드는 변경하지 않았다. Blender 허브는 현행 23개 원본과 홈 장면을 합친 24개 장면으로 갱신하고 기존 UI 편집 세션은 유지했다. 허브 갱신 (`workspace-sync.log`, 로컬 자료).

## 에뮬레이터 관측과 한계

같은 고정 시점·대기 상태에서 Android SurfaceFlinger의 Godot SurfaceView 표시 간격을 관찰했다. 측정 중 화면 녹화·데스크톱 GPU 검사는 실행하지 않았다. Flutter 레이어는 표에서 제외했다.

| 항목 | 직전 6012 | 적용 6013 |
| --- | ---: | ---: |
| 표본 구간 | 22초 | 40초 |
| 레이어 프레임 수 | 995 | 1,845 |
| 평균 표시 FPS | 47.476 | 47.495 |
| 표시 간격 p50 버킷 | 20ms | 19ms |
| p95 / p99 버킷 | 40 / 44ms | 40 / 44ms |

짧은 에뮬레이터 표본의 표시 간격은 비슷했다. 기간이 다른 단일 표본이며 렌더 GPU 실행 시간·발열·여유 성능을 측정한 결과가 아니다. 카메라와 식생을 함께 바꾼 통합 비교이므로 식생만의 비용으로 분리하지 않는다. 원본 기준 표본 (`android-baseline-timestats.txt`, 로컬 자료), 적용 표본 (`android-current-timestats.txt`, 로컬 자료), 요약값 (`android-presentation-metrics.json`, 로컬 자료). **모바일 실기기의 4배속 다중 착탄 성능은 미검증**이다. 이번 Android 검수에서는 새 웨이브를 진행하지 않았고, 큰 적·폭발 깊이는 공용 장면 검사에서 확인했다.

## APK

로컬 설치용 `build/apk-main/rune-nexus-common-shadow-arm64.apk`, versionCode **6013**. 일반 `lib/main.dart`, ARM64 release, 추가 debug define 없음. 빌드와 기존 데이터 보존 설치 완료. 공개 배포·커밋·푸시는 하지 않았다.

직전 로컬 6012 **242,214,137 → 241,990,573바이트**, **−223,564바이트(−0.0923%)**. 네이티브 압축 크기 **99,172,048**, Flutter 자산 압축 크기 **77,947,409바이트**는 동일하다. Godot PCK가 **63,155,632 → 62,932,068바이트**로 줄었고, 전용 외피 자원 제거와 식생 import 변경이 반영됐다. 원본 GLB 기하는 늘리지 않았다. ABI는 arm64-v8a 하나이며 design·Blender 원본은 0개다. 공용 PCK와 APK 내부 PCK의 SHA-256 일치를 확인했다. APK 검사값 (`apk.json`, 로컬 자료), 빌드 로그 (`apk-build.log`, 로컬 자료).

이번 완료 범위는 공통 그림자 전환이다. 참고 시안과 동일한 식생 배치·밀도나 별도 코어 유리 이관 완료를 포함하지 않는다.
