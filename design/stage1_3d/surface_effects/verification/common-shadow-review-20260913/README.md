# 공통 그림자 검토

2026-09-13. 사용자 요청: 고사리 한정 보정보다 전체 렌더에 공통 그림자 기준을 적용할 수 있는지 검토. Astra 두 에이전트가 공통 조명·모델 설정을 읽고, 주 에이전트가 동일 Godot 장면에서 비교했다. **검토 결과이며 본게임 코드·에셋·APK는 변경하지 않았다.**

## 결론

고사리 보조 외피를 확대하기보다 **공통 그림자의 수신 범위와 실제 식생 LOD부터 정리하는 것이 우선**이다. 이미 지형·포탑·적·가시 식생은 Godot 공통 그림자 생성·수신 경로를 사용한다. 별도 전역 그림자 엔진을 추가할 근거는 없다. 고사리에만 더한 넓은 차폐는 보조 외피를 사용하는 국소 표현이며, 먼저 원래 식생의 차폐가 충분히 유지되도록 해야 한다.

## 확인한 문제

1. **직교 카메라의 그림자 범위가 과도하다.** 현재 camera near/far는 `0.1/100`이다. Godot 4.7.2에서 직교 카메라는 주광의 `directional_shadow_max_distance=45` 제한을 적용하지 않는다. [엔진 소스](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/rendering/renderer_scene_cull.cpp#L2156). 대표 검수 장면의 가시 메시 AABB 깊이는 고정 `26.177–33.564`, 드론 `26.520–30.357`이었다. 프러스텀 깊이가 넓어 그림자 한 픽셀이 덮는 월드 면적과 유효 bias가 커진다. 이 측정은 해당 장면의 값이며 모든 적·효과·시점 전환의 최종 안전 범위는 아니다.
2. **가시 식생의 자동 LOD도 실제 차폐를 줄인다.** 보조 외피를 끄고 카메라·조명을 고정한 채 가시 식생의 LOD bias만 128로 올리자 넓은 잎·하부 풀·고사리의 그림자가 복구됐다. 이는 보조 외피의 완전 소실 결함과 별도로 확인한 가시 식생의 차폐 손실이다. 모든 모델의 LOD가 잘못됐다는 뜻은 아니다.
3. **보조 외피 제거만으로는 현재 품질이 충분하지 않다.** 현재 범위·LOD를 그대로 두고 외피만 끄면 군락 음영이 약해진다. 공통 범위 축소만으로도 이 간극은 모두 해소되지 않았다. 실제 식생의 차폐 보존을 함께 다루어야 한다.

## 동일 장면 비교

공용 `verify_scene.gd`의 빌드 복사본에서만 값을 바꾸어 비교했다. 물체 배치·재질·주광·PCF·bias·카메라 구도는 유지했다. 두 시점 모두 오류 없이 렌더됐다. 검사 후 빌드 복사본도 공용 소스로 복원했다.

마지막 조건에서 자연 잎의 그림자가 늘며 외피를 사용하지 않는 다른 식물도 바닥에 붙는 느낌이 강해진다. 추가 프리미티브는 30,728이며 Mac 검수 장면의 렌더 패스 합계다. 모바일 프레임 시간이나 메모리 증가량으로 환산하지 않는다. 이번 비교는 Android 앱 캡처가 아니며, 현재 설치된 6012 APK와 저장은 유지했다.

## 권장 수정 순서

1. 전장 경계·높은 모델·탄체·폭발 및 카메라 전환을 포함하는 깊이 범위를 계산하고 안정적인 여유를 둔다. 비교용 `10/50`을 그대로 제품 상수로 채택하지 않는다. 구도·화면 배치는 유지할 수 있다.
2. 정리된 범위에서 공통 PCF·bias를 포탑 기단·바위·잎 아래에 함께 맞춘다. opacity나 환경광만 낮춰 접촉 부족을 감추지 않는다.
3. 식물 종류별 특수 음영 코드 대신 **얇은 식생의 LOD가 잎의 투영 면적·겹침·바람 입력을 보존하는 공통 제작 기준**을 세운다. 우선 충분한 정밀도의 실제 메시로 시각 기준을 확보하고, Android 측정 후 필요한 부분을 단순화한다. 모든 지형·적·포탑의 LOD를 일괄 해제할 근거는 없다.
4. 그 결과에서 고사리 보조 외피 제거를 다시 판정한다. 공통 방식으로 충분하면 외피·전용 셰이더·전용 점유 재질·해당 import 예외를 함께 제거한다. 부족한 경우에만 근거가 있는 보조 표현을 검토한다.

정적 지형의 틈은 기존 AO 데이터의 역할이며, 움직이는 물체의 주광 차폐와 구분한다. Mobile에는 내장 SSAO가 없어 설정 하나로 전체 동적 접촉 AO를 더할 수 없다. 이 때문에 곧바로 엔진 변경이나 커스텀 후처리를 도입할 근거는 없다. 조명·AO 검토 (`light-review.md`, 로컬 자료), 모델별 생성·수신·LOD 검토 (`asset-review.md`, 로컬 자료).

코어·포탈 에너지·미리보기·전투 효과의 그림자 생성 OFF는 기존 명시 예외다. 동일한 공통 정책은 소재의 투명성·양면 처리까지 같은 숫자로 강제한다는 의미가 아니다. 실기기 성능과 Android 변경 후보는 이번 검토 범위에서 미확인이다.
