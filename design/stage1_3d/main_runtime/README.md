# Android 본게임 스테이지 1 연결 검수

확인: 2026-09-11. 일반 `lib/main.dart` release APK의 실제 화면이다. 디버그 패널을 켜지 않았으며, 로비에서 스테이지 1을 시작했다.

- 패키지: `com.example.rune_nexus`, 진입: `MainActivity`.
- APK: `build/apk-main/rune-nexus-stage1-godot-arm64.apk`.
- [본게임 카메라 영상](stage1-camera-transition.mp4): 약 24초, 1080×2424. 전투 준비 중 왕복, 실제 웨이브 중 왕복과 빠른 방향 변경, 4배속 변경 및 다음 라운드 진입을 포함한다.
- [본게임 적용 화면](stage1-camera.png): 기관총·대포 설치 후 기존 HUD와 고정 시점. 메인화면 재진입·백그라운드 복귀 후 캡처다.

기관총 60G·대포 90G를 실제 건설 흐름으로 설치해 170G→20G 감소와 같은 타일의 3D 포탑·선택·사거리 표시를 확인했다. 실제 웨이브에서 적 이동·공격·처치와 보상이 진행되고 2라운드로 넘어갔다. 메인화면의 이어서 진행과 백그라운드 복귀에서 전장·포탑·시점 버튼이 유지됐다.

본게임과 별도 Godot 검수 APK는 같은 `godot/` 소스와 PCK를 포함한다. 두 APK의 내장 팩 SHA-256 일치와 ARM64 구성을 검사했다. Android 브리지의 동적 메서드에는 일반 `has_method()` 검사가 맞지 않아 투영 보고를 직접 호출하도록 수정했다. 실제 앱에서 카메라 투영을 받은 뒤 기존 2D 전장 대신 Godot 전장이 나타나는 것까지 확인했다.

Flutter 정적 분석, 전체 테스트 758개(기존 조건 생략 11개), 디버그 대상 관련 테스트, 공용 Godot 카메라·런타임 검사, 일반·별도 검수 release 빌드가 통과했다. 상세 로그·APK 해시·입력 시각·영상 메타데이터는 `build/godot/main-verification/`에 있다.

Android 17 ARM64 에뮬레이터의 실제 앱 녹화이며 모바일 실기기의 지속 전투·발열·정량 성능 검증은 아니다. 기존 계정·저장·전투 규칙은 그대로 사용한다. 구조와 실행 기준은 [스테이지 1 3D 전장](../../../docs/stage1_3d_preview.md)을 따른다.
