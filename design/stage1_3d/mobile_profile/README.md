# 네이티브 실제 전투 성능 측정

> 역사 기록: 2026-09-13 ThreeJS 실행 경로를 제거했다. `main.dart`는 `main.dart.txt`로 보존하며 아래 실행 명령은 현재 사용할 수 없다. 현행 검수는 저장소의 `docs/stage1_3d_preview.md`를 따른다.

2026-09-11: 3D 검수는 웹 대신 APK로 진행한다. 바로 설치해 다중 사격을 확인하려면 [별도 설치용 대포 3D APK](../cannon_impact/barrage_runtime/README.md)를 사용한다. 이 문서의 일반 HUD 진입점은 실기기 프로파일 측정용이다.

`main.dart`는 기존 [Stage1ThreeDPreviewApp](../../../lib/app/stage1_3d_preview_app.dart)을 바로 실행하는 개발 전용 진입점이다. URL 쿼리 없이 실제 `RuneNexusGame`·`GameHud`·3D 렌더러를 사용하며, 별도의 전투 시뮬레이션이나 상태를 만들지 않는다. 시험 앱의 `MemorySaveRepository`와 `NoopOnlineSaveRepository`를 그대로 사용하므로 계정·영구 저장을 초기화하지 않고 진행은 앱 종료 시 사라진다.

## 실행

저장소 루트에서 연결된 Android/iOS 실기기의 ID를 확인하고 profile 모드로 실행한다. macOS 기준:

```sh
scripts/in_app_server_macos.sh flutter devices
ORG_GRADLE_PROJECT_runeNexus3dPreview=true WORK_DIR="$PWD" scripts/in_app_server_macos.sh flutter run --profile -d <device-id> --target=design/stage1_3d/mobile_profile/main.dart --dart-define=RUNE_NEXUS_DEBUG_PANEL=true
```

release 동작 확인에는 같은 명령의 `--profile`을 `--release`로 바꾼다. `RUNE_NEXUS_DEBUG_PANEL`은 아래 재현을 위한 기존 테스트 패널만 활성화한다. 이 대상과 플래그는 개발 측정용이며 배포 설정에는 추가하지 않는다. Windows는 [SDK 실행 규칙](../../../.agents/windows_flutter_guide.md)을 따른다.

첫 실행에서 3D 지형과 포탑이 실제로 표시되는지 확인한다. 렌더러 초기화에 실패하면 2D 전장으로 돌아가므로 그 실행은 3D 성능 결과에 포함하지 않는다. 실기기 연결·서명·네이티브 빌드 환경은 각 플랫폼 설정이 필요하다.

## 1x / 4x 다중 대포 재현

일반 HUD 진입점에서는 테스트 패널의 **대포 6문 · 고체력 표적**으로 즉시 정지 표적 부하를 구성할 수 있다. 별도 설치용 APK는 이 배치를 자동으로 시작한다. 아래는 이동 적을 사용하는 웨이브 비교 절차다. 모든 비교에서 같은 기기·화면 방향·시점·포탑 배치·라운드를 유지한다.

1. 상단 **테스트 패널**의 **+500G**로 대포 네 기를 설치할 골드를 준비한다.
2. 빈 건설칸을 선택하고 **포탑 → 대포**로 설치한다. 권장 위치는 맵 왼쪽 위를 `(0, 0)`으로 하는 `(열, 행)` 좌표 `(2, 1)`, `(3, 1)`, `(2, 3)`, `(3, 3)`이다. 모두 같은 초반 길 구간을 바라보는 건설칸이다. 레벨 1, 젬 미장착으로 통일한다.
3. 테스트 패널의 **10R**로 라운드를 준비하고 패널을 닫는다. 하단 **1x**, **시작**을 눌러 실제 전투를 기록한다.
4. 같은 배치를 유지한 채 **10R**을 다시 눌러 전투를 초기화하고 패널을 닫는다. **4x**, **시작**으로 같은 라운드를 기록한다. 준비 시간과 패널 조작은 측정 구간에서 제외한다.
5. 실제 다중 착탄 구간이 부족하면 별도 부하 실행으로 테스트 패널의 **테스트 몹 → 탱커**를 같은 횟수만큼 추가한다. 추가 수와 시작 조건을 기록하고 패널을 닫은 뒤 측정한다. 기본 웨이브 결과와 추가 적 결과를 구분한다.
6. 지속 전투에서는 라운드를 이어서 최소 10분 관찰하고 포탑·젬·업그레이드 변경을 기록한다. 짧은 동일 조건 비교와 장시간 발열 결과를 따로 남긴다.

4x는 발사·웨이브 진행뿐 아니라 이펙트 수명도 같은 배율로 진행한다. 따라서 동시 폭발 수가 자동으로 네 배라고 가정하지 않고, 실제 여러 포탄이 겹쳐 착탄하는 구간을 확인한다. 지원되는 스테이지 1 적은 일반·장갑병·보호막병·빠름·탱커·보스다.

## 기록과 판정

Flutter [성능 측정 안내](https://docs.flutter.dev/perf/ui-performance)에 따라 실기기 profile 모드에서 측정하고, [DevTools Performance](https://docs.flutter.dev/tools/devtools/performance)와 [Memory](https://docs.flutter.dev/tools/devtools/memory)를 사용한다. release는 최종 실행·지속 동작을 추가 확인하는 용도다. 디버그·에뮬레이터·웹 결과로 모바일 성능을 판정하지 않는다.

| 항목 | 기록할 내용 |
| --- | --- |
| 환경 | 커밋, 기종, OS, GPU, 해상도·DPR, 주사율, profile/release, 화면 방향·시점 |
| 전투 조건 | 라운드, 속도, 포탑 종류·수·배치·레벨, 젬, 추가 적 수, 관찰된 다중 착탄 |
| 프레임 | 평균 FPS, 프레임 시간 p95/p99·최댓값, 16.7ms 초과 빈도, UI/raster 시간 |
| 지속 실행 | 실행 시간, 시작·종료 메모리와 반복 전투 후 추이, 발열 및 시간 경과에 따른 FPS 저하 |
| 결과 | 1x/4x 각각의 측정 구간과 자료 위치, 3D 표시 여부, 오류·미측정 항목 |

성능 기록 중 화면 녹화는 끄고 시각 증빙은 별도 실행에서 남긴다. 외부 ANGLE 텍스처의 GPU 비용이 Flutter raster 시간 하나에 모두 반영된다고 가정하지 않는다. 가능하면 플랫폼의 프레임 표시·GPU 측정도 함께 기록한다.

목표는 실제 전투 4x와 다중 착탄·지속 실행에서 60fps(약 16.7ms)다. 평균만으로 통과 처리하지 않고 지연 분포·메모리·발열 후 저하를 함께 확인한다. 이 폴더는 측정 진입점과 절차이며, 실기기 성능 통과나 지원 하한 기종 확정을 의미하지 않는다. 현행 범위는 [스테이지 1 3D 기준](../../../docs/stage1_3d_preview.md)을 따른다.

## 이번 구현 검증

2026-09-11: 시간별 3D field 캐시를 포함한 Android arm64 프로파일 APK 빌드가 통과했다. 현재 렌더러가 요구하는 SDK CMake 3.31.4를 설치해 사용했으며, Flutter 자동 생성·마이그레이션 파일은 변경에 포함하지 않았다. APK에 들어간 캐시의 길이와 SHA-256이 제작 원본과 일치함을 확인했다. 산출물은 `build/app/outputs/flutter-apk/app-profile.apk`다.

관련 Dart 테스트 8개와 정적 분석이 통과했다. 기존 검수 화면에서 초기·후기 및 angled/drone 시점을 확인했으며, 이는 모바일 실기기 화면·프레임 측정을 대신하지 않는다. 연결된 모바일 기기가 없어 실기기 4배속·다중 착탄·지속 부하 결과는 아직 없다.
