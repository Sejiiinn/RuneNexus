# Android 환경 장식 검증

2026-09-12. 별도 `com.example.rune_nexus.godotpreview` 검수 앱만 설치·실행했다. 일반 앱의 계정·진행 데이터는 조작하지 않았다. 기기는 Android 17/API 37 ARM64 에뮬레이터 `emulator-5554`, 1080×2424/420dpi다.

## 비교 방법

같은 검수 앱의 고정 시점, 확대 1.0배, 그림자·폭발 볼륨 켬에서 초기 정지 장면과 4배속 대포 6문/표적 3기 연속 사격을 비교한다. 앱이 표시하는 1초 Godot 프레임 주기·렌더 통계를 `uiautomator`로 각각 5회 수집한다. FPS는 정수, ms는 소수 첫째 자리로 반올림된 UI 값이다. 이 표본으로 GPU 시간·프레임 지연 상위 백분위·실기기 성능을 판정하지 않는다. 4배속의 드로 콜/삼각형은 샘플 당시 폭발 단계가 달라 직접 차감값을 장식 비용으로 간주하지 않는다.

실기기 4배속 다중 착탄 성능 수용 기준은 미측정이다. 화면 녹화의 프레임 간격도 GPU 벤치마크로 사용하지 않는다.

## 최종 결과

최종 APK는 `build/apk-preview/rune-nexus-stage1-environment-arm64.apk`이며 실제 설치본·기존 검수 파일명 APK·내장 공용 PCK의 SHA-256 일치를 확인했다. 전체 결과는 `result.json`, 패키지 검사는 `artifact-checks.json`과 `final-apk.json`에 있다.

| 동일 조건의 비녹화 UI 표본 5회 | 변경 전 | 최종 |
| --- | --- | --- |
| 정지 FPS / ms | 모두 60 / 16.7 | 모두 60 / 16.7 |
| 정지 드로 콜 / 삼각형 | 67 / 142,700 | 70 / 167,820 |
| 4배속 FPS / ms | 모두 60 / 16.7 | 모두 60 / 16.7 |
| 4배속 드로 콜 / 삼각형 | 61–68 / 142,688–145,340 | 68–76 / 168,912–172,458 |

정지 증분은 드로 콜 3개·삼각형 25,120개이며 그림자 패스를 포함한 렌더 통계다. 최종 런타임에는 맵의 float/int 비교로 매 프레임 지형이 재생성되던 문제 수정도 포함되므로 CPU/FPS 차이를 식생만의 효과로 해석하지 않는다.

`final-fixed.png`, `final-drone.png`에서 빈 건설칸 중앙의 풀·내부 틈 식생·외곽 풀과 바위를 확인했다. 대포 6문이 있는 칸의 중앙은 비워지고 주변 틈은 유지되며, 길·포탑이 가려지지 않는다. `final-4x.png`는 같은 최종 APK의 실제 4배속 폭발 장면이다.

`environment-dressing-android.mp4`(23.72초)는 정지 상태 바람, 고정↔드론, 두 시점의 4배속 연속 사격과 다시 정지를 기록했다. 녹화 중에는 50 FPS 표시도 관측했다. 위 표는 녹화를 종료한 뒤의 별도 표본이며, 녹화 영상으로 60 FPS 고정이나 실기기 성능 통과를 주장하지 않는다.

정지 고정 장면의 두 무손실 캡처(`paused-wind-a.png`, `paused-wind-b.png`)에서 외곽 군락과 빈칸 중앙 풀의 픽셀 변화가 나타났다. 촬영 사이에는 0.8초 대기와 adb 캡처 시간이 있으며, 분석 범위·수치는 `paused-wind-pixel-difference.json`에 기록했다. 풀의 작은 움직임을 확인하는 보조 근거이고 성능 측정이 아니다.

최종 기동·시점 변경·4배속 사격에서 새 Godot 스크립트·렌더 오류와 크래시는 없었다. `xr/shaders/enabled` 설정 경고 및 MESA/gfxstream 초기화 경고는 기준선에도 동일하게 존재했다(`final-logcat.txt`).

Android에서는 기존 대포 배치의 표시 상태를 확인했다. 본게임 건설·판매 UI는 직접 조작하지 않았으며, 설치·철거·미리보기·이동·재진입 마스크는 별도의 공용 Godot 장면 회귀검사로 검증했다. 해당 검사와 제작 기준은 상위 제작 기록에서 확인한다. 일반 앱의 계정·진행 데이터는 변경하지 않았다.

최종 크기는 **219,825,369 bytes**, 기준선보다 **953,240 bytes(0.4355%)** 증가했다. 전부 Godot PCK 증가분이다. 네이티브 라이브러리·Flutter 에셋 그룹은 기준선과 동일하며 추가 장식의 임포트 장면은 PCK에서 950,061 bytes를 차지한다. `dressing.glb`는 Flutter 에셋에 중복 포함되지 않고, 기존 LTC 4개 파일은 유지된다. PCK 안에 검증 스크립트와 `design/` 원본은 없다.

외곽안 중간 결과는 `revision1-exterior-only/`에 분리했다. 최종 판단에는 이 절과 루트의 `final-*` 자료를 사용한다.

## 변경 전 기준선

- APK: 218,872,129 bytes. SHA-256 및 ZIP/PCK 항목: `baseline-apk.json`.
- 정지 장면: 5회 모두 60 FPS / 16.7ms / 67 드로 콜 / 142,700 삼각형.
- 4배속 연속 사격: 5회 모두 60 FPS / 16.7ms, 61–68 드로 콜 / 142,688–145,340 삼각형.
- 실제 앱 화면: `baseline-fixed.png`, `baseline-4x.png`.
- APK 기동부터 사격까지 Godot 스크립트·렌더 오류 및 앱 크래시 없음. 프로세스 로그: `baseline-logcat.txt`.

## 패키징 기준선

`apk_stats.py`는 실제 APK ZIP 압축 크기와 PCK v4 디렉터리를 읽는다. PCK의 모든 파일 길이·MD5를 검증한다. 원본 GLB와 Godot의 임포트 장면/텍스처는 포맷이 달라 바이트 동일성 대신 포함된 자산 경로로 중복을 확인했다.

- ABI: `arm64-v8a` 한 개. 네이티브 라이브러리 95,305,424 bytes. Godot 엔진 71,114,944 bytes, C++ 공유 런타임 한 개.
- Flutter 스테이지 1 3D 원본 36,223,484 bytes(그중 GLB 30,914,183 bytes)와 Godot PCK 46,485,208 bytes가 함께 포함된다. PCK에는 terrain GLB 임포트 장면·텍스처, 포탑·적의 임포트 장면이 존재한다.
- 기존 ANGLE 라이브러리 3개 합계 6,413,960 bytes가 남아 있고, 앱 시작 시 자동 등록된 FlutterAnglePlugin이 이를 로드한다. `pubspec.yaml`의 `flutter_angle`·`three_js`와 다른 플랫폼/스테이지 렌더 경로가 남아 있으므로 이번 환경 장식 작업에서 의존성을 제거하지 않았다.
- `design/` 편집 원본은 APK에 포함되지 않는다.
- 이번 비교는 별도 로컬 검수 APK의 전후 비교다. 공개 배포와 이전 공개 APK의 검증을 대신하지 않는다.
