# 현재 골렘의 보스 이식

범위: 승인된 목 정리 v7의 형태·금속 지지대·붉은 눈/핵·음각 룬과 기본 보행 스타일을 기존 보스 시각에 연결. 보행 기준 커밋 `226cd1b244b3441625f4a12ad16d421c4dcec4d2`, 경량화·사망·핵 광원 반영일 2026-10-06. 이 기록은 로컬 구현·검증이며 배포 기록이 아니다.

## 입력과 게임 계약

- 원본: `RuneNexus-HeavyWalk-NeckJunction-Cleaned.blend`, SHA256 `de2a8de4d069ba8ae21b2f9443d2dbabed8261156666f95d29f0a2457594e3e3`. 원본 v7은 별도 제작 보관본을 유지한다. 이미 수용한 턱 아래·목 테두리의 작은 잔여 돌출을 추가 미화하지 않았다.
- 게임 GLB: `assets/images/stage1_3d/enemies/boss.glb`, SHA256 `691e89f191faf5e3ad7adad6329f3f506d067c625c76f7449c968bbb257c9494`.
- `boss`, `shieldBoss`, `forgeBoss`가 한 모델·애니메이션·상태 메시를 공유한다. 일반 적 모델·보스 수치·충돌·경로·공격·보상·저장 계약은 변경하지 않는다. 처치 시 전투 판정·보상은 즉시 유지하고 시각 전용 사체가 자체 `BossDeath` 클립을 재생한 뒤 제거된다. 다른 종류의 사망 클립을 재사용하지 않는다.
- 17개 뼈, `HeavyWalk` 2초 루프. 보행이 빠르게 보인다는 피드백에 따라 게임 전용 다리 애니메이션의 접지 보폭을 4/3배로 늘렸다. 주기당 이동 거리 .5216151 GLB 단위에 콘텐츠 배율 .79를 적용하면 .4120759타일이다. 게임 이동 속도 .35타일/초는 그대로이며 보행 주기는 약 .88초에서 1.18초로, 반복 빈도는 25% 줄어든다. 실제 이동 거리로 위상을 구하고 전투 시계로 방향 전환을 보간한다. 일시정지·감속·배속·순간이동에 벽시계 자동 재생을 추가하지 않는다.
- GLB 정규화: 제작용 yaw를 제거하고 +Z 전방·Y=0 바닥을 유지. rest 높이 1.64885, 기본 보스 표시 높이 1.30259타일. 탱커 표시 높이 대비 약 1.5배이며 변형별 기존 .81/.83 배율도 유지한다. HP/실드 바 위쪽 앵커는 움직이는 머리의 실제 바인드 경계를 사용한다.
- 화상·성에의 기존 공용 모양을 새 스킨에 오프라인 부착하여 세 개의 상태 메시를 만든다. 상태 재생성 도구는 `scripts/bake_skinned_enemy_status.gd`의 `boss` 인자를 사용한다. 붉은 핵과 발광 부위는 성에로 가리지 않는다.

## 재질·형상 전송

원본의 8개 사용 재질·7개 packed 이미지·절차적 마스크를 기본색, 거칠기/금속성 묶음, 발광의 4096² RGB 이미지 3장과 Godot 기본 PBR 재질 하나로 굽는다. 절차적 노드를 그대로 GLB에 내보내는 방식은 사용하지 않았다. 새 노멀·범프 효과를 추가하지 않았다. 초기 고해상도 바디는 1개 메시·1개 surface, 217,230삼각형·UV/노멀 분할 정점 215,820개였다. 현재 게임용은 아래 승인된 경량화 기준을 따른다.

초기 변환본(SHA256 `30fc7dca47f04de2c602723bd73f2ee6bfae2c62253334b61690cfd53f656b4a`) 검사에서 Blender 원본의 Preserve Volume은 dual-quaternion, 표준 glTF/Godot은 linear skinning이다. 다시 불러온 결과와 원본의 동일 정점 변형 차이는 평균 .000204·최대 .021189 원본 단위(일부 다리 가중 정점), 머리 최대 .000251 단위다. 원본과 완전히 수학적으로 동일한 변형이라는 주장은 하지 않는다. 기본 재질 렌더 비교에서 형태·석재·금속·눈·음각 룬의 정체성을 보존했다.

## 보폭·좌우 균형 조정

원본 v7·Drive 제작 원본과 이전 게임 후보 보관본은 변경하지 않는다. 보폭 조정 당시에는 게임 전용 애니메이션만 조정해 정점·UV·재질·bind를 유지했다. 이후 승인된 경량화에서 형상과 텍스처 해상도만 줄였으며 보행 트랙·뼈·inverse bind·rest 변환은 그대로다. 기존 스킨 상태 메시지를 그대로 사용한다.

보폭 확대 때 무릎 잠김을 피하려고 오른발 경로를 뒤로 옮긴 보정이 좌우 차이를 키웠다. 이번에는 그 보정을 제거하고 실제 발바닥의 뒤꿈치–발끝 접지 범위를 기준으로 양발 경로 중심을 재배치했다. 골반 Y 이동과 다리 변환 트랙 10개를 함께 풀었으며 골반 XZ 경로·상체 회전은 유지한다. 골반은 주기에 맞춰 .0195~.0405 GLB 단위만 부드럽게 낮춘다. 보폭 .5216151 GLB 단위·표시 보폭 .412075929타일·기존 .35타일/초 이동 속도는 그대로다.

착지 발바닥 범위 중심의 전후 차이는 .110534에서 .000194 GLB 단위로 줄었다. 오른무릎 최소 굽힘은 19.27°에서 33.86°로 늘어나고 왼쪽은 53.39°다. 발의 들어 올리는 높이와 접지 시점은 유지한다. 모든 769개 샘플에서 접지 발바닥의 최대 전후 미끄러짐은 .000702 GLB 단위(.000555타일)로 이전과 같고, 루프 끝 자세가 일치하며 발목 회전의 경계 불연속이 발견되지 않았다.

원래 발바닥 길이는 L .600293, R .515521 GLB 단위로 서로 다르다. 이 승인 형상을 바꾸지 않았으므로 발끝을 완전히 같은 위치로 복제하지 않는다. 앞쪽 끝 차이는 .152920에서 .042580으로 줄었고 남은 차이는 서로 다른 발 길이에 해당한다. 원본 형상이나 bind를 늘리거나 무릎을 잠그는 방식이 아니다.

전후 영상은 모두 같은 1배속 시뮬레이션 1/24초 간격의 72프레임을 24fps로 재생한다. 골렘 기준 R은 게임 카메라에서 화면 왼쪽, L은 화면 오른쪽이며 진단 화면에 R 주황/L 청록으로 표시한다. 편집으로 재생 속도를 바꾸지 않는다.

## 검증 및 제한

- Godot 4.7.2 공식 Linux, headless: 보스 전용 회귀, 기존 skinned enemy 회귀, 화상 184개 검사, 성에 273개 검사, effect preparation 통과. 보스 별칭·보행·일시정지·배속·감속 거리 샘플링·방향 전환·순간이동·시간 역행·epoch·상태 중첩/해제·제거를 확인했다.
- 독립 검사: 표시 rest 높이 비율 1.500868, 다섯 포즈에서 발 최저점은 바닥 위 약 .0025~.0031타일. 머리 앵커가 포즈를 따라가고 실제 모델 위쪽을 보수적으로 덮는다.
- 네이티브 enemy state, wave/core, teleport, combat runtime 네 가지 회귀 및 콘텐츠 25스테이지 검사, 에셋 준비 Python 테스트 통과. 순간이동 뒤 동일 entry를 시간 역행할 때 이전 offset이 남던 시각 문제를 고치고 회귀를 추가했다.
- 초기 이식 실제 렌더 검증: Godot 4.7.2 Mobile/Vulkan, Mesa llvmpipe CPU, 880×1500. 실제 스테이지 5·10·15·20·25의 40웨이브 스폰 스케줄·게임 카메라를 사용한 개발 세션에서 보스 3종을 확인했다. 크기·머리 바·지면·재질·상태 부착을 확인했고, 24fps 72프레임의 보행 확대 검수 영상을 기록했다. 확대 검수는 같은 카메라 경사·조명을 유지하고 다른 적 시각과 개발 HUD만 숨긴다. 이 결과는 Android 실기기/출시판 UI 검증이 아니다.
- 좌우 균형 조정 후 대표 스테이지 5를 동일한 Mobile/Vulkan·1배속·게임 카메라 조건으로 다시 검증했다. 72프레임과 전체 주기 접지·관절 수치 및 독립 검수에서 발 접지·무릎 연속성·기존 재질을 확인했다. 보스/일반 적 보행 회귀, 화상 184개, 성에 273개 검사도 다시 통과했다. 원본과 조정본의 1배속 나란히 비교 영상은 같은 3초 길이다.
- 균형 수정의 실제 Godot 스킨 정점 검사에서 swing phase .3125의 R 최저 Y는 .05880196, 반대 .8125의 L은 .05880605로 일치한다. 도로/포탈 지형이 드는 발의 틈을 가려 보이는 경우를 분리하기 위해 같은 조명·위치의 Y=0 평면 검수도 수행했고 양발의 번갈아 드는 동작을 확인했다. 진단 평면은 게임 에셋을 변경하지 않는다.
- 현재 GLB는 11,715,824바이트로 이전 보행 커밋의 21,504,384바이트보다 약 45.5% 작다. 3×2K ASTC4×4+mipmap의 압축 이미지 데이터는 약 16MiB이며 고해상도 3×4K RGB8+mipmap 디코딩 데이터 약 192MiB와 구분한다. 이는 Android 프로세스/GPU 메모리 실측이나 FPS 개선 수치가 아니다. 실기기·발열·APK 검증은 수행하지 않았다.
- 푸시·PR·APK·배포는 수행하지 않았다. 로컬 커밋과 배포는 별개다.


## 승인된 경량화·핵 광원·사망 연결

- 실제 게임 카메라 비교 후 74,998삼각형·102,837분할 정점·원본을 축소한 3×2048² 맵을 채택했다. 50K 후보는 확대 시 이마의 밝은 삼각면과 석재 면이 두드러져 제외했다. 75K도 확대하면 미세 석재 표면이 더 단순하지만 실제 게임 거리의 실루엣·황동·룬 정체성을 유지한다. 석재 재질을 바꾸는 별도 미세 입자/거칠기 후보는 이득이 작고 파일이 커져 채택하지 않았다.
- 원본 고해상도 제작본·승인 사망 원본과 경량 editable Blender/재현 스크립트는 별도 영구 보관본을 유지한다. Git에는 실제 런타임 GLB·효과·준비 설정·유지할 회귀를 넣고 캡처 드라이버·프레임·임시 로그는 넣지 않는다.
- `scripts/prepare_godot_project.py`가 보스의 해시 공유 텍스처 3개에만 `compress/mode=2`, `high_quality=true`, mipmaps를 적용한다. Android ASTC와 데스크톱 BPTC를 생성하며 다른 텍스처의 기존 무손실 계약은 바꾸지 않는다. 작은 1024² 핵 마스크는 무손실·mipmap 없음으로 고정한다. 애니메이션은 접지 키를 보존하도록 60fps로 가져온다.
- `effects/boss_death.gd`는 공유된 불변 PBR 재질과 개별 메시 shader parameter로 핵과 사체 상태를 분리한다. 기본 핵 발광 .30, 붉은 shadowless OmniLight 에너지 .004·범위 .32를 척추에 붙인다. 성에 코팅은 원래 맵을 읽으며 활성/해제 시 핵 재질을 보존한다.
- 살아 있는 세 보스는 명시적으로 `HeavyWalk`, 사체는 `BossDeath`를 선택한다. 현재 보행 자세에서 .15초 동안 사망 자세로 연결하고 핵은 초반 한 번 펄스 후 눈/룬/국소 광원과 함께 .9초까지 꺼진다. 1.166667초에 실제 무릎이 접지하고 미세 돌조각 5개·먼지 4개가 생긴다. 최종 자세 2.2초 이후에는 뼈를 다시 평가하지 않으며 2.65초까지 페이드, 2.75초에 전체 사체·광원·잔해를 해제한다.
- 경량화에서 접지 주변 원래 정점을 보존했다. GLB 기준 무릎 최저 Y .000786859와 지지 손 .002905206은 승인 사망 원본과 동일하다. Blender 평가 무릎 오차는 약 .000000533이다. 전체 스킨 가중치를 줄이거나 사망 트랙을 다시 만든 것이 아니다.
- 전투 시계와 native kill 이벤트를 사용한다. 반복 이벤트 중복 생성, 일시정지/배속, 시간 역행/epoch 초기화, 순간이동 직후 처치 위치, 사체 terminal cache와 해제를 회귀로 검증한다. 일반 적·하운드·탱커 사망 경로는 그대로 둔다.


### 2026-10-06 프로덕션 연결 검증

- 준비 스크립트 Python 테스트 4개, 보스 사망 253개 검사, 기존 보스 표시, 화상 184개·성에 327개, 기존 skinned enemy·effect preparation 검사가 통과했다. 성에는 기존 일반 재질 검사 외에 보스의 공유 shader·원본 맵 참조·해제 복원·다른 개체 격리를 추가했다.
- 네이티브 enemy state·wave/core·teleport·combat runtime 네 가지 회귀를 격리된 실행기로 다시 통과했다. 단순 headless 성공을 GPU 표현이나 Android 검증으로 간주하지 않는다.
- 실제 준비 프로젝트의 스테이지 5 네이티브 처치(`apply_hit`→native kill event)에서 살아 있는 보스→`BossDeath`→광원/잔해/사체 해제를 30fps·150프레임으로 검수했다. 캡처가 효과나 포즈를 직접 설치하지 않으며 Mobile/Vulkan llvmpipe에서 shader 오류 없이 통과했다. 최종 빈 화면에 잔류 광원·먼지·사체가 없다.
- Android 대상 PCK 생성·목록 검사가 통과했다. 보스 맵은 ASTC 3개만 포함하고 데스크톱 BPTC·중복 원본 GLB·Blender 원본·검수 스크립트/프레임은 포함하지 않는다. 전체 PCK는 208,001,816바이트·1,145항목이며 내용이 완전히 같은 중복 payload는 0바이트다. 전체 게임 팩의 값이고 보스 증가량이나 최종 APK 크기로 해석하지 않는다. APK 빌드·설치·배포와 실제 Android 성능 검사는 하지 않았다.
