# 죽음 V2 — 가까운 팔 착지와 느린 흡수

[두 시점 영상](death-preview.mp4) · [3/4](death-three-quarter.mp4) · [25° 드론](death-drone-25.mp4) · [편집 원본](medium-guardian-death.blend) · [실제 타일 씬](death-tile-preview.blend) · [대표 위상](phase-sheet.png)

팔이 양옆으로 펼쳐지고 너무 일찍 사라진다는 피드백을 반영한 현재 권장 시안이다. [이전 0.45초 시안](../README.md)은 비교용으로 보존했다. 원본 89개 메시·15,351삼각형·승인 석재 형태와 크기를 유지한다. 게임 통합이나 커밋은 하지 않았다.

## 동작

실제 사망은 **0.85초**, 60fps에서 **f1→52**의 51개 간격이다.

- **0~0.08초:** 기존처럼 짧게 움찔하고 눈·핵·룬이 꺼진다. 공유 원본 재질을 건드리지 않고 전용 복사 재질을 사용한다.
- **0.08~0.28초:** 무릎과 몸통이 내려앉고 머리·양팔이 떨어진다. 팔을 가로로 벌리던 ±69° 회전을 제거했다. 몸 앞옆 가까운 비대칭 착지와 팔꿈치 25°/18° 굽힘으로 바꿨다. 눈·룬은 머리에, 주먹·손가락은 각 팔에 함께 남는다.
- **0.28~0.40초:** 쓰러진 잔해가 바닥에 잠깐 머문다. 기존의 작은 3D 먼지를 접촉부 가까이 재사용한다.
- **0.40~0.85초:** 잔해가 모양과 크기를 유지한 채 부드럽게 땅으로 흡수된다. 본의 Z 위치만 움직이며 모델 축소나 알파 소멸을 사용하지 않는다.

최종 침강량은 2.16 model-unit이다. 마지막 잔해 최고점이 바닥을 약 0.0119 model-unit 지나도록 최소 여유를 뒀다. 끝나기 한참 전에 모두 묻히지 않도록 침강량을 줄였다. 실제 물리 시뮬레이션이 아닌 결정적인 강체 본 키프레임이다.

## 미리보기와 크기

실제 길 타일 위 초기 표시 폭은 **0.55 tile**, 전방 -Y·위 +Z다. 모델 및 게임 이동 수치는 변경하지 않았다.

영상에는 전후 0.3초씩 정지 구간이 있다. 한 번은 87프레임/60fps=1.45초이며, 3회 반복한 MP4는 **261프레임·4.35초**다. 실제 사망은 프리뷰 f19→70이다. 합본 왼쪽은 3/4, 오른쪽은 수직에서 25° 드론 시점이다. 각 시점 800×600 Blender EEVEE 렌더다. 위상 시트는 각 행이 .20/.30/.55/.72초이며 위 3/4·아래 드론이다.

## 확인 근거

[직접 평가 수치](death-metrics.json)는 별도로 다시 연 원본을 0.1프레임 간격, 511상태에서 평가한 결과다.

| .40초 | 2.1481 |
| .55초 | 1.5881 |
| .70초 | 0.5481 |
| .82초 | 0.0156 |

- 모델 89메시·evaluated 15,351삼각형.
- 침강 전 최대 바닥 침범 3.69e-7 model-unit로 부동소수점 오차 수준.
- .28~.40초 잔해 높이 유지. 머리의 분리 후 최대 상승 오차 2.38e-7 model-unit로 눈에 보이는 튐 없음.
- .28초 머리·좌우 팔의 최저점이 모두 Z≈0.035 바닥에 닿음.
- 소등은 별도 복사 재질, 흡수는 동일 모양의 실제 Z 이동. 작은 먼지만 반투명 3D 표면으로 사라짐.

[독립 검증](independent-review.md) **PASS**. 팔 자세·착지·느린 흡수·원본 보존과 국소 보정 후 팔/머리 분리를 확인했고 미해결 결함은 없다. [영상 검사](video-check.json)는 최종 MP4 3개의 전체 디코드와 60fps·261프레임·4.35초를 확인한다.

분리 도중 .20초 우측 어깨돌과 머리의 작은 교차를 발견해 팔 낙하 중간만 최대 0.14 model-unit(약 0.019 tile) 바깥으로 우회시켰다. .20/.23/.275초 양 어깨돌과 머리의 표면 교차가 없어짐을 확인했다. 최종 착지 위치와 침강은 그대로다. 초기 승인 모델의 어깨-머리 접합 겹침은 분리 과정에서 해소된다.

## 재생성

기존 Blender 인스턴스의 `Medium_Guardian_Walk_V3` 승인 모델에서 별도 `Medium_Guardian_Death_Absorb` 씬을 만든다. 원래 Death·걷기 씬은 보존한다.

1. Blender MCP에서 `build_death.py`, `build_preview.py`, `refine_dust.py`를 순서대로 실행한다.
2. 별도 background Blender에서 `medium-guardian-death.blend --python finalize.py`를 실행해 직접 열리는 편집 파일로 정규화한다. `Death_Absorb` 액션, `Guardian_Death_Absorb_Rig` 리그가 생성된다.
3. `death-tile-preview.blend --python render_death.py -- phases`는 대표 4위상, `--python render_death.py`는 87프레임 두 시점을 렌더한다. 이 경로도 기본 씬을 정규화해 저장한다.
4. `medium-guardian-death.blend --python measure_death.py`로 수치를 평가하고 `pack_death.sh`로 영상·위상 시트를 패킹한다. `FFMPEG` 환경변수로 실행 파일을 지정할 수 있다. `check_video.py`로 최종 영상을 디코드 검사한다.
