# 죽음 V3 — 낮은 돌무더기와 사전 계산 소멸

[두 시점 영상](rubble-preview.mp4) · [3/4](rubble-three-quarter.mp4) · [25° 드론](rubble-drone-25.mp4) · [GLB](medium-guardian-rubble.glb) · [편집 원본](medium-guardian-rubble.blend) · [경량 키·PBR 원본](medium-guardian-rubble-runtime.blend) · [대표 위상](phase-sheet.png)

현재 권장 시안이다. 관절 연결이 끊어지고 돌 부품이 낮은 무더기로 내려앉은 뒤, 잠깐 머물렀다가 작은 조각부터 부스러져 사라진다. [이전 흡수 시안](../v2-absorb/README.md)은 보존했다. **물리·IK·충돌 판정은 제작 때만 계산하고, 제공 GLB는 이미 굽힌 강체 본 키만 재생한다.** 게임 코드 적용·배포·커밋은 포함하지 않는다.

## 동작과 원본 보존

실제 동작은 **53/60초 = 약 0.883초**, 60fps에서 **f1→54**다.

- 0~.08초: 눈·가슴 핵·룬이 짧게 꺼진다. 표준 GLB에서도 같은 동작이 되도록 별도 소등 본 4개로 해당 작은 표면만 사라지게 한다.
- .055~.28초: 연결이 풀리며 **14개 주요 덩어리**가 가까운 바닥으로 내려앉는다. 머리 4조각·몸통 2조각과 어깨/주먹/하체를 사용한다. 팔을 양옆으로 펼치지 않는다.
- .28~.43초: 낮고 비대칭인 돌무더기를 잠깐 유지한다. 절단면이 모두 위로 정렬되지 않도록 머리 조각별 회전을 다르게 했다.
- .43~.87초: 작은 덩어리부터 서로 다른 시점에, 자기 바닥 접점을 기준으로 짧게 부스러져 사라진다. 큰 머리도 4개 조각의 방향·시점을 나눴다. 통째로 땅 아래로 잠기지 않는다.

승인 89메시·15,351tri의 외부 표면을 바탕으로 머리와 몸통만 오프라인 분할했다. 편집 원본은 93메시·15,809tri이며 **458tri 증가는 내부 절단면/분할 경계**다. 형태를 다시 만들거나 디시메이션하지 않았다. 생성된 절단면은 분리되기 전 내부에 있다. 일부 가려진 내부 겹침은 돌무더기 표현으로 허용하며, 명백한 부유·바닥 관통은 피했다.

원래 메시별 Object 재질 좌표는 `RestObject` 정점 속성으로 보존해 합친 뒤에도 베이크 위치가 바뀌지 않게 했다. 작은 3D 먼지는 기존 표현을 재사용한 시안 보조 효과다. **GLB에는 수호자 본체만 포함**하여 단일 메시/재질 구조를 유지한다.

## 런타임 구조와 측정 범위

| --- | ---: | ---: |
| 수호자 메시 오브젝트 | 93 | **1** |
| 렌더 표면 | 여러 오브젝트·재질 슬롯 | **1 primitive / 1 material** |
| 삼각형 | 15,809 | **15,809** |

| 물리·IK·본 constraint | 제작 스크립트에서만 계산 | **0** |

GLB의 54개 채널은 18개 본의 이동·회전·크기다. 동일 움직임 부품을 본당 rigid weight 1로 묶고 atlas 한 재질로 합쳤다. 원본의 별도 부품 오브젝트를 93개 유지하는 구조를 내보내지 않았다. 최적화 후 **531상태의 실제 정점 대조 최대 오차는 0.001410 model-unit**, 표시 폭 .55타일 환산 약 **0.000188 tile**이며 목표 .002 model-unit 이내다. RDP의 내부 판단값은 근사 지표이고, 이 직접 평가값을 최종 오차로 사용한다.

최종 GLB는 **4,088,764 bytes(약 3.90MiB)**다. 기하 accessor는 1,397,558bytes, 애니메이션 accessor는 49,848bytes다. UV·법선 경계와 skin 속성 때문에 GLB 정점 저장은 원본 정점 수보다 커질 수 있다.

색·normal·금속/거칠기 통합 이미지 **3장 모두 1024×1024**다. 디코드 후 RGBA8 가정 예산은 **12MiB**, 전체 mip 포함 예산은 약 **16MiB**다. 이는 파일 구조에서 계산한 **예산**이며 실제 프로세스 RAM/VRAM 측정값이 아니다. 2K normal 비교는 효과가 작아 채택하지 않았다. 최종은 normal 강도 4로 축소 필터링 후 석재 요철을 보완한다. 원래 절차적 미세요철과 픽셀 단위 일치는 아니지만, 실제 재임포트 시 거친 석재 정체성을 확인한다.

이 변경은 반복 물리·IK·충돌 계산과 별도 부품 제출 구조를 제거한 것이다. **키 보간·스키닝·렌더 비용은 남는다.** 앱 CPU/GPU 시간·FPS·Android 부하·프로세스 메모리는 이번 디자인 작업에서 측정하지 않았으며 성능 배수로 환산하지 않는다.

## 재생 계약과 확인

초기 GLB 폭은 **1로 정규화**했다. 기존 일반형 표시와 같은 루트 배율 **.55**를 적용하면 폭 .55타일이다. 원본 전방 -Y·위 +Z는 glTF 표준 좌표 변환을 거쳐 Blender 재임포트로 확인한다. 전투 시계의 진행 시간으로 단일 클립을 한 번 재생하고, 종료 시 일반적인 풀 반환/비표시 처리를 적용할 수 있다. 실제 게임 연결은 아직 하지 않았다.

프리뷰는 시작·끝에 .3초씩 정지해 한 번 89프레임/60fps, 3회 반복한 **267프레임·4.45초**다. 왼쪽 3/4·오른쪽 수직에서 25° 드론이며 실제 길 타일 위 800×600 Blender 렌더다. 정지 위상은 0/.28/.42/.65/.80초다. [영상 검사](video-check.json)는 MP4 세 개의 전체 디코드·프레임·시간을 확인한다.

- [실제 GLB 재임포트 씬](glb-reimport-check.blend)과 [두 시점 비교 렌더](glb-reimport/)에서 0/.28/.65/.80초 형태·석재·단계별 소멸을 확인한다.
- 직접 평가한 가시 수호자 부품의 바닥 침범 최대값은 3.02e-7 model-unit로 부동소수점 오차 수준이다. 마지막 주 덩어리의 크기는 0이다.
- 전체 동작의 경계는 `motion-check.json`의 `animation_bounds_model`에 기록한다. 게임에 연결할 때는 엔진의 skinned mesh 가림 경계가 이 범위를 포함해야 한다.
- [독립 검증](independent-review.md) **PASS**. 별도 GLB 재임포트의 형태·재질·단계별 소멸과 단일 메시/재질/애니메이션 구조를 확인했다. 독립 7시점 원본 정점 대조 최대 편차는 0.00008336 tile이다. 미해결 결함은 없다.

## 재생성

기존 열린 원본을 보존하고 별도 `Medium_Guardian_Rubble` 씬을 생성한다.

1. Blender MCP로 `build_rubble.py`, `build_preview.py` 순서 실행. 승인 정적 `Medium_Guardian_Concept`와 기존 작은 먼지 씬을 참조한다.
2. 별도 background에서 `medium-guardian-rubble.blend --python finalize.py`로 직접 열리는 기본 씬을 저장한다.
3. `rubble-tile-preview.blend --python render_rubble.py -- phases` 및 `--python render_rubble.py`로 대표/연속 렌더. `pack_rubble.sh`, `check_video.py`로 패킹·디코드 확인.
4. `medium-guardian-rubble.blend --python export_runtime.py`: 기존 프로젝트의 PBR atlas 베이크 경로를 재사용하여 UV·재질 베이크, 단일 mesh/재질, rigid weights, 오차 기반 키 감소, `ACTIVE_ACTIONS` 단일 애니메이션 GLB를 생성한다.
5. `rubble-tile-preview.blend --python reimport_check.py`로 실제 GLB를 다시 가져와 렌더한다. `medium-guardian-rubble-runtime.blend --python measure_rubble.py`, `glb_stats.py`로 최종 동작·실제 파일 통계를 기록한다.
