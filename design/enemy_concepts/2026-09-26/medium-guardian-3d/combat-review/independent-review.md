# Guardian 실전투 시안 독립 검증

판정: **PASS — opt-in 데스크톱 전투 시안 범위**. 변경 소스와 실제 Godot 렌더의 시간순 프레임을 독립 검토했다. 기본 모델은 그대로이며 실제 일반몹 처치에만 0.6 전투초 죽음 연출이 추가된다.

- `guardian_preview.gd`, `battlefield_units.gd`, `main.gd` 연결을 직접 읽었다. 명시 옵션/인자가 있을 때 normal만 교체하고, 기본 경로는 preview GLB를 로드하지 않는다. 전투 수치·저장 변경은 이 표시 경로에 없다.
- native `kill` 이벤트만 시체를 만들고 `arrival`은 제외한다. 이벤트 ID와 적 ID로 중복 생성을 막으며, 전투 표시 시계로 수동 AnimationPlayer seek 후 0.6초에 제거한다. 기본 제거 경로가 사라진 적을 죽음으로 오인하지 않는다.
- 보행은 native `distanceTravelled`에 맞춰 위상을 정한다. 이동 거리 0.284375 tile당 26/60초 애니메이션 한 주기이며, pause·배속·감속이 실제 이동에 함께 반영된다. 기존 정현파 부유는 preview에 적용하지 않는다.
- 실제 Godot 검사 스크립트와 [24개 계약 검사 결과](guardian-contract-check.log)를 읽었다. pause, 4x, slow, 실제 native 처치, 도착 제외, 중복 방지, 위치/방향/스케일 유지, 0.6초 제거, 해제 검사가 통과했다. 해당 실행 근거를 재사용했으며 별도 전체 회귀를 반복하지 않았다.
- [Godot 스킨 정점 검사](guardian-skin-bounds.log)와 최종 캡처에서 import 후 본체 분리·크기 폭발·재질 소실은 없다. 보행 폭 약 0.543~0.544 tile, 죽음 시작 폭 0.55 tile로 교체 크기가 일치한다. 죽음의 바닥 오프셋 보정도 표시 코드와 계약 검사에서 확인했다.
- [고정 시점](captures/angled/)의 00034/00046/00055/00072 및 00516/00525/00540/00660/00839, [드론 시점](captures/drone/)의 00034/00052/00069/00525를 시간순으로 직접 검토했다. 게임 크기에서 큰 머리와 석재 몸체, 낮게 무너진 잔해가 구분된다. 일반몹 이동·실제 타격·쓰러짐·제거가 연결되며, 마지막 고정 프레임에 시체 잔류가 없다.
- [실제 이벤트 기록](captures/angled.json)은 stage 1 wave 3의 대포/기관총 공격으로 9처치, 최대 동시 시체 2개를 기록한다. 잔해가 길 전체를 덮거나 오래 누적되지 않는다. 대포 폭발/연기가 일부 죽음의 세부 붕괴를 잠깐 가리지만 기존 효과와 자연스럽게 겹치는 수준이다.

- 추가 4x 확인: [드론 4x 캡처](captures/drone-4x/)의 00175/00179/00183/00188/00299를 시간순으로 직접 확인했다. [이벤트 기록](captures/drone-4x.json)의 실제 처치 구간에서 붕괴·하강·제거가 압축된 시간에 진행되고 마지막에 잔해가 없다. 4x에서도 최대 동시 시체 2개이며 추가 누적·형태 이상은 발견하지 않았다. 0.6 전투초가 약 0.15 실제초로 재생되어 세부 붕괴는 빠르게 지나간다.

한계: 화면 근거는 440×900, 1x와 4x의 실제 Godot 렌더 프레임이다. 실시간 플레이어 재생을 직접 관찰했다고 주장하지 않는다. pause·slow는 Godot 계약 검사로 확인했다. 모바일 기기·FPS·대량 전투 성능은 미측정이며 이번 결과로 성능을 보증하지 않는다. preview는 기존 정적 모델용 화상/서리 본체 오버레이를 생략하지만 전투 상태·상태 표시는 유지한다. 정식 모델 교체나 배포 판정은 범위 밖이다.
