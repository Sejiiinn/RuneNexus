# 승인된 라이트닝 A의 게임 이관

2026-10-03 승인된 낮은 쌍전극 포탑, 여섯 보라색 유도 코일, 중앙 사각 코어, 전방 입체 분기 전류와 반투명 구형 아우라를 기준으로 한다.

## 원본과 재생성

`lightning-A-approved.blend`가 보존된 승인 원본이다. 1–88프레임은 공격 두 회, 101–140프레임은 충전 상태의 카메라 이동이다. 원본은 153개 부품, 23,140삼각형이다. 게임용 모델은 코일 고리 18개만 감량해 **17,380삼각형**이며, 8재질·20표면·루트/헤드/배럴/총구 계약을 유지한다. 나머지 135개 부품과 PBR 재질·전체 경계·물리적 크기는 동일하다. 현재 GLB는 817,220바이트로 이전 통합본보다 17.96% 작다. 원본 Blender 파일은 변경하지 않았다.

저장소 루트에서 Blender 4.3 이상과 프로젝트 기준 Godot 4.7.2로 재생성한다.

```sh
blender -b --python design/lightning_tower_concepts/approved_a/export_static.py
blender -b --python design/lightning_tower_concepts/approved_a/extract_lightning_paths.py
blender -b --python design/lightning_tower_concepts/approved_a/render_hud_icon.py
godot --headless --path godot --script ../design/lightning_tower_concepts/approved_a/bake_lightning.gd
python3 scripts/prepare_godot_project.py
godot --headless --editor --path build/godot/project --import --quit
godot --path build/godot/project -- --session
```

게임 자산은 `assets/images/stage1_3d/turrets/lightning.glb`와 `godot/effects/lightning_attack_meshes/`에 있다. 추출·베이크 스크립트는 승인 원본의 실제 곡선 제어점과 테이퍼를 사용한다. 정적 내보내기는 기본 `--coil-segments 16`이며 `--coil-segments 24`는 보수적인 대안, `--coil-segments 0`은 원본 GLB를 바이트 단위로 재현한다. [내보내기 기록](export-manifest.json)에 모델 해시와 부품별 수량을 기록했다. Blender의 볼륨·재질 그래프가 GLB에 그대로 이식됐다고 간주하지 않는다.

공유 설치·선택 아이콘 `assets/images/ui/hud/turrets_3d/lightning.png`은 승인 모델로 렌더한 기존 PNG를 유지한다. 이번 감량은 런타임 기하만 대상으로 한다. 기존 고정 카메라 `(4,-4,5.5)`, 주시점 `(0,0,.4)`, 정투영 1.45와 256×256 RGBA를 유지하고 다른 포탑 PNG는 변경하지 않았다. 실제 정점 경계와 입력 해시는 `hud-icon-verification.json`에 기록했다.

## 표시와 전투 계약

`lightning_presentation.gd`는 기존 전투 이벤트의 나이를 받아 `lightning_attack.gd`를 재생한다. 기존 0.3초 충전, 0.07초 연쇄 간격, 피해·대상 선택·쿨다운은 유지하고 소유 포탑·출발 적 ID만 표시 정보로 추가한다. 실제 총구와 적 메시 표면 사이에 연결하며, 제거된 배우의 진행 중 방전은 마지막 표면 위치를 보존한다.

15개 공유 메시를 재사용하고 프레임마다 곡선을 만들지 않는다. 아우라는 실제 구체 안에서 최대 10번 밀도를 샘플링하는 공간 셰이더다. 광원은 전체 라이트닝 표시에서 그림자 없는 세 개로 제한한다. 충돌 표면 바로 바깥에 배치하며 새 연쇄 타격이 발사 원점·충전 조명보다 우선한다. 0.6타일 안의 겹친 조명은 합치고 가장 강한 하나만 남긴다. 대기 풀은 32개이며 장면 종료 시 해제한다. 볼륨 옵션은 아우라·보조 조명을 제어하고 입체 전류는 유지한다. 별도의 누적 시계나 전투 난수를 사용하지 않는다.

라이트닝만 공용 화약 연기와 총기식 배럴 반동을 생략한다. 코일은 뒤에서 앞으로 밝아지고 기본 PBR 색·금속성·거칠기를 유지한다. 표시 소유 정보가 있는 새 네이티브 라이트닝 이벤트만 기존 Canvas에서 중복 생성하지 않으며, 다른 포탑·기존 입력은 보존한다. 로딩 시 기존 효과 준비 단계에서 셰이더를 예열한다.

`--session`은 실제 콘텐츠·건설 비용·네이티브 웨이브를 쓰는 개발 화면이다. 이 진입에 빠진 표시 계약 버전과 선택적 저장 실패 속성의 null 처리를 보완했다. 사용자 저장 영역과 분리해 검수한다.

## 연쇄 강도 보정

2026-10-03 실제 게임 화면의 가느다란 연쇄와 충돌 조명 부족 피드백을 반영했다. 승인 분기 경로·충전구·포탑은 보존하고 베이크 단계에서 방출 주 줄기의 외피/중심 반경을 각각 3.4/3.2배로 넓혔다. 보조 분기는 2.5/2.3배, 잔가지는 1.7/1.6배다. 연쇄의 표시 배율은 0.70에서 0.95로 조정하고 밝은 청백색 중심과 청보라 외피를 구분했다. 첫 방출의 짧은 32% 광도 강조와 더 읽기 쉬운 공간 접점 분기를 사용한다. 메시 수·표면 수·삼각형 수는 증가하지 않는다.

충돌 조명은 최대 범위 1.65타일, 시작 에너지 4.8에서 기존 이벤트 나이에 따라 빠르게 감쇠한다. 그림자·추가 시간 누적 없이 적과 지형의 실제 재질을 비춘다. 전체 공유 조명은 최대 세 개다. 기존 피해·연쇄 간격·횟수·타겟과 승인 구형 아우라는 변경하지 않았다. 프레임 렌더 직전에 새 효과가 생성될 때 원점에 잠깐 보이지 않도록 메시와 광원의 위치 갱신을 즉시 반영한다.

## 게임 시점 기준 기하 감량

2026-10-03 사용자의 “게임 시점에서 큰 차이가 없으면 감량” 조건에 따라 같은 카메라·880×760·네이티브 시계·난수·조명으로 비교해 대기·충전·연쇄와 회전 후 옆모습에서 큰 외형 차이가 없음을 확인했다. 코일은 원래 24각 실린더의 둘레 이음새까지 중복 bevel이 생기던 구조였다. 원형 단면을 16각으로 만들고 필요한 테두리 bevel만 남겨 코일 10,368→4,608삼각형으로 줄였다. 코일 표면의 최대 샘플 거리 차이는 0.000979타일이며 다른 부품은 동일하다.

번개는 주 줄기의 6각 단면과 모든 분기·제어점·테이퍼를 유지한다. 가는 분기의 단면만 4각으로 줄이고 평균 투영 폭을 맞췄다. 색·밝기·수명·타격 조명은 그대로다. 구형 아우라의 외피는 624→288삼각형이며, 셰이더가 계산하는 동일한 구체를 완전히 감싸는 보이지 않는 경계 메시다. 가장 가까운 면도 실제 구체 바깥에 있으므로 표시 경계를 다각형 안쪽으로 자르지 않는다.

| 구분 | 이전 | 감량 |
| --- | ---: | ---: |
| 포탑 본체 | 23,140 | 17,380 |
| 충전 효과 전체 | 6,024 | 3,944 |
| 방출·연쇄 한 구간 최대 | 10,512 | 6,912 |
| 기본 두 번 연쇄가 겹친 효과 최대, 0.07초 간격 | 26,632 | 17,528 |

삼각형 수는 LOD0의 표시 인스턴스 기하 기준이다. 그림자·가림 이후 GPU 작업량이나 Android FPS 측정값이 아니다. 메시 표면·드로콜·조명 수는 줄이지 않았고, 볼륨 픽셀 셰이더 비용도 유지한다. ## 검증

- 원본/GLB 형상·노멀·재질·계층 비교 및 Godot 임포트 통과
- 네이티브 전투·코어 방어·세션·입력 회귀 통과
- 기존 BattlefieldEffects와 새 효과의 나이·정지·대상 이동·재사용·재질 독립성·볼륨 전환 검사 통과
- 초기 이관 검수: 실제 Godot 4.7.2의 1스테이지 10웨이브에서 충전 13회, 주 방출 13회, 연쇄 24회 확인. 이번 보정에서는 전투·표면 접점 코드를 바꾸지 않았다
- 정지·4배속·움직이는 표면 접점·카메라 전환·판매·장면 초기화 통과. 통합 헤드리스 34항목과 240단계 기준 전투/시계/난수 동일성 확인
- 연쇄 보정 독립 검사: 조명·수명주기 126항목, 변형 정점 106,272개의 가림 경계 관련 97항목, 기존 번개 모듈 검사가 통과했다. 가장 긴 후기 분기의 표적 뒤 3.434% 돌출을 가림 경계에 포함했다
- 최신 실제 게임 화면: 11초 정상 속도에서 주 방출 6회와 연쇄 12회, 최대 효과 3개·조명 3개 확인. 같은 프레임의 광원 켜기/끄기 비교에서 적·지형의 빛 반응을 확인했고, 첫 생성 프레임의 원점 번개 조각은 수정 후 사라졌다. 정지·4배속·종료·초기화 검사 통과
- Android 기기 렌더링·지속 성능: 미검증

대표 화면은 [충전](verification/charge.png)과 [연쇄](verification/chain.png), 조건·해시는 [검증 기록](verification/verification.json)에 있다. 880×760, Godot 4.7.2 OpenGL Compatibility/X11, llvmpipe 소프트웨어 렌더 환경이다. 녹화의 30fps는 고정 시간 간격 캡처이며 실시간 성능 측정값이 아니다. Android/Vulkan Mobile 검증을 대체하지 않는다.

디버그 진입의 표시 계약과 단위 변환 누락을 함께 보완했다. 정식 앱과 동일한 48px Canvas 기준을 사용하므로 피해 숫자가 과대 표시되지 않는다. Canvas의 라이트닝 판정은 가벼운 이벤트 메타데이터 함수에 두어 2D 검사에 3D 자산 의존성을 추가하지 않았다.

감량 검수의 기준 영상은 새 기준 촬영 90프레임과 디버그 문구 외 게임 픽셀이 전부 일치하는 기존 승인 330프레임을 재사용했다. 같은 원본·카메라·난수·네이티브 시간·조명을 확인했고, 비교 영상의 서로 다른 디버그 문구는 그대로 표시했다. 감량본 11초에서도 주 방출 6회·연쇄 12회·최대 광원 3개와 정지·배속·종료·정리 검사가 통과했다. 드로콜 범위 151–262개는 같으며 이 수치로 GPU 시간이나 Android FPS 개선을 주장하지 않는다.
