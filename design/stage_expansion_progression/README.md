# 확장 스테이지 성장·해금 배분

역할: 챕터 1·2 확장에 맞춘 강화·연구·포탑 및 연관 기능의 해금 배분 원본. 확인일: 2026-09-30. 승인된 배분과 기존 권한 보존의 기준이다. 실제 구현·검증 상태는 [본게임 연결·검증 범위](../../godot/content/README.md#확장-진행과-고정-id)에서 관리하며 기존 비용·스탯·보상은 유지한다.

대상은 [챕터 1의 1-6~1-10](../chapter1_map_expansion/README.md)과 [챕터 2의 2-6~2-10](../chapter2_map_expansion/README.md)을 포함한 25개 진행 순서다. 챕터 3은 기존 **3-1~3-5**만 사용한다. 아래 새 조건은 확장 콘텐츠의 신규 진행에 적용하며, 기존 사용자에게는 [권한 보존 기준](#기존-사용자-권한과-저장-보존)이 우선한다.

## 번호와 완료 조건

| 구분 | 기존 맵의 고정 ID | 확장 진행 |
| --- | --- | --- |
| 챕터 1 | 고정 ID 1~5 = 1-1~1-5 | 1-1~1-10, 진행 순번 1~10 |
| 챕터 2 | 고정 ID 6~10 = 2-1~2-5 | 2-1~2-10, 진행 순번 11~20 |
| 챕터 3 | 고정 ID 11~15 = 3-1~3-5 | 3-1~3-5, 진행 순번 21~25 |

기존 고정 ID는 그대로 유지한다. 특히 **ID 6은 계속 2-1**, **ID 10은 계속 2-5**, **ID 11은 계속 3-1**이다. 신규 챕터 1의 고정 ID는 16~20, 신규 챕터 2는 21~25로 정했다. `chapterStage`와 `progressionOrdinal`을 저장 ID로 사용하지 않는다.

표의 `1-6 클리어`는 해당 맵의 최종 라운드를 성공으로 끝낸 상태를 뜻한다. 진입·최고 도달 라운드·총 클리어 개수로 대체하지 않는다. 기본 해금은 첫 런부터 이용 가능하다는 뜻이다. 강화 해금은 룬 구매 자격, 연구 해금은 연구 시작 자격이며 무료 레벨 지급이 아니다. 연구 완료 후 효과가 생기는 계약과 기존 비용·시간·최대 레벨은 유지한다. 슬롯 2의 클리어 조건은 **구매 자격**이고 실제 이용은 600다이아 결제 이후다.

## 이식 전 조건과 새 배분

현행 자료는 [성장 콘텐츠](../../godot/content/growth_content.json), [로컬 성장 규칙](../../godot/app/growth_rules.gd), [강화·연구 UI](../../godot/ui/lobby_growth.gd)를 대조했다. 아래 현행 열은 이식 전 조건을 뜻하며 숫자는 진행 순번이 아니라 `clearedStageNumbers`에 쓰는 **고정 ID**다.

처치 보상·긴급 매각 효과가 공유하는 기존 **경제 해금 ID 1 / 1-1 클리어**는 유지한다. 치명 집중·치명 충격의 효과 게이트는 새 배분에서도 **1-4 클리어**다. 관통 젬은 성장 콘텐츠의 명시 값 10을 기준으로 했으며 성장 규칙의 누락 시 fallback 값 3을 실제 현행 조건으로 오해하지 않는다.

## 스테이지 배분에서 제외한 성장

이 절의 제외는 기능 삭제가 아니라 기존 별도 조건의 유지다.

- 런 강화 `towerDamage`, `killGold`, `waveGold`: 기본 이용을 유지한다. 골드와 현재 레벨·최대 레벨 조건으로 반복 구매하며, 스테이지별 레벨 제한을 만들지 않는다. 연구로 늘어나는 최대 레벨만 위 표에서 배분했다.
- 포탑 레벨 1~10·링크 홈 구매: 소유 포탑·골드·앞 홈부터 구매·두 번째 홈 Lv.1 / 세 번째 이후 홈 Lv.5 조건을 유지한다. 기본 최대 홈 3개와 `linkExpansionOne` 완료 후 4개라는 제약을 유지한다. 링크 확장 연구 해금 자체가 홈을 무료로 열지 않는다.
- 포탑 1차/2차 특성: 기존 **Lv.3 / Lv.7**, 2차의 1차 선행, 해당 포탑의 선택 가능한 특성·젬 조각 비용·런당 단일 선택을 유지한다. 새 스테이지 해금으로 바꾸지 않는다.
- 코어 패시브 전체 21노드: 코어 포인트·시작 노드·연결 선행 노드 3랭크·노드별 최대 랭크와 비용으로 여는 트리를 유지한다. 노드별 스테이지 게이트를 추가하지 않는다. 기준은 [코어 트리 현행 원본](../../docs/core_passive_tree_implementation_plan.md)과 성장 콘텐츠의 `core`다.
- 모듈 구축 레벨: 누적 뽑기 수로 오르는 기존 체계를 유지한다. 단계별 등급 확률·모듈 수치·비용을 스테이지 배분과 함께 바꾸지 않는다.
- 현행에서 비활성인 구 치확·긴급 매각 영구 강화와 구 `bossBounty` 연구는 새 현행 선택지로 복원하지 않는다. 구버전 저장의 효과 이전은 아래 기준과 [현행 성장 이전 계약](../../docs/gameplay_balance_reference.md#영구-업그레이드)을 따른다.

## 기존 사용자 권한과 저장 보존

아래는 **이식의 필수 보존 기준**이다. 구현 책임은 [진행 규칙](../../godot/content/stage_progression.gd), [저장 코덱](../../godot/app/save_codec.gd), [클리어 처리](../../godot/app/quest_progress.gd), [서버 최초 보상](../../server/internal/economy/run_rewards.go), [기존 경제 최초 연결](../../server/internal/economy/bootstrap.go)에 있으며 실제 검증 상태는 [본게임 연결·검증 범위](../../godot/content/README.md#확장-진행과-고정-id)를 따른다.

1. **구 조건을 먼저 평가한다.** 새 진행표나 정규화된 값으로 덮기 전에 원본 저장의 성장 버전·클리어 ID·기존 진입 가능 상태·레벨·연구·경제 권리를 읽는다. 구 기본 기능은 기존 저장 사용자에게 레벨 0이어도 해금 상태로 보존한다. 예를 들어 `bossBounty`와 `linkMaintenance`는 레벨이 0이어도 구 기본 권리를 유지하고, ID 2 클리어 사용자의 젬 감응은 연구 레벨 0이어도 유지한다. ID 6 클리어 사용자의 번개도 2-2를 다시 클리어할 필요가 없다.
2. **해금 자격과 구매 완료를 분리해 보존한다.** 구 ID 10 클리어 사용자는 슬롯 2가 미구매여도 구매 자격을 유지하지만 600다이아를 지불해야 한다. 이미 구매한 `researchSlotTwoUnlocked=true`는 서버 권위 경제의 보유 권리로 유지하며 재결제하지 않는다. 구 ID 8 클리어 사용자의 슬롯 안내 노출도 유지한다. 구 `unlockedStageCount>=6`의 균열 낙인 권리도 실제 장착 여부와 무관하게 유지한다.
3. **보존 권한은 단조롭게 합친다.** 정규화 뒤에도 식별 가능한 영구 보존 정보로 남겨 `구 보존 자격 OR 새 맵 클리어 자격`을 사용한다. 화면·연구 시작·포탑 건설·젬 보상 풀·코어 장착·서버 모듈 뽑기·슬롯 구매가 동일 자격을 해석해야 한다. 단순 `레벨>0` 검사만으로 레벨 0 권한을 복원하지 않는다. 기존 구매/연구/활성 런의 유효한 획득 기록도 보존 근거이며, 현행 강화 UI와 명령 게이트 차이 때문에 얻은 기존 레벨·효과를 소급 취소하지 않는다.
4. **맵별 기록은 고정 ID 그대로다.** `bestRoundsByStage`, `clearedStageNumbers`, `claimedCorePointStageRewards`, 선택한 맵, 활성 런·런 ID, 클리어 보상 영수증은 표시 순번으로 다시 번호를 매기지 않는다. 구 진입 가능한 기존 맵도 유지하며 삽입된 맵 미클리어를 이유로 구 챕터 2·3 접근을 막지 않는다. 구 `unlockedStageCount`를 새 개수·최대 순번으로 그대로 해석하지 말고 구 버전의 기존 ID 접근 범위를 먼저 보존한다. 신규 삽입 맵의 접근 상태는 별도 진행 관계로 정하며, 누락된 신규 맵을 가짜 클리어로 기록하지 않는다.
5. **클리어·최초 보상·구매를 다시 만들지 않는다.** 권한 복원은 클리어 이벤트·연구 완료·원장 지급을 호출하지 않는다. `stage:11:first_clear`와 코어 포인트 수령 ID는 보존하며, 새 진행 순번 11인 2-1에는 기존 ID 11 보상을 주지 않는다. 기존 15개 맵의 보상 금액과 최초 수령 여부도 보존한다. 신규 10개 맵의 보상 고정 ID와 별도 최초 수령 키는 콘텐츠 이식 때 확정한다.
6. **연구 진행을 이어 간다.** 완료 레벨·진행 목표·시작 시각·남은 시간·취소 후 누적 경과·이미 지불한 룬·서버 즉시 완료 영수증을 유지한다. 새 해금 시점 뒤로 이동해도 유효한 기존 진행 연구를 취소·재시작·재과금하지 않는다. 구 `growthVersion=0`의 토벌 연구/치확·긴급매각 영구 강화는 현행 성장 이전 계약의 변환 규칙을 한 번만 적용하고 새 해금 이식과 중복 지급하지 않는다. 특히 토벌 연구 완료 레벨/진행 목표 중 큰 값을 영구 강화로 옮기는 기존 규칙과 서버 pending effect ACK를 보존한다.
7. **로컬·클라우드·재실행에서 같은 결과다.** 저장 스키마와 진행 배분 버전을 구분하고 이식 완료 표시·보존 권리를 원자적으로 함께 저장한다. 구 로컬 저장 복원, 클라우드 불러오기, 경제 bootstrap, 다른 기기 인계, 앱 재실행의 각 진입 경로에서 동일 원본에 이식을 두 번 적용해도 레벨·지갑·보상·권한이 늘거나 줄지 않아야 한다. 저장 실패 후 재시도도 권한 누락이나 중복 보상 없이 복구해야 한다. 클라우드 충돌 해결은 기존 writer generation/revision 계약을 유지하며 구 클라이언트가 새 보존 정보를 지우지 않도록 호환성 경계를 함께 적용한다. 정규화가 새 권한 필드를 버리는 현행 코덱 경로는 이식 시 반드시 대응한다.

현행 성장 버전 1은 이미 구 치확/긴급매각 영구 필드를 새 저장에서 제거한다. 따라서 보존 스냅샷을 만들기 전에 원본을 버리면 레벨 0 자격과 구 성장 이전 근거를 잃을 수 있다. 서버 권위 지갑·모듈·구매 권리는 클라이언트의 보존 플래그만으로 생성하지 않으며, [서버 경제 계약](../../docs/server_authoritative_economy_design.md)과 [저장 동기화 계약](../../docs/multi_device_save_sync_design.md) 안에서 검증·이관한다. 저장 스키마 v2와 서버 경제 원장·영수증 계약을 보존한다.

## 확인 범위와 남은 조건

- 문서 검사: 성장 카탈로그의 영구 강화 13개·연구 14개 및 현행 UI/성장/서버의 해금 조건을 대조하고, 새 표에 중복·누락 없이 반영했다. 기존 15개 고정 ID와 확장 진행 순번 1~25를 분리했다.
- 문서 자체 검사: 영구 강화 13개·연구 14개의 키 집합·중복 여부, 스테이지 25개의 표시/순번, 상대 링크·앵커 20개를 대조해 통과했다. 독립 검증은 별도로 판정한다.
- 구현·검증 상태: 고정 ID·실제 콘텐츠·권한 이식·클라이언트/서버 조건의 현황은 [본게임 연결·검증 범위](../../godot/content/README.md#확장-진행과-고정-id) 한 곳에서 관리한다.
- 검증 구분: 이 문서의 조건 대조와 본게임·격리 저장/DB 실행 검증, 전체 25스테이지의 40라운드 체감·연구 소요 시간·기기 경험·운영 계정 검증을 구분한다.
