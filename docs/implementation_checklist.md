# 구현·검증 체크리스트

역할: 구현 담당자(assistant 포함)가 현재 작업을 마무리할 때 확인해야 할 버그·검증·배포 선행 조건. 사용자의 미래 개발 계획은 [TODO](TODO.md)에서 별도로 관리한다.
기술 항목의 기존 대조 기준: 2026-10-10 KST(UTC 2026-10-09). 문서 역할 분리: 2026-10-10 KST. 기존 TODO의 기술 항목 5개를 보존해 옮겼으며, 이번 정리에서 게임·DB·운영 환경을 새로 실행하거나 배포하지 않았다. 구현/검증 사실은 각 근거 문서, 공개 여부는 [배포 상태](deployment_status.md)에서 관리한다.

## 등록·완료 기준

- 현재 결함, 진행 중인 승인 작업의 미완료 조건, 저장/배포 안전을 위한 필수 검증을 등록한다. 새 제품 방향이나 사용자의 장기 계획을 대신 정하지 않는다.
- P0는 해당 변경의 공개를 막는 선행 조건, P1은 현재 제품/콘텐츠의 확인된 검증 공백, P2는 명시된 시점 전에 필요한 조건이다. 이 구분은 기술적 확인 순서이며 사용자의 개발 계획 우선순위가 아니다. P0를 현재 운영 장애로 해석하지 않는다.
- 작업은 구현·로컬 자동 검사·실제 기기·실계정·배포를 구분한다. 이미 통과한 범위를 다시 구현할 일로 올리지 않는다.
- 완료하면 이 목록에서 제거하고 기존 기능/검증/배포 문서에 결과를 남긴다. 다른 문서는 해당 항목을 링크한다.
- 이 목록은 사용자에게 배정한 할 일 목록이 아니다. 사용자 담당으로 확인된 실계정 로그인 등은 담당과 제한을 따로 표시한다.
- 배포, 운영 데이터 변경·삭제, 새 기능 채택은 이 목록에 적혔다는 이유만으로 승인되지 않는다.

## P0 · 챕터3 확장 공개 전에 서버·DB 호환성 검증과 선행 반영

- 상태: ID26–30 및 경로 저장 구현·서버 단위 검사는 진행됐으나, 실제 PostgreSQL 013 실행과 해당 서버의 운영 반영은 미검증·미배포다. 로컬 경로 저장/복원 기능 자체가 미구현이라는 뜻은 아니다.
- 필요한 이유: 기존 012까지의 스키마는 스테이지 상한이 25다. 새 기록·랭킹과 다중 경로 저장을 받으려면 013의 제약/표현식 인덱스와 호환 세대5 서버가 먼저 필요하다. 순서를 어기면 새 스테이지 기록 거부 또는 구클라이언트의 경로 정보 손실 위험이 있다.
- 할 일: 격리 PostgreSQL에서 012→013, 기존 기록/달성 시각 보존, 26–30 랭킹 정렬, 저장·정산·보상 재시도, 세대4/5 경계를 검사한다. 신규 기록이 있는 상태의 down 거부와 트랜잭션 보존도 확인한다. 공개 승인을 받은 경우에만 운영 백업/복원 확인 후 013→서버→APK 순으로 반영한다.
- 완료 조건: 실제 DB 통합 검사와 이관 결과가 기록되고, 공개 시 운영 DB 버전·서버 리비전·readiness가 새 계약과 일치한다. 기존25맵의 세대4 접근은 유지하면서 새 진행/경로 저장은 세대5 미만의 덮어쓰기를 막는다. 최신 APK 공개 전에 서버 선행 반영을 확인한다.
- 근거: [013 SQL](../server/db/migrations/013_chapter_three_routes.sql), [확장 스테이지 계약](../server/db/migrations/README.md#확장-스테이지), [DB 통합 검사](../server/internal/dbtest/expanded_progression_integration_test.go), [호환 세대 판정](../server/internal/save/growth_compatibility.go), [현재 미배포 변경](deployment_status.md#현재-미배포-변경).

## P1 · 챕터3 후반의 정상 성장·연속 플레이 난이도 확인

- 상태: 정적 페이싱 감사와 전투 기능 fixture는 있다. 정상 성장 상태에서 1–40라운드를 연속으로 진행한 경제·클리어 난이도는 확인하지 않았다.
- 필요한 이유: 3-6 나선은 일반 적의 무방해 이동이 3-9보다 약2.07배 길고, 짧은 분기 맵은 후반 화력 압박이 크다. 현재 fixture는 시작 골드60,000과 미리 구성한 포탑을 사용하므로, 기능 통과만으로 실제 획득 골드·투자 선택·보스 대기 시간을 판정할 수 없다.
- 할 일: 해당 구간에 도달 가능한 성장·해금·재화로 맵별 연속 플레이를 기록한다. 라운드별 누수/클리어, 포탑·젬 투자, 골드 부족 시점, 분기 대응과 보스의 전투 후 대기 구간을 확인한다. 실제로 문제를 재현했을 때만 원인에 맞춰 조정하며 신규 시스템·전역 수치 변경을 미리 확정하지 않는다.
- 완료 조건: 사용한 성장/빌드와 맵별 연속 플레이 결과가 남고, 진행 불가·과도한 빈 대기·보상 단절 여부를 판단할 근거가 있다. 발견한 결함은 같은 조건으로 수정·재확인한다. 실패한 빌드 한 가지를 근거로 전체 난이도를 단정하지 않는다.
- 근거: [챕터3 정량 페이싱과 fixture의 한계](../design/chapter3_map_expansion/README.md#정량-페이싱-감사), [전투 fixture](../godot/session/chapter_three_combat_fixture.gd), [실제 스탯 전투 검사](../godot/verify_chapter_three_normal_combat.gd).

## P1 · 최종 Android 앱의 기기 동작·지속 성능 확인

- 상태: 최신 공개본의 APK 무결성·CI·데스크톱 검증은 있고, 최종 Android 설치/실행은 AVD 부팅 실패와 연결 기기 부재로 미검증이다.
- 필요한 이유: 모바일 GPU, 터치·시스템 뒤로가기·백그라운드 복귀, 실제 업데이트 후 저장 유지는 데스크톱 결과로 대신할 수 없다. 최근의 메시/텍스처·전투 시계 변경을 기기에서 확인할 필요가 있다.
- 할 일: 사용 가능한 Android 실기기에서 검증 대상 APK를 명시하고 기존 설치 위 업데이트→기존 저장 이어하기→전투→백그라운드/복귀→종료/재실행을 확인한다. 대표 전투의 프레임·메모리·발열/지속 성능과 터치·글자/안전 영역을 확인한다. 챕터3 포함 후보를 검증할 때는 위 서버 선행 조건을 지킨다.
- 완료 조건: APK/기기/OS/GPU와 시나리오별 결과·성능 측정 조건을 기록한다. 에뮬레이터만 확인한 항목과 실기기 결과를 구분하고, 진행 중 전투/경로/골드·보상이 업데이트와 복귀 뒤 유지된다. 발견한 재현 가능한 결함은 수정 후 해당 조건으로 확인한다.
- 근거: [최신 배포의 검증 범위](deployment_status.md#2026-10-09-android-0217--code-6046--공개-완료), [전환 단계별 검증 상태](godot_unified_app_roadmap.md#3-단계와-의존-관계), [기기 검증 범위](../AGENTS.md#godot-검증과-apk-빌드).

## P1 · 실제 Google 계정의 저장·경제 복구 E2E 확인

- 상태: 네이티브 저장소 결함 수정, 자동 검사와 합성 인증 응답 복원은 확인했다. 실제 Google 로그인·계정 전환·다중 기기 저장/경제 흐름은 완료 근거가 없다. 실계정 로그인은 사용자 담당 확인 항목이다.
- 필요한 이유: 잘못된 시험 토큰의401 응답이나 합성 성공 응답은 실제 OAuth 성공·암호화 세션 재사용·서버 저장/보상 정합성을 입증하지 못한다.
- 할 일: 사용자가 동의한 테스트 계정/기기에서 로그인→재시작 복원→계정 전환/로그아웃과 원격 저장 재조회를 확인한다. 동일 계정의 기기 전환, 오프라인 보상/경제 명령 재시도, 응답 유실 뒤 Outbox 복구, 구세대 writer 차단을 확인한다. 운영 계정의 저장을 임의로 초기화하거나 덮어쓰지 않는다.
- 완료 조건: 실제 계정·네트워크 조건과 사용 버전을 기록하고, 다른 계정으로 저장이 섞이지 않으며 저장 회귀·중복 보상 없이 복구된다. 챕터3 경로 저장을 쓰는 경우 세대4/5의 차단/허용을 실제 API에서 확인한다. 인증값·개인 저장 원문은 기록에 남기지 않는다.
- 근거: [네이티브 로그인 수정의 실제 검증 한계](deployment_status.md#2026-09-24-google-로그인-저장소-연결-수정-android-023--code-6032--공개-완료), [저장 계약](multi_device_save_sync_design.md), [서버 경제 계약](server_authoritative_economy_design.md).

## P2 · 정식 서비스 전 임시 카카오 진행 이전 경로 종료

- 상태: 임시 이전 API·서비스와 설정이 현재 서버에 남아 있다. 저장소의 Compose/운영 예시는 활성값을 사용하지만 실제 운영 플래그와 남은 이용자는 이번에 확인하지 않았다.
- 필요한 이유: 기존 guest 저장의 진위를 보장할 수 없고 복제도 완전히 막지 못한다. 현행 계약은 이 기능을 테스트 이행에 한정하고 정식 서비스 전에 종료하도록 명시한다.
- 할 일: 정식 서비스 전환 시 남은 이전 대상·복구 백업과 운영 플래그를 확인하고 종료 범위를 승인받는다. 종료·TTL 경과·잔여 데이터 확인 뒤 해당 API/설정을 제거한다. 기존 migration을 고치거나 남은 계정 백업을 임의 삭제하지 않는다.
- 완료 조건: 임시 생성/consume 경로가 닫히고 일반 계정 저장 흐름이 유지된다. 남은 복구 요구를 처리한 뒤, 필요한 별도 승인 하에 보관 데이터/테이블 정리까지 기록한다. 폐기된 Flutter/Web 클라이언트를 다시 구현하는 작업은 포함하지 않는다.
- 근거: [임시 이전의 위험·제거 계약](legacy_local_save_transfer.md#정식-배포-전-제거-체크리스트), [현재 API 라우팅](../server/internal/httpapi/handler.go), [서버 활성화 조건](../server/cmd/api/main.go), [Compose 설정](../compose.yaml).

## 계획·아이디어와의 경계

사용자가 앞으로 하고 싶은 큰 작업과 검토 중인 새 기능 아이디어는 [개발 계획 TODO](TODO.md)에 둔다. 아이디어가 논의됐다는 이유만으로 이 체크리스트의 구현 작업으로 승격하지 않는다.

완료된 Godot/Flutter 전환·서버 경제 구현·배포 자동화, 폐기된 Web/Pages·Flutter 작업을 다시 등록하지 않는다. PGS/identity 연결·저장v3·일반적인 모듈 수급 개선 등 옛 제안은 현재 범위와 필요성을 확인하기 전에는 채택하지 않는다. 측정된 병목이나 재현된 결함 없이 넓게 잡은 최적화·리팩터링·콘텐츠 추가도 등록하지 않는다. 과거 후보와 판단은 [이전 목록 보관본](archive/next_work_priorities_before_todo_20261010.md)에 남긴다.
