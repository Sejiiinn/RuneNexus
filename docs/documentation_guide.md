# 문서 작성·유지 지침

역할: 문서의 책임 분리, 작성·갱신·병합·보관 기준. 정리: 2026-09-21. 적용 범위: 저장소의 작업 지침·설계·현황·검증 기록. 진입점은 [문서 지도](README.md)다.

## 역할별 원본

같은 사실의 상세 설명과 변경 가능한 상태는 한 곳에서 관리한다. 다른 문서는 해당 절을 링크하며, 독립적으로 읽는 데 필요한 짧은 범위 설명만 둔다.

현행 기준은 채택한 동작·제약이고, 현황은 마지막으로 확인한 구현 사실이다. 코드가 다르다는 이유만으로 승인된 제품 결정을 바꾸지 않는다. 제안은 승인·구현되지 않은 후보이며, 역사 기록의 명령·승인 조건은 현재 지시가 아니다. 불일치가 있으면 해당 범위의 코드·테스트·승인 근거를 확인하고 불명확한 부분을 명시한다.

## 작성 방식

- 작업 폴더에 기록을 보관하는 것은 커밋 요구가 아니다. 임시 로그·측정 덤프·일회성 검사·중복 원본은 `.gitignore`로 제외하고 로컬에 둔다. 유지할 자료의 선정과 커밋 전 확인은 [커밋 기준](../AGENTS.md#커밋)을 따른다. 로컬 기록을 새 체크아웃에서도 제공되는 파일처럼 링크하지 않는다.

- 먼저 기존 문서의 해당 절을 갱신한다. 별도의 독자·책임·독립적인 근거 보관 필요가 있을 때 새 파일을 만든다. 매 작업마다 계획·결과·인계 문서를 모두 만들지 않는다.
- 현행 문서의 앞부분에는 역할, 적용 범위, 확인 날짜 또는 커밋, 관련 구현·검증 근거를 간단히 둔다. 부분 점검이면 확인한 범위와 미확인 범위를 구분한다. 문구 정리 날짜를 전체 기능 재검증 날짜로 쓰지 않는다.
- 현재 설명을 본문에 반영한다. 상단 정정문이나 말미 예외를 계속 붙여 독자가 과거 본문과 합성하게 하지 않는다. 바뀐 판단의 근거가 필요하면 역사 기록에 남긴다.
- 구현·자동 검사·실제 조작/화면·실기기·배포를 구분한다. 한 단계의 통과로 다른 단계까지 완료로 표시하지 않는다. 본게임과 독립 개발 경로, 플랫폼이 다르면 상태를 따로 적는다.
- 현황에는 기능별 상태·남은 조건·근거를 적는다. 파일 목록, 상세 수치, 전체 테스트 개수, 로그는 해당 계약이나 검증 기록에 둔다.
- 날짜별 검증 기록은 당시 환경·대상 리비전·방법·결과·제한을 보존한다. 후속 변경으로 과거 결과를 현재 결과처럼 덮어쓰지 않는다. 잘못된 판단은 정정 사실과 후속 기준 링크를 남긴다.
- 긴 문서는 길이만으로 나누지 않는다. 독립적으로 변경되는 계약·운영 절차·역사 기록이 섞였을 때 분리하고, 개요에는 필요한 절로 바로 가는 링크를 둔다.

## 변경과 함께 갱신할 범위

| 변경 | 갱신할 원본 |
| --- | --- |
| 승인된 UI 방향 변경 | DESIGNS.md의 해당 결정과 관련 design/ 기준 |
| 기능·API·저장 계약 변경 | 해당 기능의 현행 본문; 전체 기능 범위가 달라질 때만 구현 현황 |
| Godot 이관 진척 | 로드맵의 해당 단계 상태·남은 조건 및 검증 근거 링크 |
| 백로그 완료 | 미완료 항목 제거 또는 결과 링크로 교체 |
| 배포 선행 조건 발생 / 배포 완료 | 배포 인계의 미배포 항목 / 검증 이력 |
| 도구·실행 절차 변경 | .agents의 해당 가이드; 진입 경로가 바뀌면 지도 |
| 문서 병합·이동·폐기 | 유입 링크·앵커와 대체 위치 안내 |

동작에 영향 없는 국소 리팩터링·포맷 변경에는 문서 갱신을 강제하지 않는다. 원본 한 곳의 상태 변경 때문에 지도·요약·인계의 동일 문단을 모두 고쳐야 한다면 복제를 줄인다.

## 병합·보관·삭제

1. 같은 독자와 목적의 짧은 안내는 기준 문서에 병합한다. 고유한 제약·실패 진단·완료 조건을 누락하지 않는다.
2. 완료된 인계, 대체된 설계, 긴 과거 구현 목록은 archive/에 보관한다. 현행 작업의 첫 진입점에서는 제외한다.
3. 이동 전 저장소의 유입 링크와 앵커를 검색한다. 알려진 참조를 고치고, 기존 경로가 사용될 수 있으면 짧은 안내를 남긴다. 안내 문서에는 현황을 새로 복제하지 않는다.
4. 고유한 근거·결정·참조가 없고 내용이 대체 문서에 보존된 중복 문서는 삭제할 수 있다. 실행 코드·에셋·저장 데이터 정리는 문서 정리에 포함하지 않는다.

## 완료 확인

- 현재 작업에서 바꾼 diff와 이동 전 내용을 비교해 고유한 계약·제약·근거가 보존됐는지 확인한다. 기존 미커밋 변경은 유지한다.
- 수정 문서의 상대 링크·앵커, 이동 문서의 유입 참조를 확인한다. 이미 없는 과거 산출물은 새로 검증한 근거처럼 표시하지 않는다.
- 같은 기능의 완료·미완료 표현, 다음 작업, 실행 경로가 충돌하지 않는지 해당 원본과 요약을 대조한다.
- 문서만 수정했다면 게임 빌드·Flutter 검사·시각 검증을 추가하지 않는다. 검증하지 않은 기능을 문서 정리만으로 완료 처리하지 않는다.
