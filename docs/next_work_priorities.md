# Rune Nexus 다음 작업 우선순위

마지막 정리 기준: 2026-05-05 로컬 `main` 브랜치.

## 목적

이 문서는 새 세션에서도 현재 프로젝트의 다음 작업 후보와 우선순위를 빠르게 이어받기 위한 기준 문서다.

현재 Rune Nexus는 기본 MVP 구현을 넘어선 상태다. 전투, 젬, 링크, 저장, 스테이지 선택, 결과 화면, 영구 업그레이드 기초가 이미 동작한다. 따라서 이후 작업은 단순 기능 추가보다 "시연 가능한 MVP로 정리하는 것"에 초점을 둔다.

## 현재 판단

가장 중요한 목표는 한 판을 끝낸 뒤 다음 판을 다시 하고 싶게 만드는 루프를 강화하는 것이다.

현재 약한 지점은 다음과 같다.

- 결과 화면에서 신기록, 신규 해금, 획득 룬, 다음 행동의 의미가 충분히 강조되지 않는다.
- 릴리즈 또는 공유 빌드에서도 디버그 라운드/골드/젬 기능이 노출될 수 있다.
- 스테이지 1~5 해금 구조는 있지만, 현재는 같은 맵과 같은 웨이브를 사용해 다음 스테이지를 진행할 이유가 약하다.
- 영구 업그레이드는 시작 골드와 넥서스 HP만 있어 장기 성장 선택지가 아직 얕다.
- `RuneNexusGame`이 입력, 전투, 저장, 선택 상태, 진행 정산, 일부 렌더링 보조를 함께 담당해 장기적으로 커질 위험이 있다.

## 권장 우선순위

### 1. 결과/정산 루프 고도화

가장 먼저 추천하는 작업이다.

작업 후보:

- 결과 화면에서 신기록 여부 강조
- 신규 스테이지 해금 강조
- 획득 룬과 누적 룬의 변화 강조
- 다음 추천 행동을 더 명확히 배치
- 스테이지 선택 화면에 결과 반영이 잘 드러나는지 확인

이유:

- MVP의 끝 경험이다.
- 전투가 재미있어도 결과 화면이 밋밋하면 성장 루프가 약하게 느껴진다.
- 이후 스테이지 차별화나 영구 업그레이드 확장 작업과 자연스럽게 연결된다.

관련 파일:

- `lib/ui/menu/result_overlay.dart`
- `lib/game/systems/run_progression.dart`
- `lib/ui/menu/main_menu_screen.dart`
- `test/widget_test.dart`
- `test/game_balance_test.dart`

### 2. 릴리즈용 디버그 UI 차단

작업 후보:

- 상단 바의 디버그 젬 버튼 노출 조건 추가
- 디버그 라운드/골드/젬 패널을 디버그 빌드에서만 표시
- 테스트에서는 기존 디버그 메서드를 계속 사용할 수 있게 유지

이유:

- 작업량은 작고 효과가 크다.
- 시연/공유 빌드에서 치트 패널이 보이면 MVP 신뢰도가 크게 떨어진다.
- 전투 루프나 데이터 구조를 건드리지 않아 위험도가 낮다.

관련 파일:

- `lib/ui/hud/top_bar.dart`
- `lib/game/rune_nexus_game.dart`
- `test/game_balance_test.dart`

### 3. 스테이지 2~5 차별화

작업 후보:

- 스테이지별 웨이브 난이도 배율 추가
- 스테이지별 시작 골드, 보상, 적 구성 차이 추가
- 가능하면 최소 1~2개의 다른 맵 패턴 추가
- 스테이지 카드에 차별점을 짧게 표시

이유:

- 현재 해금 구조는 있지만 다음 스테이지를 진행할 실제 이유가 약하다.
- MVP 관점에서 진행감과 목표감을 만드는 핵심 작업이다.
- 결과 화면의 신규 해금 강조 작업 이후에 진행하면 효과가 더 잘 드러난다.

관련 파일:

- `lib/data/definitions/demo_stage_data.dart`
- `lib/domain/stage/stage_definition.dart`
- `lib/ui/menu/main_menu_screen.dart`
- `test/game_balance_test.dart`

### 4. 영구 업그레이드 1차 확장

작업 후보:

- 첫 링크 확장 비용 감소
- 특정 포탑 비용 감소
- 보상 룬 증가
- 첫 젬 보상 개선
- 시작 시 랜덤 젬 1개 지급

이유:

- 실패 후 다음 판의 선택을 바꾸게 만드는 메타 성장 축이 필요하다.
- 현재 시작 골드와 넥서스 HP만으로는 성장 선택이 단순하다.
- 스테이지 차별화와 함께 붙이면 반복 플레이 명분이 강해진다.

관련 파일:

- `lib/game/systems/run_progression.dart`
- `lib/ui/menu/main_menu_screen.dart`
- `lib/data/save/game_save_data.dart`
- `test/game_balance_test.dart`

### 5. `RuneNexusGame` 책임 분리 리팩토링

작업 후보:

- 선택 상태와 입력 처리를 별도 협력 객체로 분리
- 런 정산과 진행 기록 처리를 `RunProgression` 쪽으로 더 모으기
- 저장/복구 변환 로직을 별도 모듈로 분리
- 전투 처리와 렌더링 보조 메서드 경계를 정리

이유:

- `lib/game/rune_nexus_game.dart`가 약 1,500줄 규모로 커져 있다.
- 지금 구조로도 동작하지만, 콘텐츠가 늘면 변경 충돌과 회귀 위험이 커진다.
- 다만 지금 즉시 대규모 분리는 비추천이다. 결과/디버그/스테이지 작업을 거친 뒤 변경이 잦은 책임 경계가 더 선명해졌을 때 작게 나누는 편이 안전하다.

관련 파일:

- `lib/game/rune_nexus_game.dart`
- `lib/game/game_snapshot.dart`
- `lib/game/systems/`
- `test/game_balance_test.dart`

## 추천 실행 순서

1. 결과 화면의 신기록/신규 해금 강조
2. 디버그 UI 릴리즈 차단
3. 스테이지 2~5 차별화
4. 영구 업그레이드 1차 확장
5. `RuneNexusGame` 책임 분리 리팩토링

## 보류 기준

다음 작업은 당장 우선순위를 낮춘다.

- 고급 픽셀 아트 교체
- 사운드/효과음
- 온라인 저장 실제 연동
- 대규모 저장 포맷 변경
- 포탑/젬/적 종류 대량 추가
- 앱 패키지 배포 자동화

이 작업들은 MVP 루프의 판단 근거가 더 명확해진 뒤 진행하는 것이 낫다.
