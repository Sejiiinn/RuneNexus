# 배포 상태와 세션 간 인계

배포 요청을 처리할 때 이 문서와 [운영 배포 절차](self_hosted_api_deployment.md)를 먼저 확인한다.
이 문서는 마지막으로 검증한 이력이며 실시간 운영 상태가 아니다. 배포 직전 실제 DB 버전,
실행 중인 API 이미지, 공개 웹 커밋, 최신 APK release를 다시 확인한다.

  백업과 비밀 설정은 Git에 넣지 않는다.

## 이번 배포 변경

- 보상 젬을 전장에서 직접 장착하고, 만석 포탑에서는 기존 젬을 보관하며 교체한다.
- 모바일 장착 화면, 중앙 교체 모달, 젬 주효과와 공통 공격 규칙 안내를 개선했다.
- 글로벌 폭발·연쇄·효과 범위 규칙, 메인 로비 화면 고정, 진행 중 클리어 기록의 리더보드 반영을 포함한다.
- 젬 UI 변경에는 저장 형식 변경이나 추가 migration이 없다. 리더보드 변경에 필요한 010은
  새 API 시작 전에 적용했다.

## 검증 범위와 복구 참고

- Flutter 전체 테스트 663개 통과, 기존 skip 10개. 서버 단위 테스트와 복원 DB 통합 테스트 통과.
- 모바일 장착·교체·보관 UI는 실제 Flutter 게임 렌더와 터치 테스트로 검증했다.
- 운영 계정으로 실제 기기 Google 로그인·진행 저장을 수행한 검증은 이번 자동 배포에 포함하지 않았다.
- API는 배포 커밋에서 추출한 서버 소스로 빌드했다. 이전 이미지 `rune-nexus-api:8ccb32b`를 유지한다.
- 010은 기존 기록을 보존한다. 저장 출처 기록이 생긴 뒤에는 010 down이 거부되므로 기록을 삭제해
  down을 강제하지 않는다. API 롤백과 DB down은 별도로 판단하고 확장된 스키마 유지를 우선한다.

## 기록 유지 규칙

- 배포가 필요한 코드 변경에는 필요한 migration·환경 설정·선행 조건을 이 문서에 함께 기록한다.
- 배포 후 검증된 커밋, DB 버전, workflow/release, 검증 결과를 갱신하고 미배포 항목을 정리한다.
- 실패·부분 완료는 구성 요소별로 기록한다. 과거 대화나 로컬 작업 기록만으로 완료를 판단하지 않는다.
- 비밀번호, 토큰, 암호화 키, DB 백업 내용은 이 문서나 커밋에 넣지 않는다.
