# 배포 상태와 세션 간 인계

배포 요청을 처리할 때 이 문서와 [운영 배포 절차](self_hosted_api_deployment.md)를 먼저 확인한다.
이 문서는 마지막으로 검증한 이력이며 실시간 운영 상태가 아니다. 배포 직전 실제 DB 버전,
실행 중인 API 이미지, 공개 웹 커밋, 최신 APK release를 다시 확인한다.

## 이번 배포 변경

- 다중 투사체 젬과 젬 14종 전용 이미지 적용. 급소 +30%p, 조준경 75% 증폭 조정.
- 게임 효과의 증가·증폭·감폭 용어와 저항 변화량 %p, 중첩·보스 조건 설명 정리.
- 냉각 치명타 판정·피해 적용 수정. 서로 다른 둔화 강도의 남은 시간은 독립적으로 처리.
- 냉각 둔화는 1레벨 20%에서 레벨당 +2%p, 10레벨 38%로 성장한다.
  급속 냉각은 +8%p이며 기본 지속시간 1초는 유지한다.
- 모듈 둔화 강도 범위는 일반 1~2, 매직 3~4, 레어 5~6, 유니크 6~8%p.
  서버 카탈로그 버전은 2이며 기존 정상 둔화 옵션의 초기 이관 시 모듈·장착 상태를 보존한다.
- 스탯창은 현재 감속 강도와 다음 레벨 미리보기를 표시하며 지속시간 표기는 생략한다.
- 추가 DB migration·환경값 변경 없음. API 환경값과 인증 영수증 암호화 키의 동일성을
  교체 전후 확인했다. API 내 정리 worker도 같은 이미지로 교체했다.

## 검증 범위와 복구 참고

- 웹·APK CI의 Flutter 정적 분석·전체 테스트 통과. 서버 전체 단위 테스트·go vet 통과.
- 백업 전체 복원은 성공했다. 운영 데이터가 포함된 복원 DB에서는 순위 테스트의 고정
  순위 기대값과 실제 계정이 겹쳤다. 동일 스키마와 필수 초기값을 복원한 독립 DB에서
  전체 통합 테스트를 통과했으며, 이를 위해 운영 데이터나 테스트 코드는 변경하지 않았다.
- APK CI에서 기존 서명 동일성과 Android 패치 디코더, 최근 3개 버전용 차등 패치의
  Python·Kotlin 복원 검증 및 임시 서명 파일 정리를 통과했다.
- 변경 UI는 관련 위젯 테스트와 320px 테스트 렌더로 확인했다. Mac 잠금으로 실제 앱
  화면 확인은 제한됐다. 운영 계정의 실제 기기 로그인·저장·APK 설치 검증은 포함하지 않았다.
- 구 저장의 단일 둔화 정보는 복원하지 않고 해제한다. 적 체력·진행 상태는 보존되며
  구 저장 로드의 예외 없는 복원과 새 둔화 목록의 저장·복원을 테스트했다.
- 이전 API 이미지 `rune-nexus-api:6c5529e`를 유지한다. API 롤백과 DB down은 별개이며
  이번 배포에는 DB down이 필요하지 않다. 구 클라이언트와 신규 클라이언트의 둔화·모듈
  수치 차이가 있으므로 클라이언트 롤백 시에는 밸런스와 저장 효과 차이를 함께 확인한다.

## 미배포 항목

이번 요청 범위의 미배포 코드 변경 없음. 배포 기록 문서 커밋은 실행 산출물을 바꾸지 않는다.

## 기록 유지 규칙

- 배포가 필요한 코드 변경에는 필요한 migration·환경 설정·선행 조건을 이 문서에 함께 기록한다.
- 배포 후 검증된 커밋, DB 버전, workflow/release, 검증 결과를 갱신하고 미배포 항목을 정리한다.
- 실패·부분 완료는 구성 요소별로 기록한다. 과거 대화나 로컬 작업 기록만으로 완료를 판단하지 않는다.
- 비밀번호, 토큰, 암호화 키, DB 백업 내용은 이 문서나 커밋에 넣지 않는다.
