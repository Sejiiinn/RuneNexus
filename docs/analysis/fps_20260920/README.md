# Android 표시 FPS 측정 — 2026-09-20

현재 웨이브·코어 주기를 Godot으로 이관한 작업 트리를 측정했다. 성능 개선 구현이나 이전 버전과의 A/B 비교는 하지 않았다.

## 조건과 방법

- Android 17 ARM64 에뮬레이터 `sdk_gphone64_arm64`, 화면 1080×2424, 주사율 60Hz.
- 일반 `lib/main.dart` profile APK 0.1.19+6027. API·업데이트 주소·디버그 패널을 켜지 않았다.
- 스테이지 1, 23웨이브, 드론 시점. 포탑: 대포 레벨1 6개·마법 레벨4 1개·화살 레벨1 1개. 기본 MSAA 2×·그림자 2048, 기존 저장 사용.
- 3D 초기화 후 약 49초가 지난 준비 상태부터 측정. 이어서 1배속 시작 후 2초, 4배속 변경 후 2초를 제외하고 기록했다. 같은 웨이브의 연속 구간이므로 적 배치와 효과 부하는 서로 다르다. 4배속의 첫 구간에 셰이더 워밍업 효과 등이 섞일 수 있어 배속 성능 우열로 해석하지 않는다.
- Android SurfaceFlinger `--latency`로 Godot SurfaceView의 실제 표시 시각을 약 0.7초마다 수집하고 중복을 제거했다. 준비 화면에 먼저 생성된 Flutter SurfaceView는 표시 시각을 제공하지 않았으며 Godot 레이어 `#7315`가 표본을 제공했다. Flutter HUD FPS·Godot 내부 엔진 FPS·CPU/GPU 시간은 별도 측정하지 않았다.
- FPS = 프레임 간격 개수 × 1,000 / 간격 합(ms). p95/p99는 모든 원시 간격의 nearest-rank. Android 합성 전체와 개별 Godot 표면의 FPS를 혼동하지 않도록 TimeStats 전체값은 참고 원본으로만 남겼다.
- 화면 녹화·캡처 및 동시 빌드는 하지 않았다. 4배속 측정에 포함된 완료 후 준비 프레임은 같은 monotonic 시계의 `NATIVE_WAVE_COMPLETED` 시각으로 제거했다. 별도 전투 재실행은 하지 않았다.

## 결과

| 조건 | 유효 시간 | 표시 프레임 수 | 평균 FPS | p95 간격 | p99 간격 | 최대 간격 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 준비 화면 | 9.63초 | 577 | 59.81 | 20.01ms | 21.51ms | 33.51ms |
| 1배속 전투 | 11.95초 | 587 | 49.03 | 34.73ms | 49.74ms | 190.75ms |
| 4배속 전투 | 3.30초 | 166 | 50.01 | 34.29ms | 35.40ms | 64.53ms |

준비 화면은 약 60 FPS, 이번 전투 표본은 약 49~50 FPS였다. 1배속에서는 50ms 초과 간격이 5개, 최대 약 191ms로 순간 지연이 관찰됐다. 4배속은 완료 전 **3.30초의 짧은 구간**만 남아 참고값이며 지속 성능 판단에는 부족하다. 두 배속의 서로 다른 적/효과 부하와 첫 전투의 영향을 분리하지 않았다.

이 결과는 에뮬레이터의 Godot 표면 표시율이다. 실기기 FPS·발열·지속 성능이나 이번 이관의 개선율을 뜻하지 않는다. CPU/GPU 병목 원인은 이 측정만으로 판정하지 않는다.

측정 후 이전 debug APK를 다시 설치하고 앱을 정지했다. 백업된 로컬 데이터 98개 파일은 바이트 단위 동일하게 복원했으며 추가 파일도 없다. 게임 소스·설정은 수정하지 않았다.
