# Godot 저장 호환 기반 — 2026-09-21

선행 1단계는 `dab5148` (`refactor: 전투 시계와 입력을 Godot 세션으로 이관`)로 커밋했다. 푸시는 하지 않았다. 이번 변경은 [Flutter 제거 로드맵](../../godot_unified_app_roadmap.md)의 **2단계 중 저장 호환 기반**이며, 2단계 전체 완료가 아니다.

## 구현

- 기존 Dart 저장 v2의 기본값·숫자 타입·null·enum·배열 순서·모듈 ID와 v1 이전을 Godot codec으로 구현했다.
- signed int64 JSON 정수가 기본 Godot JSON 처리에서 반올림되지 않도록 읽기 경로를 추가했다. 큰 정수·경계값·이스케이프 문자열·표식 충돌·잘못된 숫자를 검사했다.
- 기존 guest/account UUID 경로와 파일명, 원본/백업, 중단된 `.tmp`·`.replace` 복구, v1 가져오기, 충돌 백업, 쓰기 오류를 처리한다.
- 전투 체크포인트는 앱 소유 재화·성장·모듈 봉투를 보존한다. 미처리 이벤트가 남았거나 포탑 설정이 없으면 저장을 거절한다. coreDestruction은 failure로 기록하고 투사체 저장을 추가하지 않는다.
- 독립 Godot 개발 세션에 Save/Load를 연결했다. `user://standalone-session/` 아래 별도 개발 저장만 사용한다. 고정 개발 fixture가 지원하지 않는 포탑·성장·계정 런은 기존 장면과 저장을 유지한 채 거절한다.

## 추가 저장·타입 재검수

- 스테이지 기록 키를 Dart `int.tryParse`와 맞췄다. 부호 있는 16진수·유니코드 공백을 처리하고 범위를 벗어난 값이 최대 정수 키로 변환되는 문제를 수정했다. 별도 키 645개 대조에서 불일치가 없었다.
- 저장 직전 JSON 표현 가능 여부와 v2 정규화 후 값·타입 일치를 확인한다. NaN/Infinity·엔진 객체와 정수 필드의 문자열/불리언/실수를 거절하며 기존 파일 바이트·백업을 보존한다.
- 실제 Dart 기준 fixture를 91개로 확대했다. int64 양끝·2^53 초과 정수·작은 실수·ID·null 슬롯을 포함해 Godot 실제 파일 쓰기 → 새 저장소 읽기 → Dart 재읽기의 값과 숫자 타입을 비교한다. Godot끼리만 같은 방식으로 비교하는 데서 생길 수 있는 누락도 방지한다.
- 저장 관련 하네스 5개와 정적 분석을 통과했다. 서로 다른 Godot 프로세스의 개발 전투 저장·복원도 다시 통과했다. 실제 사용자 저장은 수정하지 않았다.

## 남은 범위

본게임의 저장 호출·런·성장·정적 콘텐츠는 아직 Dart가 담당한다. 이번에는 실제 사용자 저장을 읽거나 쓰지 않았다. Android 기존 설치 디렉터리 자동 인계와 실제 업그레이드 검증, 전체 콘텐츠로 전투 설정 복원, 성장·구매·젬·보상·연구 명령 소유권 이전이 남아 있다. 데스크톱 개발 fixture의 재시작 검증을 본게임 전체 저장 동등성으로 간주하지 않는다.

웹 localStorage/Web Locks 어댑터는 구현·문법 검사만 했고 실제 브라우저 다중 탭 검증은 미완료다. Windows 교체 fallback도 현지 OS 실행 검증이 남아 있다. 프로덕션 Android HUD·저장 경로를 바꾸지 않았으므로 새 APK 배포·실기기 성능 측정은 수행하지 않았다. 전체 Flutter/Dart 제거는 후속 단계다.
