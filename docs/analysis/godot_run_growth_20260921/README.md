# Godot 런·성장 명령 이관

역할: 2026-09-21 독립 Godot 앱 도메인의 구현·검증 기록. 앞선 [콘텐츠 이관](../godot_content_migration_20260921/README.md)에 이어 현재 작업 트리에서 검증했다. 커밋·푸시·배포하지 않았다.

## 완료 범위

- 실제 골드 차감으로 건설·레벨/링크 강화, 투자금 기준 판매 환급과 젬 반환.
- 젬 재고·null 슬롯·종류별 장착 제한, 1/2차 특성 비용·레벨 조건, 해금된 공격 우선순위.
- 런 업그레이드 비용·최대 레벨·연구 확장·효과, 전장 포탑/젬 종류 수에 반응하는 코어 패시브.
- 기존 progression 입력 기반 영구 강화(룬), 연구 시작·취소·경과시간·완료, 코어 배분·스킬 선택, 기존 보유 모듈 장착과 실제 전투 스탯 생성.
- 실제 처치 골드·보스 보너스·소수 골드 지갑, 웨이브 골드·조각, 5웨이브 젬 선택/젬 선택 구매·선택 후 재개. 다이아는 미정산 수량으로만 누적한다.
- 코어의 선택 스킬·성장·해당 라운드 일반 적 HP를 기존 Godot 코어 런타임에 연결. 일반 성장 갱신과 매 라운드 설정에서도 원래 타이머 계약을 보존한다.

`run_commands.gd`는 상태를 복사한 성공 결과와 전투 명령을 반환한다. 거절은 골드·재고·포탑을 변경하지 않는다. `run_session.gd`가 scene epoch/event ID별로 메모리 상태 반영 후 ACK하므로 재조회로 보상을 중복 지급하지 않는다. 기존 런타임은 강화 후 쿨다운·조준·피해 기록을 유지한다. 특성 선택만 Dart의 해당 연속 공격 상태 초기화를 명시적인 `resetTraitState`로 수행한다.

## 원본과 실행

원본은 Dart 정의·RunProgression·TurretActionController·RuneNexusGame이다. `tool/content/growth_export.dart`, `growth_game_fixture.dart`, `tool/godot_growth_core_export.dart`가 실행용 `godot/content/growth_content.json`과 테스트 fixture를 생성한다. 수동 수치 복제 없이 [재생성 안내](../../../tool/content/README.md)를 따른다. 런타임/준비는 Dart 없이 동작하며 재생성과 Dart 동등성 검증에는 SDK가 남아 있다.

Godot 기본 `--session`에서 실제 비용·해금 규칙으로 실행한다. 하단 개발 조작은 Level up/Sell/Add link, 젬 슬롯/장착·반환, 특성/런 업그레이드, 보상 선택·구매 및 일반 성장 구매를 제공한다. 연구·코어·모듈 전체 로비 UI는 아직 이관하지 않았으며 해당 명령은 앱 도메인 API로 제공한다. 단순 비용/강화 명령 이관을 전체 UI 이관으로 보고하지 않는다.

## 검증 결과

- `verify_run_commands.gd`: **4,800 checks**, 실패 없음. 실제 Dart 포탑 상태 명령 300개와 메모리 저장소를 사용한 실제 RuneNexusGame 건설·런 업그레이드 204개 사례를 비교했다. 기본/코어·모듈·연구 성장/골드 부족, 중복·단계·최대 조건, before/after 골드·슬롯·저장 포탑 상태와 전 레벨/발사 스탯을 포함한다. 신규 포탑 피해 통계 4개 초기값 누락을 발견해 수정했다. `run-commands.log` 참조.
- `verify_growth_rules.gd`: **3,729 assertions**, 실패 없음. Dart 실제 일반 성장 132개 상태, 연구 시간·취소·재개·슬롯 제한, 코어 연결성/초기화, 모듈 적용/상한, 실제 균열 낙인의 1/3회 발동과 성장 배율·라운드 설정/타이머 유지·해제 후 정지를 검사했다. `growth-rules.log` 참조.
- `verify_run_session.gd`: 실제 금액 건설·거절·강화·판매, 젬 장착/반환, 특성 상태 초기화, 일반 성장으로 실제 포탑 능력치 변경, 기본 코어 연결, 진행 중 젬 선택 구매→전투 정지→선택 후 재개, 실제 사격과 이벤트 중복 지급 방지 통과.
- `verify_content_session.gd`: 챕터별 실제 편성/보스·유료 건설·배속/정지와 저장 거절/기존 슬롯 보존 통과. 모든 종류를 확인하는 이 검사만 명시적 해금·테스트 예산을 제공하며 건설 비용은 차감한다.
- Flutter 저장/native regression/스탯/일반 성장/젬 회귀 **418개 통과**, analyze 문제 없음. Dart 새 생성물 검사도 재생성 없는 비교를 통과했다.
- 기존 `verify_standalone_session.gd`와 별도 write/read 프로세스 재시작 통과. 실제 콘텐츠 Save/Load의 명시적 거절을 유지했다.

대표 화면: `build/godot/captures/run-commands-combat.png`. macOS Godot 4.7.2, Apple M4 Metal Forward Mobile, 880×760 실제 독립 앱에서 포탑·전장과 비용/상태 조작을 확인했다. 시각 에셋은 변경하지 않았다. Android 본게임의 Flutter 경로는 아직 새 앱 도메인으로 교체하지 않았으며 Android HUD·설치·실기기 성능 완료 근거로 사용하지 않는다.

## 다음 작업과 제한

다음은 **본게임 저장·런 수명 연결**이다. 성장/런/전투를 v2로 투영하고 재시작 때 정확한 설정·보상 대기·실패·재시도를 복원해야 한다. 계정 보상 정산·퀘스트·미정산 이벤트 저장/재시도, 기존 설치 디렉터리 인계도 이어서 처리한다.

현재 로컬 도메인은 메모리 상태다. Save/Load는 ACK·파일 쓰기 전에 거절하며 실제 사용자 저장과 온라인 API를 사용하지 않는다. 스테이지 변경/종료는 검증 런을 버린다. 다이아·모듈 뽑기/분해 등 서버 권위 재화를 로컬 지급하지 않으며 서버 구매 명령을 거절한다. 전체 2단계·Flutter 제거·배포 완료가 아니다.
