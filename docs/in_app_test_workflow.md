## 실패 시에만 확인할 항목

- 접속 실패: 53000 실제 LISTEN 여부와 HTTP 응답, 실행 중인 터미널 출력을 확인한다. PID 파일만으로 서버가 살아 있다고 판단하지 않는다.
- 오래된 화면: 현재 URL·빌드·서버 종류를 확인한다. 정상 서버를 새 세션이라는 이유만으로 종료하거나 로그·PID 파일을 일괄 삭제하지 않는다.
- 포트 충돌: 대상 프로세스와 작업 소유권을 확인한 뒤 필요한 경우에만 해당 서버를 정리한다. 포트 점유 자체를 종료 사유로 삼지 않는다.
- SDK·옵션 오류: 스크립트의 실제 FLUTTER/DART 경로와 오류를 확인한다. 과거 로그의 옵션을 그대로 재사용하지 않는다.
- 캡처 실패: 페이지 동작 확인과 시각 검증을 구분한다. 같은 재시작 루프 대신 DESIGNS.md의 대안·중단 기준을 따른다.

완료 보고에는 기동·동작·화면 확인 중 실제 수행한 것만 적는다. 문서만 수정한 작업에는 서버를 띄우지 않는다.
