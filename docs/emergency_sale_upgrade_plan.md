# 긴급 매각 업그레이드 작업 계획

## 목표

경제 영구 업그레이드에 `긴급 매각`을 추가한다. 현재 포탑 환급률은 투자 골드의 75%이며, 이 업그레이드는 환급률을 소폭 높여 배치 실수 복구와 빌드 전환 비용을 낮추는 역할을 맡는다.

## 확정 사양

- 분류: 경제 영구 업그레이드
- 이름: 긴급 매각
- 기본 환급률: 75%
- 최대 레벨: 5
- 레벨당 효과: 환급률 +1%p
- 최종 환급률: 80%
- 추천 해금 조건: 스테이지 2 클리어
- 추천 비용: 처치 보상보다 약간 높은 `10 + 현재 레벨 * 6`

## 비목표

- 포탑 판매 시스템 자체를 재설계하지 않는다.
- 환급 대상 범위를 바꾸지 않는다. 기존처럼 설치 비용, 레벨업 비용, 링크 확장 비용을 포함한 투자 골드 기준을 유지한다.
- 장착 젬 반환 규칙을 바꾸지 않는다.
- 런 한정 업그레이드나 연구 탭으로 분리하지 않는다.

## 구현 방향

현재 환급률은 `TurretComponent.refundGold`에서 `investedGold * 75 ~/ 100`으로 계산된다. `긴급 매각`은 영구 진행도에 속하므로, 환급률 계산은 게임 진행도 값을 참조하도록 바꾼다.

추천 구조:

- `RunProgression`
  - `maxEmergencySaleUpgradeLevel = 5`
  - `emergencySaleUpgradeBaseCost = 10`
  - `emergencySaleUpgradeCostPerLevel = 6`
  - `emergencySaleRefundPercentPerLevel = 1`
  - `emergencySaleUpgradeLevel`
  - `turretRefundPercent = 75 + emergencySaleUpgradeLevel`
  - 구매 가능 여부와 구매 메서드 추가

- `RuneNexusGame`
  - `upgradeEmergencySaleProgression()` 추가
  - 스테이지 2 클리어 전 구매 차단
  - `turretRefundPercent` 또는 `turretRefundRate`를 포탑 계산에서 사용할 수 있게 노출
  - 스냅샷에 레벨, 비용, 구매 가능 여부, 현재 환급률 추가

- `TurretComponent`
  - 고정 75% 대신 게임의 현재 환급률을 사용
  - 정수 골드 환급은 기존처럼 내림 처리 유지

- 저장 데이터
  - `SavedProgression`에 `emergencySaleUpgradeLevel` 추가
  - 기존 저장 데이터는 필드가 없으면 0으로 복원
  - 복원 시 최대 레벨 5로 clamp

- 메뉴 UI
  - 경제 업그레이드 보드에 카드 추가
  - 스테이지 2 미클리어 시 `미해금 업그레이드` 카드로 표시
  - 표시값 예:
    - 현재 `75%`
    - 다음 `76%`
  - 이미 저장된 레벨이 있더라도 스테이지 2 미클리어 상태면 잠금 표시와 효과 미적용을 우선한다. 처치 보상에서 발생했던 예외를 반복하지 않는다.

## 테스트 계획

- `RunProgression`
  - 최대 레벨 5까지만 구매된다.
  - 비용이 `10, 16, 22, 28, 34` 순서로 증가한다.
  - Lv.5에서 환급률이 80%가 된다.

- 게임 밸런스 테스트
  - 스테이지 2 미클리어 상태에서는 구매되지 않는다.
  - 스테이지 2 클리어 후 구매 가능해진다.
  - 포탑 판매 환급 골드가 75%에서 레벨에 따라 76~80%로 증가한다.
  - 저장/복원 후 레벨과 환급률이 유지된다.

- 위젯 테스트
  - 경제 탭에 `긴급 매각` 카드가 표시된다.
  - 스테이지 2 미클리어 시 잠금 카드로 표시된다.
  - 저장된 레벨이 있어도 스테이지 2 미클리어라면 잠금 카드로 표시된다.
  - 스테이지 2 클리어 후 `현재 75%`, `다음 76%` 형태의 성장 카드로 표시된다.

## 주의점

- 환급률 100%에 가까워지면 판매 페널티가 사라져 배치 전환 비용이 무의미해진다. 이번 사양은 최대 80%라 비교적 안전하지만, 이후 상위 티어를 추가하더라도 85% 이상은 신중히 검토한다.
- 포탑 판매는 라운드 중에도 가능하므로, 환급률 증가는 방어 중 임시 배치와 빠른 빌드 전환에 직접 영향을 준다.
- 환급률 표시와 실제 계산이 다르면 신뢰가 깨지므로 UI 표시값은 `RunProgression`의 단일 계산값을 사용한다.
