# Rune Nexus 개발 계획

역할: 사용자가 앞으로 하고 싶은 작업을 큰 단위로 기록하는 개발 계획. 정리: 2026-10-10 KST.
구현 담당자가 마무리해야 할 버그·검증·배포 조건은 [구현·검증 체크리스트](implementation_checklist.md)에 둔다. 두 목록의 목적과 우선순위를 섞지 않는다.

## 기록 기준

- 기능·콘텐츠·성장 체계 등 사용자가 만들거나 바꾸고 싶은 큰 작업을 기록한다. 구현 파일, 테스트 명령, 배포 절차 같은 세부 작업으로 목록을 채우지 않는다.
- 확정 계획과 검토 중인 아이디어를 나누고, 계획에 등록했다는 이유만으로 구현에 착수하지 않는다.
- 우선순위·범위·일정은 사용자가 정한 내용만 적는다. 아직 정하지 않은 부분은 미정으로 남긴다.
- 구체화할 때는 작업명, 하고 싶은 변화, 결정 상태와 관련 설계를 간단히 남긴다. 세부 구현·검증 조건은 해당 설계와 구현 체크리스트에서 관리한다.
- 완료한 계획은 결과가 있는 기능·설계·배포 문서로 연결하고 현재 계획에서 정리한다. 오래된 제안을 확인 없이 다시 계획에 넣지 않는다.

## 확정된 개발 계획

아직 등록된 항목 없음.

## 검토 중인 아이디어

### 마법·희귀 몬스터 옵션 시스템

- 방향: PoE처럼 마법·희귀 몬스터에 추가 옵션을 붙여 전투에 변화를 주는 시스템.
- 논의한 안: 이동 속도 +25%, HP +50% 같은 옵션을 사용하고, 마법 몬스터는 최대 2개, 희귀 몬스터는 3개 이상 옵션을 갖는다.
- 먼저 고정 라운드에 정해진 개체 수를 배치하는 방식을 검토한다. 예시는 한 라운드 20마리 중 2~5마리다. 이후 고난도에서는 출현 비율과 보상을 함께 늘리는 방향이다.
- 아직 검토 중이며, 적용 범위·우선순위·일정은 미정이다.
