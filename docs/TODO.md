# Rune Nexus 개발 계획

역할: 사용자가 앞으로 하고 싶은 작업을 큰 단위로 기록하는 개발 계획. 정리: 2026-10-10 KST.
구현 담당자가 마무리해야 할 버그·검증·배포 조건은 [구현·검증 체크리스트](implementation_checklist.md)에 둔다. 두 목록의 목적과 우선순위를 섞지 않는다.

## 기록 기준

- 기능·콘텐츠·성장 체계 등 사용자가 만들거나 바꾸고 싶은 큰 작업을 기록한다. 구현 파일, 테스트 명령, 배포 절차 같은 세부 작업으로 목록을 채우지 않는다.
- 확정 계획과 검토 중인 아이디어를 나누고, 계획에 등록했다는 이유만으로 구현에 착수하지 않는다.
- 우선순위·범위·일정은 사용자가 정한 내용만 적는다. 아직 정하지 않은 부분은 미정으로 남긴다.
- 구체화할 때는 작업명, 하고 싶은 변화, 결정 상태와 관련 설계를 간단히 남긴다. 세부 구현·검증 조건은 해당 설계와 구현 체크리스트에서 관리한다.
- 완료한 계획은 결과가 있는 기능·설계·배포 문서로 연결하고 현재 계획에서 정리한다. 오래된 제안을 확인 없이 다시 계획에 넣지 않는다.

## 확정된 개발 계획

## 검토 중인 아이디어

### 고난도 설정

- 방향: 더 어려운 난이도를 선택하면 일반 몹이 일정 확률로 마법·희귀 몬스터로 승급하고, 승급한 몹에 무작위 옵션이 붙는다.
- 기본 설정의 고정 배치는 [마법·희귀 몬스터 설계](enemy_rarity_design.md)에 구현되어 있다. 고난도의 확률·보상·옵션 추첨 방식과 우선순위·일정은 미정이다.

### 포탑 컬렉션·덱 슬롯·지원 구조물

- 문제의식: 스테이지마다 적 내구도는 계단식으로 오르는데, 플레이어 성장은 강화·연구의 반복 수치에 기대고 있어 반복해서 키우는 느낌이 강하다. 챕터 3에는 새 포탑 해금이 없다. 수치 축을 더 늘리지 않고, 스테이지마다 새 선택지가 생기는 성장 계위를 추가하려 한다.
- 포탑 컬렉션과 덱: 스테이지를 진행하면 기본 포탑 계열이 해금되고, 최종적으로는 포탑 뽑기로 여러 포탑을 모은다. 좋아하는 포탑으로 최대 6~8개의 덱을 꾸려 스테이지에 입장한다.
- 지원 구조물(강화 코어): 맵에 설치하면 주변 포탑을 강화하는 구조물을 둔다.
- 사용자가 정한 방향:
  - 스테이지 해금 포탑 목록과 포탑 뽑기 풀을 따로 둔다. 진행 순서는 스테이지 해금 포탑을 먼저 갖추고, 뽑기는 그 뒤의 계획으로만 둔다.
  - 높은 등급이 무조건 좋은 것은 아니다. 높은 등급은 낮은 등급보다 골드 대비 효율이 낮은 대신 타일 하나당 성능이 높다. [장기 성장 방향](long_term_progression_direction.md)의 '기본 포탑은 가격 효율, 상위 포탑은 슬롯 효율'과 같은 원칙이다.
  - 전설 등급도 조각으로 교환할 수 있되, 교환 비용을 높게 책정한다.
- 검토 중인 안:
  - 스테이지 클리어 보상으로 덱 슬롯을 단계적으로 늘린다.
  - 지원 구조물은 포탑 덱과 슬롯을 따로 둔다.
  - 입장 전에 해당 스테이지의 적 구성을 보여 준다.
- 뽑기 풀에 대해 검토 중인 안:
  - 모듈 뽑기처럼 계열을 지정해 뽑는다. 뽑기권은 모듈권·다이아와 분리하고, 최초 클리어 보상으로 꾸준히 지급한다.
  - 중복 획득분은 공용 조각으로 바꾼다. 조각으로 포탑을 교환하고, 아끼는 포탑의 특성 후보도 해금한다. 런 안에서 쓰는 젬 파편과 헷갈리지 않게 다른 이름(예: 설계도)을 쓴다.
  - 해금하는 특성 후보는 상위호환이 아닌 사이드그레이드로 둔다.
  - 전설 확정 천장과 덱 안 개수 제한은 골드 효율로 균형이 맞는지 본 뒤 필요 여부를 정한다.
  - 중복 획득으로 포탑별 스킬포인트를 주는 방식은 쓰지 않는다. 테스터가 모듈로 강화한 포탑만 쓰게 된다고 지적한 것과 같은 쏠림이 생기기 때문이다.
  - 계정 투자는 덱이나 계정 전체에 주고, 포탑 하나에는 선택지만 준다.
  - 확률 정보 공개 의무를 따르고, 뽑기 결과·조각·천장 카운트는 서버 원장에서 처리한다.
- 함께 정할 쟁점:
  - 포탑이 늘어날 때 포탑별 [모듈](turret_module_design.md) 뽑기가 희석되고 쏠림이 커지는 문제. 계열 단위 장착이나 포탑 간 자유 이동을 검토한다.
  - 보유 포탑을 서버 권위로 관리하는 방식
  - 뽑기권 지급량, 조각 교환 비용, 특성 후보 수, 전설 천장 횟수
  - 구조물 버프가 들어갈 피해 계층
  - 기존 [성장·해금 배분](../design/stage_expansion_progression/README.md)과의 관계
  - 과거 상위 포탑 구상은 [장기 성장 방향](long_term_progression_direction.md)에 있다.
- 결정 상태: 위 '사용자가 정한 방향'만 정했다. 나머지 안의 채택 여부·범위·덱 크기·해금 시점·수치·우선순위·일정은 미정이다. 구현에는 착수하지 않는다.

### 독 포탑·속성 부여 젬

- 방향: 독 포탑을 추가한다. 물리 포탑의 피해를 화염·냉기·독으로 바꾸는 속성 부여 젬을 추가한다. 화상·독·감속의 공통 규칙을 함께 정리한다.
- 정한 규칙과 시작 수치는 [독·속성 부여 설계](poison_elemental_infusion_design.md)에 있다.
- 결정 상태: 규칙과 시작 수치를 정했다. 화상의 포탑별 합산, 지속피해 방어구 비율, 독의 포탑별 중첩 구조, 보스 둔화 저항, 독 포탑의 전투(독 장판 박격포)·연출·게임 모델은 구현했다. 기본형은 빠른 장판형, 피해 계열은 독으로 정했고 착탄 독 1중첩과 1·2차 특성 4종, 2-8 해금·건설 UI·특성 아이콘·저장(세대 13)과 독 피해 증폭 젬까지 구현했다. 부여 젬 해금 시점·이름, 나머지 구현 순서·우선순위·일정은 미정이다.
