# 계정 닉네임 정책

## 이름과 태그

- 로그인한 계정은 최초 1회 닉네임을 직접 설정한다. Google 이름이나 임의 이름을 자동으로 사용하지 않는다.
- 허용 문자는 한글 완성형(`가`~`힣`), 영문 대소문자, 숫자, 밑줄이다.
- 앞뒤 공백은 제거하고 내부 공백은 허용하지 않는다.
- 최소 길이는 실제 문자 2자다. 최대 길이는 한글 2칸, 영문·숫자·밑줄 1칸으로 합계 16칸이다.
  - 한글만 입력하면 최대 8자, 영문만 입력하면 최대 16자다.
  - 한글 4자와 영문 8자를 함께 사용할 수 있다.
- 모든 계정에 서버가 랜덤 숫자 태그 `0000`~`9999`를 부여한다. 태그는 직접 입력하지 않으며 닉네임 길이 계산에서 제외한다.
- 계정 이름은 항상 `룬마스터#0382`와 같이 닉네임과 태그를 함께 표시한다.
- 닉네임 자체는 중복을 허용하되 `닉네임 + 태그` 조합은 중복될 수 없다. 영문 대소문자는 구분한다.
- 서로 다른 닉네임은 같은 태그를 사용할 수 있다. 동일 닉네임의 태그 10,000개가 모두 사용되면 다른 닉네임을 선택하도록 안내한다.
- 닉네임과 태그는 최초 설정 후 고정한다. 다른 기기에서 로그인하거나 요청을 재전송해도 바뀌지 않는다. 닉네임 변경 기능은 이번 범위에 포함하지 않는다.

## 로그인 흐름

1. Google 인증 또는 기존 세션 복원을 완료한다.
2. 서버의 본인 계정 프로필을 확인한다.
3. 닉네임이 없으면 필수 설정 화면을 표시한다. 뒤로가기나 바깥 영역 클릭으로 건너뛸 수 없다.
4. 서버에서 닉네임·태그 저장을 확정한 뒤 계정 저장 데이터, 경제 정보, 기존 진행 가져오기를 연결한다.

프로필 조회 실패 시 재시도 또는 로그아웃을 선택한다. 닉네임 저장 실패 시 입력값을 유지한다. 다른 기기에서 먼저 설정한 경우 서버의 확정된 프로필을 다시 조회한다. 로그아웃하면 게스트 흐름으로 돌아가며, 이전 세션의 늦은 응답은 적용하지 않는다.

## 서버 계약과 데이터 보존

| 요청 | 동작 |
| --- | --- |
| `GET /v1/account/profile` | 인증 토큰의 계정에 대한 `{accountId, nickname, tag}` 반환 |
| `PUT /v1/account/nickname` | `{nickname}`으로 최초 설정, 확정된 프로필 반환 |

미설정 프로필의 `nickname`, `tag`는 모두 `null`이다. 동일 닉네임 설정을 재요청하면 기존 태그를 반환한다. 이미 설정된 계정에 다른 닉네임을 지정하면 `NICKNAME_ALREADY_SET`을 반환한다.

서버는 닉네임 미설정 계정의 저장·경제·보상·진행 가져오기 API를 `NICKNAME_REQUIRED`로 차단한다. 프로필 조회, 닉네임 설정, 인증 세션 갱신과 로그아웃은 허용한다. 게스트 플레이와 기존 게스트 이전 링크 생성은 유지한다.

닉네임은 서버 계정 정보이며 게임 세이브에 넣지 않는다. 기존 계정 ID와 진행 데이터, 로컬 저장 슬롯, 대기 중인 저장 요청을 보존한다. 기존 계정은 다음 로그인 또는 자동 복원 시 최초 설정을 진행한다.

## 배포 시 주의

DB 마이그레이션과 대응 서버·클라이언트가 모두 필요하다. 구버전 클라이언트에는 설정 화면이 없으므로 서버 필수 검사를 적용하는 배포 시점에 대응 클라이언트 업데이트를 제공해야 한다. 코드 반영만으로 운영 DB나 배포 서버가 변경되지는 않는다.
