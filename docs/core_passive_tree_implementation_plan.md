# 코어 패시브 트리 현행 참조

역할: 코어 트리의 투자·효과·런 고정·저장 이관 계약. 2026-10-13 확장 구현 기준이다. 운영 API·APK 배포 사실은 [배포 인계](deployment_status.md)를 따른다. 과거 초기 계획은 [역사 기록](archive/core_passive_tree_plan_2026-07-20.md)에 보존한다.

## 카탈로그와 투자

- 현재 `corePassiveTreeRevision`은 5다. 구매 가능한 노드 60개와 구매 대상이 아닌 중앙 `CORE`, 연결 89개, 독립 순환 29개, 시작 노드 `S1`~`S6`를 사용한다. 승인 원본의 좌표·연결·노드별 최대 랭크를 유지한다.
- [v5 원본](../godot/content/source/core_passive_tree_v5.json)이 이름·좌표·증분 비용·랭크별 총 효과의 원본이다. [생성기](../scripts/compile_core_passive_tree.py)가 `growth_content.json`의 `core`와 Godot·Go의 동일한 검증 레지스트리를 만든다. 생성된 영역은 직접 편집하지 않는다.
- 비용 배열의 각 항목은 다음 한 랭크를 사는 추가 비용이다. 예를 들어 소형 3랭크는 `1+1+2=4P`, 5랭크는 `9P`다. 중형 3랭크는 `2+3+5=10P`, 핵심 1랭크는 `5P`다.
- 시작 노드는 즉시 투자 가능하다. 그 외 노드는 **시작점에서 도달 가능한 인접 비종단 노드 중 하나**가 3랭크 이상이면 열린다. 여러 이웃을 전부 요구하지 않는다. 연결되지 않은 순환은 스스로 열리지 않으며, 핵심 노드는 종단이므로 다른 노드를 여는 경로로 전파되지 않는다.
- 사용 가능 포인트는 저장된 실제 `totalCorePoints`에서 투자한 증분 비용 합계를 뺀다. 60P를 저장 상한으로 사용하지 않는다.
- 단일 환급으로 투자된 다른 노드가 단절되면 그 변경을 거부한다. UI가 영향을 받을 노드를 보여 주고 별도로 확인받은 묶음 환급 또는 무료 전체 초기화를 사용한다. 환급 재화나 초기화 비용을 추가하지 않는다.

## 포인트 보상

모든 스테이지 최초 클리어 보상은 2P이며, 현재 30개 스테이지의 자연 획득 합계는 60P다. 반복 클리어는 다시 지급하지 않는다. 기존 실제 포인트와 보상 수령 기록을 보존하며 차액을 소급 지급하거나 회수하지 않는다. 원본은 [스테이지 정의](../godot/content/source/stages/)의 `firstClearCorePointReward`다.

## 핵심 효과와 방어 노드

핵심 8개는 모두 페널티가 없다. 각 효과는 이미 존재하고 해금된 전투 기능에만 적용하며, 새 포탑·젬·특성·스킬·링크 슬롯을 해금하지 않는다.

| ID | 효과 |
| --- | --- |
| K1 처치 충전 | 적 처치마다 코어 최대 충전량의 10% 회복 |
| K2 비축 사격 | 대기 중 최대 2회 비축. 비축 사격 조준 속도와 발사 후 쿨다운 회복 속도 각각 +50% |
| K3 잔류 연성 | 지속 피해 DPS ×1.5, 지속시간 ÷1.5. 추가 지속 피해를 새로 부여하지 않음 |
| K4 광역 파동 | 폭발 주변 대상 피해 계수 +15%p. 기본 50%는 65%가 되고 주 대상 피해는 유지 |
| K5 정예 육성 | 포탑 최대 레벨 +1. 추가 레벨도 기존 방식으로 골드를 지불하고 구매 |
| K6 지원 연결 | 해당 포탑에 장착한 모든 젬 하나당 피해 증폭 +5%. 먼저 개수를 합산하여 `1+0.05×개수`, 최대 ×1.25 |
| K7 선제 제압 | 각 적에게 처음 **성공한** 둔화·기절·빙결 지속시간 ×2. 적 단위로 공유하는 1회 효과이며 지속 피해 제외, 면역 유지 |
| K8 불굴 성채 | 스테이지당 1회 치명 피해에서 넥서스 체력 1로 생존하고 3초 무적. 사용 여부 저장 |

`S3`·`A06`·`C10`의 지속시간 증가는 둔화뿐 아니라 제어 지속시간에 적용한다. 둔화 강도 증가는 여전히 둔화에만 적용한다. 나머지 비핵심 수치는 승인된 반올림 원본의 랭크별 총량을 유지한다.

`C12`는 최대 체력 배율 대신 **추가 체력**을 부여한다. 스테이지 시작 시 기본 최대 체력(영구 HP 강화 포함, 트리 최대 HP 배율 적용 전)의 5/10/15%를 한 번만 부여하고 일반 체력보다 먼저 소모한다. 한번 잃은 추가 체력은 회복·웨이브 전환으로 채워지지 않는다. 이어하기는 남은 추가 체력과 지급 여부를 복원하며 다시 지급하지 않는다.

## 런 고정과 v4 이관

- [v4 보존 원본](../godot/content/source/core_passive_tree_v4.json)의 기존 21개 노드와 효과 계산을 남긴다. v4의 진행 중·정지·준비·보상 대기 런은 기존 카탈로그·효과를 유지한다. 이관을 위해 런을 강제로 종료하지 않는다.
- 새 스테이지가 시작할 때 `runCorePassiveTreeRevision`과 `runCorePassiveNodeRanks`를 고정한다. 계정 투자 변경은 다음 스테이지에 적용하며, 현재 런의 고정 투자·장착 스킬·모듈은 바꾸지 않는다.
- 진행 중 런이 없거나 실제 종료된 성공·실패 상태에 도달했을 때만 v5로 이관한다. 기존 투자와 정확한 비용을 `corePassiveLegacyAllocation`에 보존하고 계정 투자를 비운다. 총 포인트·최초 보상 수령 기록은 변경하지 않는다. 반복 이관은 아무것도 추가하지 않는다.
- 종료 기록을 보관하는 경우에도 그 기록의 고정 카탈로그는 v4로 유지한다. 저장·전환 저널의 기존 원자적 성공 경계에서만 새 계정 상태를 반영하며, 저장 실패 시 실제 투자 상태를 먼저 바꾸지 않는다.
- 저장 봉투 버전은 v2를 유지한다. 제공된 트리 버전이 정수가 아니거나 지원 범위를 벗어나면 거부한다. 버전이 생략된 기존 저장은 v4로 읽는다. v5의 알 수 없는 노드·소수 랭크·최대 초과 랭크를 삭제하거나 낮추어 수용하지 않는다.
- 추가 체력, 불굴 사용 여부·무적 잔여시간, 비축 충전, 첫 제어 성공 여부를 저장한다. 구 저장에 없는 새 선택 필드를 임의로 추가하지 않아 기존 요청·체크포인트 해시 재조회 계약을 유지한다.
- 새 writer·저장·경제 명령은 클라이언트/서버 호환 세대 10을 함께 사용한다. 구 요청의 동일 본문·키 재조회와 계정/경제 권위는 유지한다. 운영 적용은 별도 배포 절차다.

## 화면과 검증 근거

로비 코어 메뉴는 트리를 바로 표시하고 중앙 코어에서 기존 전투 스킬 선택을 연다. 이동·확대되는 트리와 고정 포인트/투자 조작을 구분한다. 자세한 시각 기준은 [DESIGNS.md](../DESIGNS.md)를 따른다.

- 투자·도달성·환급·원본/서버 일치: `scripts/test_core_passive_tree.py`, `verify_expanded_core_tree.gd`, 서버 `internal/coretree`·`internal/save` 검사.
- 생성 최신성: `python3 scripts/compile_core_passive_tree.py --check`. 콘텐츠 검사·네이티브 회귀 준비에서도 확인한다.
- 기존 저장·성장·해시: `verify_save_codec.gd`, `verify_growth_rules.gd`, `verify_godot_account_services.py`. 기존 fixture의 무효 합성 버전은 새 버전 판별 규칙에 따라 명시적으로 거부하며, 구 요청 해시는 보관된 정규화 값으로 별도 비교한다.
- 실행·체크포인트: `verify_expanded_tree_combat.gd`, `verify_stockpile_firing.gd`, `verify_expanded_tree_integration.gd`.

자동 검사의 통과는 모바일 실기기·실제 화면 조작·운영 배포 완료를 뜻하지 않는다. 각 미검증 범위와 최종 검증 결과는 [구현·검증 체크리스트](implementation_checklist.md) 및 [배포 인계](deployment_status.md)에서 관리한다.
