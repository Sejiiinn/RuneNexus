# Rune Nexus 데모 앱 작업 계획서

> 현재 문서 상태: 초기 MVP 계획서를 유지하되, 현재 로컬 구현 상태를 반영해 갱신했다. 세부 구현 현황은 `docs/implementation_status.md`를 기준으로 한다.

## 1. 목적

이 문서는 모바일 로그라이트 타워 디펜스 기획서를 바탕으로, Flutter + Flame 기반의 간단한 데모 앱을 만들기 위한 실행 계획을 정리한다.

데모의 목적은 전체 콘텐츠를 많이 구현하는 것이 아니라, 다음 핵심 재미가 실제 조작과 전투 흐름 안에서 성립하는지 검증하는 것이다.

- 포탑에 젬을 연결하는 선택이 직관적인가
- 라운드 종료 후 젬 3개 중 1개를 고르는 선택이 의미 있는가
- 골드를 포탑 구매, 레벨업, 링크 확장 중 어디에 쓸지 고민되는가
- 같은 맵을 반복해도 젬 조합에 따라 다른 전투 양상이 나오는가

## 1.1 현재 구현 반영 요약

현재 데모는 초기 계획의 기본 전투 루프를 넘어 다음 기능까지 구현되어 있다.

- Flutter + Flame 실행/웹 빌드 검증
- 8 x 10 Grid 맵과 50라운드 웨이브
- 포탑 3종, 적 4종, 젬 9종
- 포탑 레벨업, 2링크/3링크 확장, 젬 장착/해제
- 전투 중 포탑 설치/레벨업/링크 확장
- 라운드 진행 저장과 복구
- 스테이지 1~5 선택 화면, 잠금/해금, 스테이지별 기록
- 룬 기반 영구 업그레이드 기초
- 한국어/영어 문구 구조

따라서 이후 작업은 "기본 기능 구현"보다 "MVP 루프 완성도, 결과 화면, 스테이지 차별화, 성장 구조 확장"을 우선한다.

## 2. 기획 검토 결론

현재 기획은 MVP 기준으로 방향성이 명확하지만, 첫 데모 앱으로는 범위가 다소 크다. 특히 포탑 3종, 적 3종, 젬 6종, 10라운드, 저장, 결과 화면을 한 번에 구현하면 핵심 검증 전에 전투 안정화와 UI 작업에 일정이 많이 사용될 가능성이 높다.

따라서 첫 번째 데모는 다음 순서로 나누어 진행하는 것이 적합하다.

1. 젬 없는 기본 타워 디펜스 루프를 먼저 완성한다.
2. 라운드 종료 보상 UI를 붙인다.
3. 1링크 젬 장착을 붙인다.
4. 2링크 확장과 젬 조합을 붙인다.
5. 마지막에 픽셀 에셋과 연출을 교체한다.

이 순서가 적합한 이유는, 젬 시스템의 재미를 판단하려면 먼저 적 이동, 포탑 공격, 웨이브 종료 판정이 안정적으로 동작해야 하기 때문이다. 데모의 핵심 검증 지점은 "많은 콘텐츠"가 아니라 "젬 조합으로 포탑 역할이 바뀌는 느낌"이다.

## 3. 데모 범위

- Flutter + Flame 프로젝트 기본 세팅
- 모바일 세로 화면 기준 게임 화면
- 8 x 10 또는 9 x 12 고정 Grid 맵
- 고정 S자형 경로를 따라 이동하는 적
- 포탑 배치 가능 타일과 경로 타일 구분
- 포탑 3종
  - 화살 포탑: 빠른 단일 공격
  - 대포 포탑: 느린 범위 공격
  - 마법 포탑: 중간 속도, 방어 무시 또는 특수 피해
- 적 3종
  - 일반 적
  - 빠른 적
  - 탱커 적
- 50라운드 데모 웨이브
- 포탑 자동 타겟팅, 투사체, 피격, 사망 처리
- 라운드 종료 후 젬 3개 중 1개 선택
- 포탑별 1~3링크
- 젬 장착에 따른 전투 효과 변화
- 포탑 레벨업
- 스테이지 클리어 / 실패 처리
- 간단한 로컬 저장
- 스테이지 1~5 선택, 잠금/해금, 기록 표시
- 룬 기반 영구 업그레이드 기초

### 제외 기능

- 젬 희귀도
- 젬 제거 비용
- 동료 성장
- 상점, 광고, 배틀패스, BM
- 실시간 길찾기
- 자유 길막
- 복잡한 메타 성장과 대량 업그레이드
- 스테이지별 고유 맵/웨이브 완성
- 온라인 저장 실제 연동

## 4. 데모 콘텐츠

### 맵

초기 데모는 단일 맵으로 구성한다.

- 화면 방향: 세로
- Grid 크기: 8 x 10 우선 검토
- 경로 형태: 단일 입구 S자형 경로
- 타일 종류:
  - `PathTile`: 적 이동 경로
  - `BuildTile`: 포탑 배치 가능
  - `BlockedTile`: 배치 불가
  - `SpawnTile`: 적 출현 지점
  - `CoreTile`: 방어 대상

### 포탑

| 포탑 | 역할 | 기본 특징 | 데모 검증 포인트 |
| --- | --- | --- | --- |
| 기관총 포탑 | 단일 대상 딜러 | 빠른 공격, 낮은 피해 | 공격속도, 물리 포탑 증폭, 사거리 젬과의 궁합 |
| 대포 포탑 | 광역 딜러 | 느린 공격, 범위 피해 | 폭발, 물리 포탑 증폭 젬과의 궁합 |
| 화염 포탑 | 지속피해 딜러 | 중간 속도, 짧은 화상 피해 | 연쇄, 사거리 젬과의 궁합 |

### 젬

초기 계획은 5종 젬으로 시작했지만, 현재 구현은 9종 젬을 포함한다.

용어 기준:

- `증가`: 합연산 보너스에 사용한다.
- `증폭`: 곱연산 배율 보너스에 사용한다.

| 젬 | 효과 | 우선 구현 방식 |
| --- | --- | --- |
| 공격속도 증가 | 초당 발사 횟수 증가 | 포탑 `attackRate` 배율 적용 후 쿨다운은 `1 / attackRate`로 계산 |
| 사거리 증가 | 탐지 범위 증가 | 타겟 검색 반경 증가 |
| 물리 포탑 증폭 | 물리 포탑 피해 40% 증폭 | 물리 타입 포탑 최종 피해에 1.4배 적용 |
| 마법 포탑 증폭 | 마법 포탑 피해 40% 증폭 | 마법 타입 포탑 최종 피해에 1.4배 적용 |
| 경량화기 증폭 | 경량화기 피해와 연사 강화 | 경량 태그 포탑에만 적용 |
| 중화기 증폭 | 중화기 피해와 범위 강화 | 중화기 태그 포탑에만 적용 |
| 지속피해 증폭 | 화상 피해와 지속시간 강화 | 지속피해 태그 포탑에만 적용 |
| 폭발 피해 | 착탄 시 범위 피해 | 충돌 지점 기준 범위 탐색 |
| 연쇄 | 다른 적에게 추가 타격 | 타겟 주변 적 1명에게 보조 피해. 중화기 포탑에는 장착 불가 |

독과 둔화는 젬에서는 제외하고, 이후 전용 포탑 유형 또는 포탑 스킬로 재도입한다.
젬 장착은 보유 젬 선택 후 효과를 확인하고 장착하는 2단계 UX를 기본으로 한다.
장착된 젬은 링크 슬롯에서 해제할 수 있으며, 해제 시 보유 젬으로 되돌아간다.

### 라운드

초기 계획은 5라운드 버전으로 시작해 10라운드로 확장하는 것이었지만, 현재 구현은 50라운드 데모 웨이브를 사용한다. 5라운드 단위로 젬 보상/탱커/보스 압박을 배치하고, 10라운드 단위로 큰 웨이브를 만든다.

| 라운드 | 구성 | 목적 |
| --- | --- | --- |
| 1 | 일반 적 중심 | 기본 배치와 공격 검증 |
| 2 | 일반 적 증가 | 포탑 추가 구매 유도 |
| 3 | 빠른 적 추가 | 사거리, 공격속도, 경량화기 가치 검증 |
| 4 | 탱커 적 추가 | 레벨업, 대포, 중화기 가치 검증 |
| 5 | 혼합 웨이브 또는 미니 보스 | 젬 조합과 빌드 완성도 검증 |
| 10 단위 | 보스/강한 혼합 웨이브 | 장기 생존과 스테이지 클리어 압박 검증 |

## 5. 그래픽 방향

첨부 컨셉 아트의 방향성은 유지하되, 데모에서는 제작 속도와 가독성을 우선한다.

### 목표 스타일

- 어두운 판타지 배경
- 푸른 Nexus 코어를 중심으로 한 마법 방어 분위기
- 도트풍 또는 저해상도 픽셀 느낌의 2D 스프라이트
- 타일, 포탑, 적, 투사체가 작은 모바일 화면에서도 명확히 구분되는 색상
- 젬 효과별 색상 정체성 유지
  - 지속피해/화상: 녹색 또는 주황색
  - 사거리/마법: 하늘색
  - 폭발: 주황색
  - 연쇄/번개: 청백색 또는 보라색
  - 공격속도: 노란색
  - 사거리: 파란색

### 데모용 에셋 원칙

- 초기에는 고품질 완성 에셋보다 기능 검증용 픽셀 에셋을 우선한다.
- 포탑은 실루엣으로 구분되도록 만든다.
- 적은 색상과 크기로 역할을 구분한다.
- 투사체와 피격 이펙트는 단순 도형/파티클로 시작한다.
- UI 아이콘은 임시 픽셀 아이콘으로 구성하되, 젬 종류는 색상과 심볼을 고정한다.

## 7. 구현 단계

### 1단계: 프로젝트 기반 세팅

목표는 Flutter + Flame 프로젝트가 실행되고, 세로 화면에서 빈 게임 캔버스와 HUD가 표시되는 상태를 만드는 것이다.

작업:

- Flutter 프로젝트 생성
- Flame 의존성 추가
- 세로 화면 고정
- 기본 라우팅과 게임 위젯 구성
- HUD 오버레이 구조 추가
- Android/iOS 실행 확인

완료 기준:

- 앱 실행 시 게임 화면이 표시된다.
- 상단 또는 하단 HUD 영역에 골드, HP, 라운드 텍스트가 보인다.

### 2단계: Grid 맵 렌더링

목표는 맵 데이터 기반으로 타일을 렌더링하는 것이다.

작업:

- `TileType` 정의
- 단일 S자형 데모 맵 데이터 작성
- Grid 좌표와 화면 좌표 변환 구현
- 타일별 색상/스프라이트 렌더링
- Path, Build, Blocked, Spawn, Core 구분 표시

완료 기준:

- 8 x 10 또는 9 x 12 맵이 화면에 맞게 표시된다.
- 경로와 배치 가능 타일이 명확히 구분된다.

### 3단계: 적 이동

목표는 적이 Spawn에서 Core까지 고정 경로를 따라 이동하는 것이다.

작업:

- 적 도메인 모델 정의
- 경로 포인트 기반 이동 구현
- HP, 속도, 도착 처리 구현
- Core 도착 시 Nexus HP 감소
- 적 사망 및 제거 처리

완료 기준:

- 적이 경로를 따라 자연스럽게 이동한다.
- 적이 Core에 도착하면 HP가 감소한다.
- 적 HP가 0이 되면 제거된다.

### 4단계: 포탑 배치

목표는 플레이어가 배치 가능 타일에 포탑을 설치할 수 있게 하는 것이다.

작업:

- 포탑 타입 3종 정의
- 포탑 구매 비용 정의
- BuildTile 터치 처리
- 선택한 포탑 설치
- 이미 설치된 타일에는 중복 배치 방지
- 골드 부족 처리

완료 기준:

- 플레이어가 포탑 타입을 선택하고 타일에 배치할 수 있다.
- 골드가 차감된다.
- 배치 불가 타일과 경로에는 설치되지 않는다.

### 5단계: 자동 타겟팅과 공격

목표는 포탑이 범위 내 적을 자동으로 공격하는 것이다.

작업:

- 타겟 검색 구현
- 공격 쿨다운 구현
- 투사체 생성 및 이동
- 피격 판정
- 단일 피해 처리
- 대포 범위 피해 처리

완료 기준:

- 포탑이 범위 안의 적을 자동 공격한다.
- 투사체가 적에게 도달하면 피해가 적용된다.
- 적 처치 시 골드 보상이 지급된다.

### 6단계: 웨이브와 라운드

목표는 라운드 단위 전투 흐름을 만드는 것이다.

작업:

- 웨이브 데이터 정의
- 라운드 시작/진행/종료 상태 머신 구현
- 적 스폰 간격 처리
- 라운드 클리어 판정
- 다음 라운드 예고 표시

완료 기준:

- 라운드를 시작하면 정해진 적이 순서대로 등장한다.
- 모든 적을 처치하면 라운드가 종료된다.
- 라운드 종료 후 보상 단계로 이동한다.

### 7단계: 젬 보상 UI

목표는 라운드 종료 후 젬 3개 중 1개를 선택하는 흐름을 만든다.

작업:

- 젬 데이터 6종 정의
- 무작위 보상 후보 3개 생성
- 젬 카드 UI 구현
- 선택한 젬을 인벤토리에 추가
- 보상 선택 후 준비 단계로 이동

완료 기준:

- 라운드 종료 후 젬 카드 3장이 표시된다.
- 하나를 선택하면 보유 젬에 추가된다.
- 선택 전까지 다음 라운드가 시작되지 않는다.

### 8단계: 링크와 젬 장착

목표는 포탑에 젬을 장착해 공격 방식이 변하게 하는 것이다.

작업:

- 포탑별 링크 슬롯 모델 구현
- 기본 1링크 제공
- 골드로 2링크 확장
- 포탑 선택 패널 구현
- 보유 젬 장착 UI 구현
- 젬 효과 계산 구조 구현

완료 기준:

- 포탑에 젬을 장착할 수 있다.
- 2링크 확장 시 젬을 2개까지 장착할 수 있다.
- 젬 조합에 따라 포탑 성능이 달라진다.

### 9단계: 젬 효과 구현

목표는 데모의 핵심 조합 재미를 만드는 것이다.

작업:

- 공격속도 증가 적용
- 사거리 증가 적용
- 물리 포탑 피해 증폭 적용
- 폭발 범위 피해 적용
- 연쇄 추가 타격 적용
- 복수 젬 동시 적용 순서 정리

완료 기준:

- 각 젬 효과가 눈으로 확인된다.
- 같은 포탑이라도 장착 젬에 따라 전투 역할이 달라진다.

### 10단계: 포탑 성장

목표는 골드 사용처를 포탑 구매 외에도 만들고, 선택 압박을 제공하는 것이다.

작업:

- 포탑 레벨 1~5 정의
- 레벨업 비용 정의
- 레벨별 공격력, 사거리, 공격속도 성장 정의
- 레벨업 UI 구현
- 링크 확장 비용과 레벨업 비용 밸런스 초안 작성

완료 기준:

- 포탑을 골드로 레벨업할 수 있다.
- 레벨업과 신규 포탑 구매, 링크 확장 사이에 선택이 발생한다.

### 11단계: 승패와 저장

목표는 데모를 한 판의 완결된 경험으로 만드는 것이다. 현재 로컬 저장, 실패/성공 처리, 룬 정산, 스테이지 기록, 결과 화면의 주요 선택지 분리는 구현되어 있다. 남은 핵심은 기록 갱신과 신규 해금 정보를 더 명확히 강조하는 것이다.

작업:

- Nexus HP 0 이하 실패 처리
- 마지막 라운드 클리어 성공 처리
- 결과 화면 구현
- 간단한 로컬 저장 구현
- 누적 클리어 횟수 또는 성장 재화 저장
- 결과 화면에서 재도전/스테이지 선택/영구 업그레이드/다음 스테이지 이동 분리
- 결과 화면에서 기록 갱신/신규 해금 강조

완료 기준:

- 실패와 성공 결과가 명확히 표시된다.
- 앱 재실행 후에도 최소 저장 데이터가 유지된다.
- 룬 정산 후 다음 행동을 자연스럽게 선택할 수 있다.

### 12단계: 데모 폴리싱

목표는 플레이 가능한 프로토타입에서 시연 가능한 데모로 정리하는 것이다.

작업:

- 픽셀 스타일 임시 에셋 교체
- 타격감 개선
- 포탑 사거리 표시
- 선택 중인 타일 강조
- 적 HP 바 표시
- 젬 효과 아이콘과 색상 정리
- 모바일 화면 터치 영역 조정
- 기본 사운드 또는 효과음 추가 검토

완료 기준:

- 핵심 정보가 작은 화면에서도 읽힌다.
- 포탑, 적, 젬 효과가 구분된다.
- 한 판 플레이 흐름이 끊기지 않는다.

## 11. 밸런스 초안

초기 수치는 정확한 완성 밸런스보다 선택 압박이 느껴지는지를 우선한다.

- 포탑 구매 비용은 초반에 1~2개를 깔 수 있는 수준으로 설정한다.
- 레벨업은 같은 비용의 신규 포탑 구매보다 단일 지점 화력을 높이는 선택지가 되어야 한다.
- 2링크/3링크 확장은 당장 딜 상승이 작더라도 젬 조합 가치를 크게 만드는 선택이어야 한다.
- 젬은 단독으로도 효과가 보이고, 조합 시 역할 변화가 명확해야 한다.
- 빠른 적은 공격속도/경량화기/사거리의 가치를 검증한다.
- 탱커 적은 레벨업/대포/중화기 선택의 가치를 검증한다.
- 혼합 웨이브는 연쇄/폭발의 가치를 검증한다.

## 12. UX 원칙

- 전투 중 조작은 포탑 배치, 포탑 레벨업, 링크 확장까지 허용한다.
- 젬 장착/해제는 라운드 종료 후 준비 단계에서만 허용한다.
- 포탑을 누르면 현재 장착 젬, 레벨업, 링크 확장, 사거리가 즉시 보여야 한다.
- 링크 슬롯을 선택하기 전에는 보유 젬 목록을 열지 않아 전투 화면을 과하게 가리지 않는다.
- 젬 카드는 이름, 아이콘, 색상, 짧은 효과 문구만 표시한다.
- 작은 모바일 화면에서 긴 설명문은 피한다.
- 라운드 예고는 한 줄로 표시한다.
- 실패 원인은 Nexus HP 감소로 명확히 전달한다.
- 갑작스러운 종료 후 전투 중 진행을 복구할 때는 즉시 재개하지 않고, 일시정지 상태에서 계속 진행 여부를 묻는다.

## 13. 주요 리스크와 대응

## 14. 검증 체크리스트

데모 빌드가 완성되면 다음 질문으로 검토한다.

- 한 손 세로 화면에서 타일 선택과 포탑 배치가 편한가
- 라운드 시작 전 다음 적 구성이 이해되는가
- 포탑 사거리와 타겟팅 결과가 납득되는가
- 젬 선택 3개 중 하나를 고를 때 고민이 생기는가
- 2링크 확장이 충분히 매력적인 선택인가
- 젬 조합에 따라 같은 포탑의 역할이 바뀌는가
- 실패했을 때 다음 판에 다른 선택을 해보고 싶은가
- 임시 그래픽 상태에서도 전투 상황을 읽을 수 있는가
