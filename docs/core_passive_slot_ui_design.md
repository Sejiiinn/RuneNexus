# 코어 패시브 슬롯 UI 설계

## 목적

현재 코어 화면은 `수호 광선`이 해제 불가능한 고정 패시브처럼 보이고, 이후 다른 코어 전투 스킬이나 패시브가 추가될 여지가 약하게 보인다.

코어 화면은 다음 구조가 즉시 읽히도록 개편한다.

```text
전투 스킬 1칸
일반 패시브 2칸
```

`수호 광선`은 고정 보너스가 아니라 전투 스킬 슬롯에 기본 장착된 스킬이다. 이후 `룬 파동`, `관통 성창`, `연쇄 광휘` 같은 전투 스킬이 해금되면 같은 슬롯에서 교체할 수 있어야 한다.

## 기준 프로토타입

HTML 프로토타입:

- `docs/prototypes/core_passive_slot_layout.html`

프로토타입은 최종 시각 사양이 아니라 레이아웃 기준이다. 실제 Flutter UI에서는 기존 메뉴 화면의 톤, 여백, 폰트 크기, 버튼 스타일과 맞춘다.

## 화면 구조

### 상단 요약

상단에는 코어 이름과 슬롯 요약을 표시한다.

```text
새벽 코어
전투 스킬 1칸 / 패시브 2칸
Lv.6
```

레벨은 현재 실제 성장 데이터가 없다면 기존 코어 화면의 `Lv.1 기본 코어` 표현을 유지해도 된다.

### 중앙 코어 영역

중앙에는 코어 본체를 배치하고, 주변에 세 슬롯을 소켓처럼 배치한다.

| 위치 | 슬롯 | 초기 표시 |
| --- | --- | --- |
| 상단 중앙 | 전투 스킬 | 수호 광선 |
| 하단 좌측 | 패시브 1 | 자가 수복 또는 잠김/빈 슬롯 |
| 하단 우측 | 패시브 2 | 빈 슬롯 또는 잠김 |

핵심은 `전투 스킬`과 `패시브`가 한 목록 안에 섞이지 않는 것이다. 전투 스킬은 1칸 제한이 강하게 보여야 하고, 패시브는 별도 보조 슬롯으로 보여야 한다.

### 슬롯 카드

각 슬롯은 다음 정보를 짧게 표시한다.

```text
슬롯 종류
아이콘
이름
짧은 상태 문구
변경/장착 버튼
```

예시:

```text
전투 스킬
수호 광선
자동 발동 / 교체 가능
변경
```

```text
패시브 1
자가 수복
5라운드마다 체력 회복
변경
```

```text
패시브 2
슬롯 해금
500 룬 필요
해금
```

패시브 슬롯은 서로 겹치지 않아야 한다. 모바일 폭이 좁을 때는 슬롯 카드 너비와 아이콘 크기를 줄여 좌우 간격을 우선 확보한다.

## 하단 코어 능력 패널

하단은 상세 설명창이 아니라 다른 코어 능력을 확인하고 장착하기 쉬운 별도 관리 패널이다.

이 패널은 코어 장착 슬롯과 역할이 다르다.

| 영역 | 역할 |
| --- | --- |
| 코어 장착 슬롯 | 현재 장착된 전투 스킬과 패시브 2칸 확인 |
| 코어 능력 패널 | 보유/잠김 능력 확인, 장착 후보 선택 |

`코어 능력 패널`은 장착 슬롯과 시각적으로 분리한다. 필요하면 아래에서 올라오는 패널처럼 보이게 만들 수 있지만, 가로 캐러셀 형태는 사용하지 않는다. 후보 비교와 해금 상태 확인이 어려워지기 때문이다.

### 탭

하단 탭은 두 개만 둔다.

```text
전투 스킬 / 패시브
```

`전체` 탭은 사용하지 않는다. 전투 스킬과 일반 패시브는 장착 규칙이 다르므로 처음부터 분리해 보여주는 편이 낫다.

### 목록 항목

목록 항목은 세로 목록 또는 2열 그리드로 짧고 조밀하게 구성한다.

```text
아이콘
이름
카드 보유/해금 상태
장착/장착중/잠김 액션
```

예시:

| 이름 | 타입 | 상태 | 액션 |
| --- | --- | --- | --- |
| 수호 광선 | 전투 스킬 | 카드 2/3 / 장착 | 장착중 |
| 룬 파동 | 전투 스킬 | 카드 1/3 / 교체 가능 | 장착 |
| 연쇄 광휘 | 전투 스킬 | 챕터 2 해금 | 잠김 |
| 자가 수복 | 패시브 | 카드 3/3 / 장착 | 장착중 |
| 절약 설계 | 패시브 | 카드 1/3 / 패시브 | 장착 |
| 공명 축전 | 패시브 | 스테이지 2 클리어 | 잠김 |

하단 패널은 고정 높이를 갖고, 목록이 길어지면 내부 목록만 스크롤한다. 코어 슬롯 영역을 침범하지 않는다.

### 업그레이드 방향

패시브와 전투 스킬의 직접 `강화` 버튼은 두지 않는다.

업그레이드는 후속 카드 획득으로만 진행한다.

```text
카드 획득 -> 보유 수 증가 -> 조건 충족 시 자동 또는 별도 카드 승급 화면에서 등급 상승
```

따라서 코어 능력 패널의 액션은 아래로 제한한다.

| 상태 | 액션 |
| --- | --- |
| 장착 중 | 장착중 |
| 장착 가능 | 장착 |
| 잠김 | 잠김 |

카드 보유 수는 강화 버튼 대신 진행 상태로만 표시한다.

## 상호작용

1. 중앙의 전투 스킬 슬롯을 누르면 하단 목록이 `전투 스킬` 탭으로 전환된다.
2. 중앙의 패시브 슬롯을 누르면 하단 목록이 `패시브` 탭으로 전환된다.
3. 하단 목록의 `장착`은 해당 타입의 슬롯에 장착한다.
4. 전투 스킬은 항상 1개만 장착된다.
5. 패시브는 최대 2개까지 장착된다.
6. 하단 목록에는 직접 `강화` 버튼을 두지 않는다.
7. 잠긴 항목은 선택 불가 상태로 표시하고, 해금 조건만 짧게 보여준다.

## 이번 구현 범위

이번 UI 구현은 코어 메뉴 화면의 구조 개편에 집중한다.

포함:

- 코어 화면의 `영구 패시브` 행형 UI를 소켓형 UI로 변경
- `전투 스킬 1칸 / 패시브 2칸` 구조가 보이도록 표시
- 하단에 `전투 스킬 / 패시브` 능력 목록 표시
- 수호 광선이 기본 장착된 전투 스킬처럼 보이도록 문구 변경
- 후속 능력 후보를 잠김 또는 교체 가능 항목으로 표시
- 직접 강화 액션을 제거하고 카드 보유 상태를 표시

제외:

- 실제 신규 전투 스킬 효과 구현
- 실제 패시브 효과 적용
- 강화 비용, 재화, 레벨업 공식 구현
- 패시브 직접 강화 버튼
- 카드 획득/승급 실제 처리
- 저장 데이터 구조 변경
- 코어 성장 시스템의 실제 해금 조건 연결

## 구현 주의

- 현재 프로젝트 구조와 맞게 `main_menu_screen.dart` 내부의 코어 화면 UI만 좁게 수정한다.
- 임시 효과 로직이나 저장 포맷 변경을 추가하지 않는다.
- 실제 데이터 모델이 아직 없다면 UI용 정적 항목으로만 구성한다.
- 후속 기능 연결을 위해 문구와 타입 구분은 명확히 유지한다.
- 버튼은 현재 단계에서 눌러도 치명적 상태 변경이 없어야 한다. 실제 장착 기능과 카드 획득/승급 기능은 후속 구현 범위로 둔다.
