# 인앱 피드백 시간을 줄이는 원칙

역할: 실행 절차의 배경 설명. 정리: 2026-09-09.
명령과 실행 순서는 [공통 인앱 가이드](../.agents/in_app_test_guide.md), 실패 진단은 [실행 참조](in_app_test_workflow.md)가 기준이다.

- 작은 Dart 변경은 살아 있는 개발 서버의 hot reload를 우선해 전체 웹 빌드 비용을 줄인다.
- 서버 상태는 PID 파일보다 실제 LISTEN·HTTP 응답과 현재 페이지로 판단한다.
- 여러 시안을 비교해야 하는 요청이라면 가능할 때 하나의 미리보기에서 비교한다. 후보마다 서버를 새로 시작하지 않는다.
- 이미 승인된 시안 구현에는 새로운 비교 시안이나 전용 미리보기 하네스를 기본으로 만들지 않는다.
- 실제 결함이 없으면 캡처·전체 테스트·빌드를 반복하지 않는다. 미세한 픽셀 차이를 맞추기 위한 반복은 하지 않는다.
- 시각 검증의 대표 사례·완료 조건·캡처 실패 대안은 [DESIGNS.md](../DESIGNS.md)에서 관리한다.

이 원칙은 필수 검사나 확인된 기능 결함을 생략하라는 뜻이 아니다. 검증 비용은 요청 범위와 실제 위험에 맞춘다.
