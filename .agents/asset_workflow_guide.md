# 에셋 작업 절차

역할: [AGENTS.md](../AGENTS.md#ui시각-에셋)의 도구 선택·표현 계약을 유지하는 실행 절차. 착수·대표 부분 검증·반복 실패의 방법 재판단은 [시안 보존 기준](../DESIGNS.md#승인-시안-보존과-채택), 최종 판정은 [완료 기준](../DESIGNS.md#검증과-완료-기준--완벽한-복제보다-요청-충족)을 따른다.

## 기존 작업과 연결 보존

- GIMP 작업 전 실행 중인 인스턴스·MCP 연결·열린 문서를 확인하고 기존 인스턴스를 재사용한다. 연결 실패만으로 새 인스턴스를 띄우지 않는다.
- MCP 등록·시작·상태 확인·재연결은 GIMP 앱을 자동 실행하지 않는다. GIMP를 실제로 사용하는 작업에서만 명시적으로 실행하고, 필요하면 열린 창의 `Tools > MCP > Start MCP Server`로 연결한다. 종료 여부는 프로세스 조회로 확인하며 앱 열기 기능을 확인 수단으로 사용하지 않는다.
- 연결 실패 원인을 확인하고 기존 연결 복구를 먼저 시도한다. 실행 중인 인스턴스가 없거나 사용할 수 없다는 근거가 있을 때만 새로 실행하며, 기존 문서와 미저장 작업을 보존한다.
- 같은 실패를 상태 변화 없이 반복하지 않는다. [도구 복구와 대체 경로](in_app_test_guide.md#도구-복구와-대체-경로)를 따르며, 사용자 지정 도구나 합의한 표현 방식을 임의로 바꾸지 않는다.
- 제작 전에 해당 에셋의 채택 기록에서 편집 원본·실제 게임 적용본·사용할 스크립트와 입력을 확인한다. 기존과 같은 제작 요청은 당시 채택 경로를 확인한 뒤 이어가며, 예전 생성기나 일반적인 제작 순서로 대체하지 않는다. Blender Python/bpy와 ComfyUI 등 지정 흐름을 재사용하고, 독립 background 실행은 열린 원본·미저장 작업을 보존한다.

등록된 경로는 `python3 scripts/asset_workflow_report.py`로 조회한다. 특정 에셋의 기존 원본·채택본·게임 출력·producer/review 기록 대응은 다음처럼 읽기 전용으로 대조한다.

```sh
python3 scripts/asset_workflow_report.py frost-rebaked-10k --verify-records --json-out /tmp/frost-records.json
```

[catalog](../design/stage1_3d/blender_workspace/catalog.json)의 해당 ID만 읽는다. 기존 `source_sha256`·`approved_source_sha256`과 선택적 `accepted_source`, `runtime_outputs`, `record_inputs`의 SHA를 현재 파일과 대조한다. `expected_hashes_from_records=true`인 ID는 catalog에 기대 SHA를 복제하지 않고 해당 target의 첫 유효한 `record_links.bindings` SHA 필드를 원본으로 읽는다(JSON의 `expected_record`에 출처 표시). 이 모드에서 `runtime_outputs` 생략 시 기존 `outputs`를 대조 대상으로 쓰며, `records` 생략 시 `record_links`의 경로를 쓴다. 다른 연결 기록도 각각 대조하므로 기록 간 SHA 불일치를 숨기지 않는다. `sha256_field`·`path_field`는 기존 JSON의 정확한 키/배열 인덱스 목록이며, 경로는 기본적으로 저장소 기준이다(`path_base=record`이면 기록 파일의 폴더 기준). `runtime_references`는 지정한 코드의 로딩 경로 문자열 존재만 확인한다. 기존 `sources` 목록은 제작 라이브러리이므로 최신 게임 채택 목록으로 간주하지 않는다.

대조 결과와 종료 코드는 `matched`/0, `mismatch`/1, `unknown`/2다. 파일·기록·필드·기대 SHA 부재와 SSD 미마운트는 사유와 함께 `unknown`, 변경 SHA·기록 경로·recipe/로딩 경로 불일치는 `mismatch`다. 두 상태가 함께 있으면 `mismatch`가 우선한다. 옵션을 생략한 기존 요약은 파일 존재 여부에 따른 0/1과 `record_freshness=not_verified`를 유지한다. JSON의 `validation=not_run`은 항상 유지하며, 기록 대조를 과거 검수 PASS·receipt 서명 검증·현재 시각 검증·준비 프로젝트/패키지 검증으로 해석하지 않는다. Markdown 검수 등 명시적 SHA 필드 연결이 없으면 대응은 미확인이다. 제작·Git 원본 추출·도구 실행·SSD 쓰기는 수행하지 않는다.

## 보존 전용 자료 분리

- 실사용 적용본은 `assets/`, 현재 제작 원본·재사용할 도구와 입력·검토 중 시안은 해당 `design/` 작업 경로에 유지한다. 미채택이어도 다른 에셋에 활용할 수 있는 독립적인 형태 후보는 남긴다. 해상도·생성 시각·미채택 여부만으로 레거시를 판정하지 않는다.
- 대체되어 보존만 필요한 원본·중간 시안은 `design/legacy/` 아래 저장소 기준 원래 경로를 유지해 이동한다. 삭제하거나 같은 이름의 현재 원본을 덮어쓰지 않는다. 보존본의 과거 승인 기록은 현행 외형 기준이 아니다.
- 이동 전 실제 로딩·패키징·제작 스크립트·문서 참조를 확인한다. 필요한 입력은 도구와 함께 활성 경로에 남기고, 이동된 자료를 사용하는 링크는 새 위치로 연결한다. 당시 로그·측정값·프롬프트의 과거 경로는 역사 기록으로 보존한다.
- 해당 작업의 기존 안내에서 현재 적용본·제작 원본·보존본을 구분한다. 이동 파일의 내용 보존과 현재 입력 선택을 대조하며, 픽셀이 바뀌지 않는 기계적 이동에 게임 시각 검수나 APK 빌드를 추가하지 않는다. 보관 위치와 Git 추적 여부는 별도로 판단한다.

## 작업 완료와 프로세스 종료

- 도구를 사용하는 작업·검증이 끝날 때 이어서 사용할 구체적인 다음 작업이 있는지 확인한다. 후속 사용이 없으면 커밋이나 전체 작업 종료를 기다리지 않고 관련 편집 원본과 최종 산출물을 저장한 뒤 정상 종료해 메모리를 확보한다. 막연히 나중에 쓸 가능성이나 MCP 연결 유지를 위해 앱을 계속 켜 두지 않으며, 다시 필요해지면 저장한 원본을 열어 사용한다.
- 종료 전에는 실제 파일 존재·저장 성공·미저장 변경 여부를 확인한다. 커밋은 저장을 대신하지 않으며 기존 승인 범위에서만 수행한다.
- 앱의 종료 메뉴나 문서화된 종료 API를 사용한다. `kill`·`pkill`·`SIGTERM`·`SIGKILL`·실행 세션의 Ctrl-C는 편집기의 정상 종료를 대신하지 않는다. MCP 서버 연결 해제와 편집 앱 종료도 구분한다. 정상 종료 경로가 실패하면 해당 PID·종료 요청·오류 로그를 확인하고, 같은 요청을 반복하거나 강제 종료로 성공 처리하지 않는다.
- GIMP는 레이어를 보존하는 XCF, Blender는 `.blend` 등 다시 편집할 수 있는 원본을 저장한다. 이름 없는 문서나 같은 경로에서 파생된 여러 작업은 서로 덮어쓰지 않는 별도 경로로 보존한다. 저장 도구가 미저장 표시를 해제하지 않는 경우 저장 파일을 다시 열어 확인한 뒤 문서를 닫는다.
- 필요한 검증까지 마쳤으면 현재 작업에서 사용한 GIMP·Blender·미리보기·임시 렌더의 문서·프로세스와 공유 여부를 확인한다. 사용자·다른 채팅·하위 에이전트가 사용하지 않는다고 확인된 대상만 정상 종료하고 실제 종료 여부를 확인한다. 현재 작업의 완료·커밋이나 파일 저장만으로 공유 인스턴스 전체의 사용이 끝났다고 판단하지 않는다.
- Blender는 현재 파일 경로·미저장 변경·진행 중인 렌더와 외부 이미지의 저장 상태를 확인하고, 모든 필요한 장면을 포함한 `.blend`와 변경된 외부 리소스를 저장하거나 패킹한다. 저장 성공을 확인한 뒤 해당 인스턴스의 `bpy.ops.wm.quit_blender()` 또는 앱의 정상 종료 메뉴를 사용한다. 종료 요청 후 해당 PID가 사라졌는지 OS 프로세스 조회로 확인하며, 종료 확인을 위해 Blender나 MCP 연결을 다시 시작하지 않는다.
- GIMP는 저장 후 `list_images`로 미저장 여부를 확인하고 해당 문서를 `close_image`로 닫은 뒤, 이미지 ID가 목록에서 사라졌는지 확인한다. 현재 브리지가 생성하지 않은 창은 GIMP UI에서 닫는다. 모든 문서가 닫혔고 다른 사용이 끝났으면 `quit_gimp(confirm_no_other_users=True)`로 정상 종료를 요청한다. 기존 MCP 연결의 도구 목록에 `quit_gimp`가 없으면 GIMP 메뉴의 `Quit GIMP`를 사용한다. `accepted`는 요청 수락이며 종료 완료가 아니다. 반환된 GIMP PID와 앱 자식 프로세스가 사라졌는지 OS 프로세스 조회로 확인한다. 종료 후 앱 객체의 `getApp`·`getAXState`·스크린샷 호출로 확인하지 않는다. 닫힌 앱을 다시 실행할 수 있다.
- 다른 작업이 사용 중이거나 소유·사용 여부가 불명확한 파일·문서·프로세스는 임의로 삭제·덮어쓰기·닫기·종료하지 않는다. 종료 대상인지 확인할 수 없으면 유지하고, 필요한 경우 해당 대상만 사용자에게 확인한다. 프로세스명으로 일괄 종료하거나 공유 앱의 문서를 일괄 닫지 않는다.
- 저장 실패·출처 불명 문서·진행 중인 렌더가 있으면 먼저 보존·완료 상태를 해결한다. 복구본을 저장했다는 이유로 다른 작업의 열린 문서나 미저장 변경을 버리지 않으며, 강제 종료하지 않는다. 보존한 원본·복구본의 삭제는 프로세스 종료와 별개로 판단한다.

## 산출물 점검

- 제작 원본·중간 산출물과 게임용 최종 파일의 위치는 AGENTS.md를 따른다. 게임용 결과는 기존 로딩 경로에 연결한다.
- 크기·프레임·투명 배경·형식은 실제 사용처에 맞춘다. 움직이는 에셋은 순서·여백·루프·게임 크기를 확인한다. 형상·재질·분할 변경 시에는 관련 삼각형·표면 수·텍스처·파일 크기의 전후 변화도 확인하고 예상 밖 증가를 보고한다. 이 수치를 실제 FPS 개선으로 해석하지 않는다.
- 표면 텍스처·렌더 후처리는 원본의 입체 표현을 대체하지 않는다. 회전·조명 변화·애니메이션과 실제 게임 크기에서 합의한 특징을 확인한다.
